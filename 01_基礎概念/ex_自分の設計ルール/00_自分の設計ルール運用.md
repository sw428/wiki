# 00_自分の設計ルール運用

## 目的

このフォルダは、`01_基礎概念` の中で使う運用用の置き場。

一般的な基礎概念そのものではなく、検証や基礎概念から得た内容をもとに、自由度の高い設計判断について「自分は当面こう運用する」と固定するために使う。

## 位置づけ

```txt
02_実践/ケース検証
= 具体例、迷った過程、案件条件、検証ログ

01_基礎概念/各分野
= 一般的にはどういう仕組みか、広く通る区別や判断軸

01_基礎概念/ex_自分の設計ルール
= 基礎概念を踏まえて、自分はどう運用するか
```

## 入れるもの

- BEM命名をどの厳しさで使うか
- SCSS分割をどういう責務で分けるか
- `components` / `pages` / `layout` の境界
- 見た目命名ではなく責務命名を優先する方針
- GPTで初期案を作り、人間が責務で再判定する運用
- 案件ごとに揺れやすいが、自分の中で基準を持ちたい設計判断

## 入れないもの

- 案件固有の条件、素材、納品都合
- 検証中の長い会話ログ
- 一般的な仕様説明だけで済む内容
- まだ採用方針として固めるほどではない思いつき

## 判断の流れ

1. まず `02_実践/ケース検証` で具体例として受ける
2. 案件固有の条件を外しても成立するか見る
3. 一般的な仕組みは `01_基礎概念` の各分野へ戻す
4. 自分の採用方針として使うものだけ、このフォルダへ置く
5. ルール化した場合も、必要なら後で見直せるように条件と例外を残す

## 書き方

- 「絶対の正解」ではなく「現時点の採用方針」として書く
- 条件、理由、例外をセットで残す
- 一般概念の説明を長く重複させず、必要なら各基礎概念ノートへリンクする
- 案件で起きた経緯は、ケース検証側へ残す
