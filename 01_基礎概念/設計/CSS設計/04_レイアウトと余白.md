## Layout接頭辞の運用

`l-` は、CSSに配置指定があることを表す接頭辞ではない。

FlexやGridを使用していても、特定のBlock内部の配置であれば、そのBlockのElementとして扱う。

```css
.staff__list {
  display: grid;
  gap: 24px;
}
```

当面、Layout接頭辞は `.l-page` と `.l-inner` の2つに限定する。

## `.l-page`

ページ全体の外枠を管理する。

```css
.l-page {
  width: 100%;
}
```

最大幅やページ全体の表示制御が不要な場合は、使用自体を再検討する。

## `.l-inner`

複数のBlockで共通するコンテンツ幅を管理する。

担当するのは、最大幅、中央寄せ、共通の左右余白。

```css
.l-inner {
  width: 100%;
  max-width: 1200px;
  margin-inline: auto;
  padding-inline: 20px;
}
```

`.l-inner` は、すべてを同じ外枠へ閉じ込めるためのクラスではない。
Heroのようにページ幅いっぱいへ見せたい領域と、本文やカード一覧のように中身幅を制限したい領域を分ける。

`inner` は、単に「外側の要素の中にある」という意味では使用しない。横幅管理をしない内部要素には、`__body`、`__content`、`__media` など、実際の役割を表す名前を使用する。

### カンプの大きな左右余白を持たせる場合

たとえば、1600px幅のカンプで中身が1020pxなら、左右290pxは固定の余白値ではなく、最大幅の中身を中央へ置いた結果として扱う。

```css
.l-inner {
  width: min(calc(100% - 40px), 1020px);
  margin-inline: auto;
}
```

この場合、画面幅1600pxでは左右290pxになり、狭い画面では左右20pxを残して中身が縮む。`padding-inline: 290px` や `clamp()` を先に選ぶのではなく、次の順で決める。

1. 最大幅を持つのはページ全体か、中身だけか
2. 中身の最大幅はいくつか
3. 狭い画面で最低限残す左右余白はいくつか
4. 余白自体を連続変化させる要件がある時だけ `clamp()` を検討する

`.l-page` はサイト全体の幅を止める役、`.l-inner` は複数Blockで共有する中身幅を止める役として分ける。

## `.l-inner` とBlock固有の箱を分ける

共通横幅とBlock固有の配置が別の責務なら、当面はHTMLの箱も分ける形を優先する。

```html
<section class="staff">
  <div class="l-inner">
    <div class="staff__body">
      ...
    </div>
  </div>
</section>
```

```css
.l-inner {
  max-width: 1200px;
  margin-inline: auto;
  padding-inline: 20px;
}

.staff__body {
  display: grid;
  gap: 40px;
}
```

- `.l-inner`: 共通の最大幅、中央寄せ、左右余白
- `.staff__body`: staff内の並び、間隔、固有レイアウト

この形なら、変更時にどちらのクラスを触るかを予測しやすい。HTML要素は1つ増えるが、共通レイアウトとBlock内部の責務が混ざりにくい。

`staff__inner` という名前でもHTMLとして問題はない。ただし、横幅を持つ `.l-inner` の内側で、さらに「内側」という意味だけの `__inner` を置くと役割を区別しにくい。中身の本体なら `__body`、主要内容なら `__content` のように実際の役割を名前にする。

## 同じ要素へのMixは例外として使う

共通横幅とBlock固有の配置を1つの要素が自然に担当し、プロパティの責任が重ならない場合は、クラスを併用してもよい。

```html
<header class="header">
  <div class="header__body l-inner">
    ...
  </div>
</header>
```

```css
.l-inner {
  max-width: 1200px;
  margin-inline: auto;
  padding-inline: 20px;
}

.header__body {
  display: flex;
  align-items: center;
  justify-content: space-between;
}
```

クラスを2つ付けただけで、セレクタの詳細度が自動的に高くなるわけではない。

```css
.l-inner {
  padding-inline: 20px;
}

.header__body {
  padding-inline: 30px;
}
```

この2つのクラスセレクタは同じ詳細度である。同じプロパティを指定した場合は、`!important`、詳細度、記述順などのカスケードで結果が決まる。問題の中心は詳細度ではなく、`padding-inline` をどちらが担当するのか分かりにくくなることにある。

同じ要素へMixする場合も、次を守る。

- `.l-inner` だけが共通横幅と共通左右余白を持つ
- Block側は内部の並びなど、そのBlock固有の指定だけを持つ
- 同じプロパティを両方で上書きし始めたら、HTMLの箱を分ける

Block固有の指定がない場合は、`.l-inner` だけを使用する。

```html
<header class="header">
  <div class="l-inner">
    ...
  </div>
</header>
```

## 親が子の配置を決める

レイアウト崩れの多くは、子Block自身に外側配置まで持たせることから始まる。

- 親: トラック、幅、配置、子同士の間隔を決める
- 子: 自分の内部構造と見た目を決める

```css
.staff__list {
  display: grid;
  gap: 40px 20px;
}

.staff-card {
  /* カード内部の配置と見た目 */
}
```

配置責務そのものは [コンポーネントと責務](./03_コンポーネントと責務.md) も参照する。

## `margin` / `padding` / `gap` の使い分け

- `gap`: 同じ親に属する反復要素同士の間隔
- `margin`: 別Blockとの距離、文脈側の外側余白
- `padding`: 線・背景・箱の内側に必要な余白

「全体レイアウトの空白だから `margin`」「要素の近くにあるから `padding`」とは決めない。空白が対象の箱の境界に含まれるかを先に見る。

| 観測する境界 | 選ぶ候補 | 典型例 |
|---|---|---|
| 背景・線・クリック領域の内側 | `padding` | ナビ領域の左右安全余白、リンクの操作範囲 |
| 箱自体と周囲の要素との距離 | `margin` | ヘッダー内でパンくずだけを左から離す |
| 同じ親が並べる項目同士 | `gap` | ナビ項目、カード一覧 |

たとえば、ヘッダー内のすべての内容を左右30px内側へ入れるなら、共通親の `padding` が合う。

```css
.site-header__inner {
  padding-inline: 30px;
}
```

ロゴは中央のままで、パンくずだけを左端から30px離すなら、配置用の箱の `margin` が合う。

```css
.site-header__breadcrumb {
  margin-inline-start: 30px;
}
```

短い内容の右側に大きな空間が残っていても、それは利用可能幅から内容幅を引いた残りかもしれない。カンプ上の残り幅を、そのまま固定 `margin-right` や `padding-right` へ置き換えない。

`margin-inline-start` / `padding-inline-start` は書字方向の開始側を表す。通常の日本語・英語の横書きでは左側になる。案件が左から右の横書きだけを対象とし、チーム内で `left` の方が読みやすいなら、`margin-left` / `padding-left` を使ってもよい。

```txt
カード同士の間隔      -> 親一覧の gap
セクション間の距離    -> セクション側の margin-bottom
線と本文の距離        -> 内側の padding-top / padding-bottom
```

## Block間の余白

BlockとBlockの間隔は、原則として上のBlockの `margin-bottom` で管理する。

`margin-top` はページ文脈・例外調整にのみ使う。
上下両方から余白を持たせると、マージン相殺や二重余白の原因になる。

## 横方向マージンの扱い

- 横方向の `margin` は相殺されない（縦方向のcollapse前提を持ち込まない）
- 要素間スペースを `margin-left` と `margin-right` の両方で作らない
- 「左だけ」または「右だけ」の片側固定で運用する
- レスポンシブで `row -> column` / `column -> row` が起きる箇所は `gap` で管理する

```css
/* OK: 片側固定 */
.card + .card {
  margin-left: 16px;
}

/* 推奨: レスポンシブ切替を含む並びは gap で統一 */
.card-list {
  display: flex;
  gap: 16px;
}
```

## 文章（pタグ）の扱い

### 基本方針

- `p`タグ自体には余白を持たせない
- 文章の余白は親（レイアウト or Block）で制御する

```css
p {
  margin: 0;
}
```

### 文章ブロック例（汎用）

```html
<div class="richtext">
  <p>...</p>
  <p>...</p>
</div>
```

```css
.richtext > * + * {
  margin-top: 1em;
}
```

### 大きな段差が必要な場合

余白量に意味が生じた時点で、構造として扱う。
`p`にModifierや専用クラスを付けて段差を作らない。

```html
<div class="l-text">
  <p>通常段落</p>

  <div class="l-section-break">
    <p>次の話題</p>
  </div>

  <p>続き</p>
</div>
```

## Flex / Grid の並びと間隔

- 1方向の並び中心: Flex
- 行列を同時に設計: Grid
- 同一親内の反復間隔: `gap`
- 幅が想定より広がる、縮まない、はみ出す場合: [07_レイアウト](../../HTML・CSS/07_レイアウト.md) の `min-width: 0` / `flex-basis + padding` を確認する

## まとめ

- レイアウトは親が並びと幅を決める
- 子Blockは内部構造と見た目に集中する
- 反復間隔はまず `gap`
- Block間距離は文脈側の `margin`
- 箱の内側距離は `padding`
