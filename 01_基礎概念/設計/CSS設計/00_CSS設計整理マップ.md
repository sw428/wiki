# 00_CSS設計整理マップ

## 目的

このフォルダは、BEM、SCSS分割、コンポーネント責務、レイアウト責務、実装手順など、CSSまわりの設計判断をまとめる場所。

HTML・CSSの一般的な仕組みではなく、自分が実装時に採用する判断基準を置く。

## 読む順番

1. [BEMとクラス命名](./01_BEMとクラス命名.md)
   - Block / Element / Modifier の切り方、接頭辞、Mix、タイポグラフィ命名
2. [SCSSとCSS分割](./02_SCSSとCSS分割.md)
   - SCSS導入、分割、`components` / `pages` の責務
3. [コンポーネントと責務](./03_コンポーネントと責務.md)
   - 共通コンポーネント、配置ラッパー、親子Block、上書き境界
4. [レイアウトと余白](./04_レイアウトと余白.md)
   - `l-`、`.l-page` / `.l-inner`、`margin` / `padding` / `gap`、`p`の余白
5. [CSS設計の実装手順](./05_CSS設計の実装手順.md)
   - 構造決定、SPからPC、見返し、完了チェック

## 追記先の判断

CSS設計内では「CSS設計全体」を1テーマとして扱わない。
まず次のどれかへ分ける。

- BEM、接頭辞、Mix、タイポグラフィ命名は [BEMとクラス命名](./01_BEMとクラス命名.md)
- SCSS分割、`components` / `pages` / `layout`、読み込み順は [SCSSとCSS分割](./02_SCSSとCSS分割.md)
- `c-` と `p-` の境界、親子Block、配置ラッパー、上書き、Modifier、再利用昇格は [コンポーネントと責務](./03_コンポーネントと責務.md)
- `l-page` / `l-inner`、`margin` / `padding` / `gap`、`p`の余白、Flex/Gridの並びと間隔は [レイアウトと余白](./04_レイアウトと余白.md)
- 実装順、SPからPC、仮画像を使う作業順、見返し順は [CSS設計の実装手順](./05_CSS設計の実装手順.md)
- `flex-basis` や `min-width: 0` などCSSプロパティの仕組みは [HTML・CSS整理マップ](../../HTML・CSS/00_HTML・CSS整理マップ.md) から該当ノートを見る
- 案件固有のクラス名、画像名、`nth-child` 指定、固定運用は [ケース検証運用](../../../02_ケース検証/00_ケース検証運用.md) 側に残す

## 置くもの

- BEM命名の採用方針
- SCSS / CSS分割の判断基準
- コンポーネントの責務分離
- レイアウトと余白の責務分離
- `c-` / `p-` / `l-` / `u-` など接頭辞の使い分け
- ケース検証から戻した、案件を超えて使うCSS設計判断
- 実装時に再現するための作業順

## 置かないもの

- HTMLタグやCSSプロパティの一般説明だけで済む内容
- 案件固有の条件、素材、納品都合
- Blogなど特定対象に依存する画像命名
- 特定案件の `nth-child` 指定や固定運用
- JavaScriptやWordPress固有の設計判断
- 公開記録を増やすためだけの内容
