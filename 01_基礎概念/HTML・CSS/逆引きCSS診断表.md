## この診断表を正本にしない理由

以下が理由です。

この診断表は、コンピュータが毎回漏れなく走査するなら合理的だが、人間が固定手順として覚えるには重すぎる。
記憶力がある人ほど「この症状ならこの順番で見る」という正解ルートとして覚えやすく、文脈ごとに確認順を組み替える経験が減る。

一方で、覚えることが苦手な人には、現象別の項目、確認順、戻るページ、用語、例外を抱えるだけで作業メモリを使い切りやすい。
表を覚えられるかどうかと、HTML/CSSを直せるかどうかは別の能力として扱う。

このWikiで人間が持つべきなのは、細かい診断表ではなく、次のような切り口だけでよい。

- 何が起きているかを言葉にする
- HTML構造と親子関係を見る
- DevToolsで実際の適用値を見る
- 構造の問題か、CSSが当たっていない問題か、箱の大きさの問題か、親レイアウトの問題か、上書きや状態の問題かを見る
- 分からない原因候補はGPTにその場で出させ、一つずつ検証する
- 解決後に、今回の原因を基礎概念かケース検証へ戻す

固定表を覚えるより、現在のHTML、現在のCSS、DevToolsの観測結果、期待する見た目をGPTへ渡せる方が再利用性が高い。
このページは、人間に処理手順をインストールするためではなく、旧方針を見直した記録として扱う。
