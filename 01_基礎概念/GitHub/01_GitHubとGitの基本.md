# GitHubとGitの基本

## 目的

GitとGitHubを混ぜずに見るための基礎メモ。

Web制作では、VS Code上の表示、ターミナルのGit、GitHub上のリポジトリがつながって見える。
ただし、それぞれは同じものではない。

## GitとGitHubの違い

Gitは、ローカル側でファイルの変更履歴を管理する仕組み。

GitHubは、そのGitリポジトリをクラウド上に置き、共有・バックアップ・公開連携に使うサービス。

ざっくり分けるとこう見る。

- Git: 手元の変更履歴を管理する仕組み
- GitHub: その履歴を置くリモート側の場所
- VS Code: Git操作を見やすくする作業画面

VS CodeにGitHubっぽい表示が出ても、Gitそのものが消えたとは限らない。
VS Codeは、今のローカルリポジトリとリモートのつながりを見て表示を変えている。

## ローカルとリモート

ローカルは、自分のPC内にある作業場所。
リモートは、GitHub上にある共有先。

たとえば、手元に `main` ブランチがあっても、GitHub側の `origin/main` と対応づいていない場合がある。

このとき、ローカルGitは存在している。
ただし、GitHub側のどのブランチへ送るかが決まっていない。

## よく使う言葉

- `commit`: ローカルの変更履歴として記録する
- `push`: ローカルの履歴をGitHub側へ送る
- `pull`: GitHub側の変更をローカルへ取り込む
- `remote`: GitHubなど、リモート側の接続先
- `origin`: よく使われるリモート名
- `upstream`: 今いるローカルブランチが追跡するリモートブランチ

## 判断の基本

GitHubまわりで迷ったときは、いきなりボタンを押す前に次を分ける。

1. 今、どのフォルダをVS Codeで開いているか
2. そのフォルダに `.git` があるか
3. 今いるブランチは何か
4. GitHubのリモートURLが設定されているか
5. 今いるブランチにupstreamがあるか

見るコマンドは次。

```bash
git status
git branch
git branch -vv
git remote -v
```

## Web制作での見方

Web制作では、GitHubを「公開する場所」とだけ見ない。

まずは、自分が書いたコードの履歴を守る場所として見る。
そのうえで、必要に応じてGitHub Pagesなどの公開設定を見る。

`push` はコードをGitHubへ送る操作。
GitHub Pagesの公開は、GitHub側の設定とデプロイ結果で決まる。

この2つを分けておくと、`push` したのに公開ページが変わらないときに切り分けしやすい。
