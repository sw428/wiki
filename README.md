このWikiは、HTML / CSS / JavaScriptの学習や制作、GPTとの対話から得た情報を、実務で再利用できる知識として整理する学習ノートです。

読者が「何の話か」「どこで使うか」「何を基準に選ぶか」をつかみ、説明から実装と確認へ進めることを重視しています。企業・採用担当者に実装力、学習過程、判断理由を確認してもらうことと、同じ目的を持つ学習者との知識共有を目的に公開しています。

内容は学習・制作と並行して継続的に修正しています。整理途中の記事には、重複や構成のばらつきが残る場合があります。正確性においてもその時の作業段階で後から見る前提の箇所もあるので利用時は必要に応じて一次資料や公式ドキュメントとも照合してください。

人間向けの学習経路は、可能な限りカテゴリフォルダと、その配下のファイルの番号順で追えるようにしています。複数の記事を束ねるカテゴリでは、`00_...整理マップ.md`をCodex用の内部ルーター、`01_...md`を人間向けの入口にしています。

| 置き場所               | 役割                                                                       |
| ---------------------- | -------------------------------------------------------------------------- |
| [01\_導入](./01_導入/) | 何も知らない状態から、基礎本文や最小例を読めるところまでをつなぐ           |

## 整理と運用

具体例や未確認の判断は、まず04で検証します。一般性を確認できた内容は、読むための前提を01、学習・実装の中心を02、基本理解後の掘り下げを03へ反映します。

GPTとの会話は、そのまま正解や記事にはしません。今回残す疑問・判断を一つ選び、既存の記事と照合してから必要な箇所へ反映します。原文を掲載する対話ログは、整理済みの本文や確認済みの知識とは分けて扱います。

ChatGPTとの対話で実装中の疑問を掘り下げ、次の順序で記事を仕上げます。

1. **Workで記事間のつながりを整える。** 対象記事と関連ファイルを読み、必要な前提や説明の順序、関連記事への案内を確認し、読者が自然に理解を進められる修正案を作ります。
2. **一次チャットで一記事として仕上げる。** 最後に、その記事の本文だけを渡します。周辺記事や過去のレビュー、既存SVGなどを追加入力せず、文章そのものの流れと、SVGで何を示し、本文のどこでどう使うかを考え直して、本文と図を再作成します。周囲の情報に引かれず、一記事としての理解しやすさを高めるためです。
3. **Codexで採用版を反映する。** 著者が選んだ一次チャットの版を保ち、既存Wikiに合わせてフォルダ名・配置・参照を整えます。例示数値、クラス名、例文も必要に応じて同期し、作例の成立条件が崩れる場合は報告します。

採否と反映の範囲は著者が決めます。

Wiki全体の役割や考え方は、[三者運用](./00_Wiki共通/01_Wikiの運用思想/01_三者運用.md)で説明しています。

プロジェクト内の「設定・指示」に記載する文章を、Agent(work用)として扱います。指示文と詳しい制作手順は[エージェントワーク](./00_Wiki共通/01_Wikiの運用思想/AGENTS_Work.md#workと一次チャットで仕上げる順序)に保存しています。

詳しい方針や現在の状態は、次の文書で確認できます。

- [Wikiの運用思想](./00_Wiki共通/01_Wikiの運用思想/00_Wikiの運用思想.md): ChatGPT・Codex・自分の役割と正本管理
- [AI対話ログ整理マップ](./00_Wiki共通/04_AI対話ログ%28一部抜粋%29/00_AI対話ログ整理マップ.md): 原文ログの目的と、本文との区別
- [AGENTS](./AGENTS.md): Codexの行動・判断ルール
- [CURRENT](./CURRENT.md): 現在の構造、作業状況、保留事項
- [CHANGELOG](./CHANGELOG.md): 運用変更と判断理由の履歴

## SVGの使い方と保存の流れ

SVGは、本文で説明する仕組みや、指定によって何が変わるかを図でたどるために使います。本文・コード・図の対象、条件、数値をそろえ、読者が確かめたい箇所に置きます。基本の制作はGPT／Workが担当し、Codexが依頼された範囲の再評価、数値などの調整、保存・命名・参照の整備を行います。採用された形・構成・色を保ち、内容を変える必要がある場合は著者へ伝えます。

### 作業・履歴・採用・掲載の置き場所

通常のSVG作成・取り込み・掲載では、共用画像の保存先`07_画像/img/`を使います。`SVG(作業)/`は、著者が自分で調整するための受け渡しを依頼したときに使います。

| 置き場所 | 役割 |
| --- | --- |
| [SVG(作業)の直下](./SVG%28作業%29/00_SVGの手動調整.md) | 手動調整するSVGの受け渡し。不要になった作業版は削除できる |
| [svg(作業履歴)](./SVG%28作業%29/svg%28作業履歴%29/00_SVG履歴の案内.md) | 各版のSVGそのものを保存し、比較・復元に使う。変更ログもここに残す |
| [svg(採用)](./SVG%28作業%29/svg%28採用%29/00_SVG採用版の管理.md) | 著者が選んだ完成版を保管する |
| [07_画像/img](./07_画像/img/) | Wiki本文から参照する共用画像の保存先。HTML・CSSの図は`html-css/`へ置く |

### 手動調整から採用・掲載まで

1. **調整する版を保存する。** Codexは元のファイル名の拡張子の前に`(1)`・`(2)`のような番号を付け、作業用フォルダの直下へ保存します。同じ名前・同じ内容のSVGを履歴にも自動で追加し、[SVG変更ログ](./SVG%28作業%29/svg%28作業履歴%29/01_SVG変更ログ.md)へ変更内容と確認できた範囲を記録します。作業版を消した後も、履歴を含む最大番号から続きを付けます。
2. **開いて確認・調整する。** 保存後は作業版をChromeで自動で開きます。著者が手動編集した版も、保存を依頼すれば同じように履歴へ残します。過去の履歴を上書きせず、内容が変わった版は新しい番号で追加します。PC幅・SP本文幅343pxで実際に確認した範囲と、未確認の範囲は分けて記録します。
3. **完成版を選ぶ。** 著者が採用する版を指定したら、内容を保って`svg(採用)/`へ保存し、採用した一式をレビュー番号の管理に登録します。別の会話・GPT／Workなどで作られた図も、採用指定されたものは同じ扱いです。採用フォルダへの保存と、Wiki本文への反映は別に管理します。
4. **Wikiへ反映する。** 著者が承認した対象と範囲で、掲載用の図を`07_画像/img/`へ配置し、本文からの相対リンクを整えます。採用版の内容と、本文・コード・図の対応を確認し、反映状態を記録します。

括弧の番号は、手動調整した個々の版を見分けるためのものです。`r001`・`r002`などのレビュー管理番号は、採用・再整理するファイル一式を識別するもので、保存のたびには増やしません。所属・状態・更新記録は[ファイル一覧](./00_Wiki共通/02_再整理/01_ファイル一覧%28Codex用%29.md)、図の一覧は[画像一覧](./00_Wiki共通/02_再整理/03_画像一覧%28ユーザー用%29.md)で確認できます。

### 変更・削除の扱い

このリポジトリ内の採用版は削除せず、内容を自動で変更しません。数値・文字・形・色を直す場合も、対象・変更案・理由・影響を示し、著者がその変更を承認した後に進めます。承認された修正は作業版で行い、元の採用版を残して、新しい採用版を別名で追加します。

作業用フォルダ直下のSVGを削除しても、履歴と採用版は残します。「SVGを消して」のように対象が分からない依頼では、どの場所のどのファイルを消すかを確認します。詳しい保護と変更権限は[AGENTSの本文用画像の管理](./AGENTS.md#本文用画像の管理)を正本とします。

### エクスプローラーでの誤削除を防ぐ

エクスプローラーで自分が直接ファイルを操作すると、作業を速く進める中で、フォルダごと誤って削除してしまう可能性があります。手動調整に使う次の3フォルダは、Codexに依頼して、利用するPCのWindowsのアクセス権でフォルダ本体を削除できないように設定することを推奨します。

- `SVG(作業)/`
- `SVG(作業)/svg(作業履歴)/`
- `SVG(作業)/svg(採用)/`

保護はフォルダ本体を対象とし、作業用SVGの編集・保存は続けられるようにします。フォルダ自体の移動・名前変更も制限されるため、必要になったらCodexへ保護の解除を依頼してください。

この削除防止設定はPCごとの設定です。GitHubからcloneまたはダウンロードしても引き継がれないため、別のPCで使う場合は、そのPCで設定します。

## 公開範囲と権利関係

このWikiでは、自分の学習内容、実装方針、判断理由を整理して全て公開しています。

会社・クライアントの未公開情報や実案件の資料・ソースコードは公開しません。実務に関する内容は、元の案件を推測できないように抽象化・一般化して記録します。

教材、画像、ロゴ、デザインカンプなど第三者が権利を持つものは、それぞれの権利者に帰属します。教材の課題文、提供素材、解説本文などを再配布する目的ではありません。
