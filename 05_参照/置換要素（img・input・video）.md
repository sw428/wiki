# 置換要素（img・input・video）

## このページの役割

`img`や`video`などでは、通常のテキスト要素とは異なり、要素自身の子テキストをそのまま表示内容として扱わない場合がある。

このページでは、

```text
置換要素とは何か
↓
通常の要素と何が違うか
↓
imgを代表例として見る
↓
要素や状態によって扱いが変わる条件を知る
↓
void要素とは別の分類だと分ける
```

という順番で整理する。

## 置換要素はCSSの整形モデル側の分類

置換要素は、画像や埋め込み文書のように、表示される内容がCSSの通常の整形モデルの外側にある要素。

たとえば、通常のテキスト要素では、

```html
<p>こんにちは</p>
```

HTML内に書いた文字が内容になる。

一方、画像を表している`img`では、

```html
<img src="photo.jpg" alt="作業画面">
```

HTML内に子テキストを書いて表示するのではなく、`src`で参照した画像が表示内容になる。

```text
通常のテキスト要素
HTML内の内容
↓
表示内容になる

画像を表すimg
srcで参照した画像
↓
表示内容になる
```

この違いを扱うのが、置換要素という分類。

## imgを代表例として見る

正常に画像を表している`img`は、置換要素を理解する代表例として扱いやすい。

```html
<img src="photo.jpg" alt="作業画面">
```

画像には、その画像自身が持つ幅や高さ、縦横比がある。

そのため、

```css
img {
  width: 100%;
  height: auto;
}
```

のようにCSSで表示寸法を指定するときも、通常のテキストだけを持つ要素とは異なり、画像自身が持つ寸法や比率が関係する。

[通常の非置換inline要素](./非置換inline.md)では`width`や`height`がそのまま寸法を決めないが、置換要素ではinlineの位置にあっても、自然寸法やCSSの寸法指定がサイズ計算に関係する。

画像の具体的な幅・高さ・比率の設計は、[レスポンシブ画像設計の選び方](../02_基礎/01_HTML・CSS/12_レスポンシブ画像設計/01_レスポンシブ画像設計の選び方.md)から確認する。

このページでは、

```text
imgには
要素内部の通常のテキストとは別に
画像という表示内容がある
```

という点を押さえる。

## すべてを要素名だけで判断しない

HTML Standardでは、

```text
audio
canvas
embed
iframe
img
input
object
video
```

が置換要素になり得る要素として挙げられている。

ただし、

```text
この要素名なら
すべての状態で同じ扱い
```

と単純に決められるとは限らない。

要素が現在何を表しているかや、要素の種類によって扱いが変わる場合がある。

## canvasやobjectは状態によって扱いが変わる

`canvas`は埋め込みコンテンツを表しているときに置換要素として扱われ、それ以外では通常の要素として扱われる。

`object`も、画像、プラグイン、埋め込まれた閲覧コンテキストを表している場合などに置換要素として扱われる。

そのため、

```text
canvas = 必ず置換要素
object = 必ず置換要素
```

と暗記するより、

```text
要素によって
置換要素として扱われる条件がある
```

と捉える。

個々の要素の細かい条件は、その要素を実装するときに確認する。

## imgも常に同じ扱いとは限らない

`img`も、

```text
imgという要素名
↓
必ず同じ置換要素の状態
```

とだけ覚えると例外を見落とす。

正常に画像を表している`img`は、置換要素の代表例として考えられる。

一方、画像を表せない場合には、代替表示の条件によって非置換要素として扱われることがある。

最初は、

```text
正常に読み込まれ
画像を表しているimg
→ 置換要素の代表例
```

として理解し、例外は必要になったときに確認する。

## inputとvideoは条件を分けて見る

`video`は置換要素として扱われる。子に`source`や代替内容を書けても、表示される動画やポスター画像は通常の子テキストと同じ方法ではレイアウトされない。

`input`は種類によって表示内容が異なる。たとえば`type="image"`の`input`が画像を表している場合は、置換要素として扱われる。

ここでも重要なのは、

```text
要素名だけで
すべての種類や状態を一律に判断しない
```

こと。具体的な条件は、それぞれの要素を扱うときに確認する。

## void要素とは別の分類

`img`は、HTMLではvoid要素でもある。

そのため、

```text
img
→ void要素
→ 置換要素
```

と一つの性質から説明したくなるが、この2つは別の分類。

| 分類 | 答える疑問 |
| --- | --- |
| void要素 | HTML構文で終了タグや子の内容を持つか |
| 置換要素 | CSSの整形モデルが要素の表示内容を通常どおり扱うか |

たとえば、

| 要素 | void要素 | 置換要素としての扱い |
| --- | --- | --- |
| `img` | はい | 画像を表す場合は、はい |
| `br` | はい | いいえ |
| `video` | いいえ | はい |
| `div` | いいえ | いいえ |

`img`は両方に当てはまる場合があるが、

```text
void要素だから
置換要素になる
```

わけではない。

`video`のように、void要素ではなくても置換要素として扱われるものもある。

終了タグと子の内容の規則は、[void要素と終了タグを理解する](../02_基礎/01_HTML・CSS/01_HTMLの土台/05_void要素と終了タグを理解する.md)で確認する。

## 迷ったときの分け方

確認したいことが、

```text
終了タグを書くのか
子の内容を持てるのか
```

なら、void要素の話。

確認したいことが、

```text
画像や動画などの表示内容を
CSSがどのように扱うのか
```

なら、置換要素の話。

この2つを分けると、HTML構文とCSS上の表示特性を混同しにくい。

実装時は、置換要素かどうかだけでなく、次も分けて確認する。

1. 要素の箱の幅・高さは何から決まったか。
2. `object-fit`や`object-position`で、決まった箱の中の内容をどう表示するか。
3. inlineの位置にある場合、ベースラインによる隙間が生じていないか。

箱の寸法は[ボックスモデルの4領域](../02_基礎/01_HTML・CSS/05_ボックスとdisplay/03_ボックスモデルの4領域.md)、画像と背景の選択は[imgとbackground-imageを選ぶ](../02_基礎/01_HTML・CSS/10_画像と背景/01_imgとbackground-imageを選ぶ.md)、行内の揃い方は[ベースラインと見た目のずれ](../02_基礎/01_HTML・CSS/08_インラインと行の仕組み/04_ベースラインと見た目のずれ.md)で扱う。

## 一言でいうと

置換要素は、画像などの表示内容がCSSの通常の整形モデルの外側にあり、その内容を持つ要素の種類や状態によって扱いが変わることもある分類。

void要素とは別の軸で考える。
