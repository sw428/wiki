# 文脈リセットと出力解釈

## 目的

ChatGPTの文脈をリセットした直後に出力がずれたとき、モデルそのものの性能低下と決めつけず、入力語、共有前提、専門分野の慣習、回答時点で新しく加わった文脈を分けて確認するための参照カードです。

GPTを全面的に信用するか、間違えるものとして疑うかの二択ではなく、なぜその出力が成立したのかを確認し、ツールとしての信頼範囲を調整できるようにすることを目的とします。

## 前提

LLMは、HDDのような記憶装置から、過去の知識や思考過程をそのまま取り出して回答しているわけではありません。

入力された言葉、それまでの会話、共有されている前提などをもとに、文脈上続く可能性の高い表現を生成します。

無関係な言葉の中から、人間と同じ方法で「一番正しい言葉」を意識的に選んでいるわけではありません。一方で、完全にでたらめな言葉をランダムに並べているわけでもありません。

その時点の文脈から、確率的に妥当性が高いと処理された出力が生成されます。

そのため、モデル自体の処理能力が変わっていなくても、文脈や共有前提が変われば、同じ言葉に対する解釈や出力は変化します。

## 確認すること

- 文脈リセット後は、ユーザーとの共有前提が少ない。
- 過去の会話で作られた「当たり前」も失われる。
- 曖昧な言葉は、専門分野の慣習より一般的な意味へ寄ることがある。
- 出力のずれだけで、LLMそのものの処理能力が低下したとは判断できない。
- 出力後に理由を聞いても、最初の判断過程が保存されて返るとは限らない。
- 質問された時点で、ユーザーの訂正、不満、期待する回答が新しい文脈として加わる。
- 返ってきた理由は「内部処理の完全な記録」ではなく、原因候補として扱う。
- 原因を考えるときは、実際の入力、文脈、仕様、出力結果を分けて確認する。

## 観測例

HTML / CSSの会話で、`line-height`を「pxから割合で出して」と依頼したところ、文脈をリセットした直後には`%`指定が返ることがありました。

今回ユーザーが意図していたのは、次のような単位なしの倍率です。

```css
.example {
  line-height: 1.5;
}
```

しかし、「割合」という日本語は、一般的にはパーセントと結び付きやすい表現です。

また、CSSでも`line-height`のパーセント指定自体は構文上成立します。

そのため、パーセント指定は完全に無関係な回答ではなく、次の条件が重なって成立した可能性があります。

- HTML / CSSについての共有文脈がまだ薄かった
- ユーザーが「割合」を単位なし倍率の意味で使うという前提がなかった
- 「割合」という一般語がパーセントと結び付きやすかった
- CSSでもパーセント指定が成立した
- 「単位なしの倍率にする」という指定が明文化されていなかった

この例では、モデルそのものの根本的な処理能力が落ちたと考えるよりも、文脈リセットによって共有前提が減り、一般語としての解釈が出力へ反映された可能性として捉えます。

なお、`1.5`のような単位なしの値とパーセント指定では、継承時の計算などに違いがあります。

したがって、どちらでも同じという意味ではなく、出力された指定が現在の実装意図に合っているかは別途確認します。

## 性能が落ちたように見える理由

文脈を継続すると、ChatGPTはユーザーの言葉の使い方、好み、過去の判断、扱っている分野へ適応します。

これにより、短い指示でも意図が通りやすくなります。

文脈をリセットすると、この適応によって補われていた前提がなくなります。そのため、以前は通じていた表現が通じなくなり、モデル自体の性能が落ちたように見えることがあります。

しかし、変化しているのは根本的な処理能力ではなく、判断へ使える文脈や、出力が適応している範囲かもしれません。

文脈リセットには、過去の認識への迎合を減らし、別の入口から判断材料を得られる利点があります。

一方で、以前は共有されていた専門分野の前提や、ユーザー固有の言葉の使い方まで失われるというデメリットがあります。

## 理由を聞くときの注意

パーセント指定が返ったあとに、

> なぜパーセントにしたの？

と質問すると、ChatGPTから次のような回答が返る場合があります。

> 確かにCSSの話なので、`1.5`のような単位なしの値にするのが自然でした。

この回答だけを、最初にパーセントを選んだ理由の正確な再現とはみなしません。

質問した時点では、次の情報が新しい文脈として追加されています。

- ユーザーはパーセント指定を問題視している
- ユーザーは別の表記を期待していた
- 元の回答には修正が必要だと考えている
- 「なぜ」と聞かれたため、説明や謝罪が求められている

ChatGPTは、この新しい文脈も含めて次の回答を生成します。

そのため、ユーザーの認識に合わせた説明や、会話として協調的な回答が生成されることがあります。

これは、ChatGPTが意図的に本当の内部処理を隠していると決めつけるものではありません。

そもそも、出力後のChatGPTが最初の判断過程を完全な記録として読み出し、人間へそのまま提示しているとは限りません。

安全性や会話上の配慮などを含む製品側の応答傾向と、LLMの生成上の性質を、個別の出力だけから完全に切り分けることもできません。

したがって、返ってきた説明は、内部処理の確定情報ではなく、入力と結果を説明できる原因候補の一つとして扱います。

## 原因確認の聞き方

原因を確認したいときは、こちらの訂正を最初から正解として含めすぎないようにします。

```txt
私の訂正を正しい前提として合わせるのではなく、
元の「pxから割合で出して」という依頼だけから成立する解釈を複数挙げてください。

そのうえで、パーセントを選びやすくした言葉と、
不足していたHTML / CSS上の文脈を分けて説明してください。

なお、この説明も元の内部処理の確定記録ではなく、
入力と出力から考えられる原因候補として示してください。
```

確認するときは、次の情報を分けます。

- 実際に入力した言葉
- その時点までに共有されていた文脈
- 文脈リセットによって失われた前提
- 入力から成立し得る複数の解釈
- CSSなど対象分野の仕様
- ChatGPTが実際に出力した結果
- ユーザーが本来意図していた結果
- 質問を変えたときの回答の変化
- 一次情報や実際の表示結果との一致

## 依頼を明確にする場合

同じずれを避ける必要がある場合は、「割合」という言葉だけに依存せず、求めている形式を指定します。

```txt
line-heightをpx指定から、
1.5のような単位なしの倍率へ変更してください。
パーセント指定にはしないでください。
```

ただし、毎回すべての指示を完全に書かなければGPTを使えない、という意味ではありません。

曖昧な表現によって実装上の違いが生まれる場所だけ、必要に応じて明確にします。

## 信頼の調整

このような挙動を知らないと、次のような認識になりやすくなります。

- GPTを使うには、常に完璧なプロンプトが必要である
- GPTは理由もなく適当なことを言う
- 文脈を消すとモデルの性能そのものが落ちる
- GPTの説明は、内部で行われた処理の正確な記録である
- 間違いがあるため、GPT全体を信用できない
- もっともらしいため、GPTの回答をそのまま信用してよい

しかし、全面的に信用することと、全面的に疑うことのどちらかへ固定する必要はありません。

出力がずれたときは、何が間違っていたかだけでなく、なぜその表現が成立したのかを考えます。

原因が分からないまま疑いだけを残すと、不確定な感覚や不信感を抱えたまま使い続けることになります。その状態が積み重なると、どこかでツールの使用自体をやめてしまう可能性があります。

一方で、仕組みや適用範囲を確認せずに信じ続けても、誤りが重なったときに心理的な負担へ耐えられなくなる可能性があります。

重要なのは、GPTを信じるか疑うかではなく、どの範囲まで信頼でき、何を確認する必要があるかを自分で把握することです。

## 他者の意図を読み取ることとの関係

入力、文脈、一般的な言葉の意味、専門分野の慣習を分けて考えることは、GPTを使うためだけのものではありません。

なぜその言葉、説明、コード、設計が選ばれたのかを考える経験は、他者の意図や前提を読み取るための訓練にもなります。

ただし、自分が推測した意図を、そのまま相手の本当の意図として確定してはいけません。

必要に応じて、本人、仕様、一次情報、コードの動作、成果物によって確認します。

うまくいかないときに、単純に相手の能力不足や自分の伝達不足と決めつけるのではなく、どの前提で処理され、どこで認識が分かれたのかを確認します。

質問の仕方を変えながら、相手がどのような情報をもとに回答しているのかを理解できれば、人とGPTの双方がパフォーマンスを発揮しやすくなります。

## 混同しやすいもの

- 文脈リセットによる共有前提の不足
- LLMそのものの処理能力低下
- モデルや製品側の実際の変更
- 専門用語としての意味と一般語としての意味
- ユーザーの意図と、入力文から読み取れる内容
- 最初の出力理由と、訂正後に生成された説明
- 会話上の協調性と、内部処理を意図的に隠すこと
- 確率的な生成と、根拠のない完全なランダム出力
- GPTへの適切な信頼と、無条件な信用
