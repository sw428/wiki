# 三者運用

## このページの役割

ChatGPT、Codex、自分の役割分担と、対話・検証・整理を繰り返しながらWikiを育てる基本方針を扱います。

## 運用方針

このWikiは、GPTとの会話を整理材料として受け取り、Codexが既存の正本と照合しながら分類・反映するように設計しています。具体的な条件、事象、検証履歴はまず `04_検証` で受け、公式仕様、独立した最小検証、複数ケース、既存基礎概念との一致などで一般性を確認します。その後、中心に読む知識を `02_基礎`、それを読むために独立して説明する前提を `01_前提知識`、追加の疑問や例外を `03_詳細` へ振り分けます。

単なる会話ログの保存ではなく、実装中に出てきた疑問や判断をもとに、再利用しやすい知識へ変換していくことが目的です。

内容ごとの汎用性を判定し、未確認の主張や未採用の方針は保留として扱います。本人の理解が曖昧な箇所は、必要な前提や説明順を見直す手掛かりにします。内容の確かさと、読み手が理解できたかどうかは別に確認します。

記憶力や整理能力にかかるコストをできるだけ減らし、社会で求められる仕事に対して、必要最低限のパフォーマンスを安定して出すための補助として使います。

## ChatGPT / Codex / 自分の役割

ChatGPTは現在の対話と判断を進める司令塔、Wikiは採用済み判断を保存する長期的な正本、Codexは既存状態を確認しながら正本へ安全に反映する実作業担当です。ユーザーは目的と最終決定権を持ち、自分で確認できる範囲の検証と採否の判断を行います。

自分は三者の関係をメタ的な視点から観測し、対話と実装を通じて自分自身の能力を底上げしていきます。

対話と実装を往復しながら、つまずきやすい概念、理解が進んだ説明、あとから修正された認識を記録します。

Codexの内部運用は、トップの `AGENTS.md` を正本にしつつ、カテゴリごとの細かい手順は各 `00_...整理マップ.md` / `00_...運用.md` に寄せます。判断性能や好みを保ちながら、ケース整理、ファイル移動、単語カード追加などの反復作業を見通しよく扱うためです。

## 日本語で対話しながら育てる

大事なのは、最初から仕様を完全に理解することでも、自分ひとりで完璧にまとめることでもありません。

まず、自分が考えていることを日本語でCodexに伝えます。その出力を確認しながら、次を見ます。

- 何が形になったか
- 何をWikiシステムとして残せそうか
- どこが自分の意図とずれていたか
- 何がうまく伝わらなかったか
- 次にどう伝えればよいか

最初から正しい指示を出すことより、出力を見て会話しながら調整することを重視します。

会話から疑問を拾い、前提を探し、説明順と配置を考え、文章を点検する作業はCodexが担います。ユーザーが先にすべてを分類したり、内部処理を理解したりする必要はありません。一方、Codexの推測だけでは本人がついていけたかは分からないため、少量の記事を読み、「ここで分からなくなった」という反応をもとに調整します。ルールを作ったことを、学習効果の確認とは扱いません。

うまくいかなかった出力も、自分の考え方、Codexへの伝え方、Wikiに残すべきルールを見つける材料です。このWikiシステムは、仕様を暗記して作るのではなく、日本語で考えを伝え、出力を確認し、ずれを修正しながら育てます。

## 会話からCodex自身の運用を作る

現在の運用は、ユーザーが最初から完成したエージェント構成や処理手順を指定して作ったものではありません。ユーザーが目的、違和感、優先したいことを会話で伝え、Codexが既存のWikiと会話の文脈を読み、必要な分類、ファイル構成、説明順、確認方法を提案して実装する中で形になりました。

ユーザーは、方向性が変わる判断、残したい価値、出力への違和感をCodexと話し合います。合意した方向を実現するための反映先の調査、既存本文との照合、小さな構造調整、リンク修正、差分確認はCodexに任せます。すべての作業手順をユーザーが先に指定するのではなく、Codexがその時点の文脈から必要な処理を組み立てられる余地を残します。

Codexに何が可能か、どこまで任せられるかが不明なときは、Codex自身にも現在の機能、実行方法、限界を説明させ、その内容をもとに実現可能な設計を作らせます。ただし、Codexによる自己説明をそのまま事実とは扱いません。実際のrepo、設定、実行結果、必要に応じた公式情報と照合し、可能だと確認できた方法だけを採用します。

このため、現在の「エージェント」は、外部から固定した役割一覧を与えたものではなく、会話、提案、実装、確認、修正を繰り返す中でCodex自身も設計に参加して形成された運用です。調査、分類、執筆、レビューを常設の別Agentへ機械的に分けず、Codexが文脈を保ったまま必要な役割へ切り替えます。リンク切れや差分など機械的に確認できる作業は固定し、意味や説明の主従に関わる判断は会話と文脈に残します。

成功した判断をすべて新しいルールにはしません。同じ迷いが繰り返される境界、安全性、変更権限、正本の置き場所だけを明文化し、それ以外はCodexが既存状態から判断できる余白として残します。

## 認識の変化を残す

確定知識だけでなく、実装中の違和感、検証履歴、主観的理解、GPTとの照合結果も扱います。

知識を単発で並べるのではなく、次を見える形にします。

- どの概念で何度もつまずいたか
- どの説明で理解が進んだか
- どの認識があとから修正されたか
- 実装上どこに重みを置くべきか
- 自分がどの順番で問題を切り分けているか

### 学習ロードマップとして残す

このWikiには、現在の正しい知識に加えて、理解をどう積み上げてきたかも残します。理解が進んだことは、初期の説明が不要になったことを意味しません。時間が空いたあとでも、最初に何を意識し、どこまで確かめてから次へ進めばよいかをたどれることを重視します。

たとえば、段階を分ける必要があるテーマでは、次の役割を見出しで分けると再開地点を探しやすくなります。

| 説明の役割 | 残す内容 |
| ---------- | -------- |
| 最初に押さえること | 使い始めるときに意識する範囲 |
| 今は考えなくていいこと | その段階の目的・条件では後回しにできること |
| ここまでできれば十分 | 次へ進むために確かめること |
| 次に増やす認識 | ここまでの理解に何を加えると、何を扱えるようになるか |
| 認識の修正 | 以前の捉え方の不足や誤りと、修正した理由 |
| 現在の理解 | 現在使ってよい説明と、その適用範囲 |

これは全ページ共通の履修順ではなく、テーマに応じて使う構成例です。段階が複数ある場合は、各段階で意識する範囲と次へ進む目安を対応させます。本人の認識が実際には前後したり、必要になってから戻ったりした経緯も、整った一本道へ書き換えません。

同じ概念でも、入口の説明、仕組みの説明、実装時の判断は異なる役割を持ちます。役割を見分けられる構成にすることで、文章量が増えても今読む範囲を選べます。現在の知識の正本は一つに保ち、案件固有の認識や検証の経緯は既存のケース側からたどる形にします。整理・統合時の保持ルールは [AGENTSの「学習経路の保持」](../AGENTS.md#学習経路の保持)を正本とします。

記事の題名や各節をつなぐ行動ルールは、[AGENTSの説明方針](../AGENTS.md#読者の疑問から説明を組み立てる)に置いています。学習段階を残したうえで、その段階の読者が「何の話か」「どこで使うか」をつかめる入口を作ります。

## 明文化しすぎない設計

このWikiは、ユーザー / ChatGPT / Codexが意思疎通しながら認識をすり合わせる中間媒体でもあります。そのため、すべての判断基準を各ファイルへ直接書き切る運用にはしません。

直接記述を増やしすぎると、ルールが固定化され、文脈ごとの調整余地が狭くなります。本来は会話、検証、実装の流れで調整すべき判断まで硬直化しやすくなるため、一部の認識は会話や検証履歴の流れで共有する前提として扱います。

これは記述漏れではなく、調整幅を残すための意図的な設計です。

## 三者の性能を制限しない

このWikiは、ユーザーがChatGPTやCodexの出力をすべて事前に理解し、完全に制御することを前提にしていません。

ChatGPTやCodexには、ユーザー個人が把握しきれない知識の包括性、処理能力、整理能力があります。AIをユーザーの現在の理解範囲へ無理に縮小させず、それぞれが最大限の性能を発揮できる余地を残します。

ただし、AIへ判断を丸投げするわけではありません。出力、整理、反映の結果は、最終的にユーザーが確認し、必要に応じて修正します。ChatGPTやCodexには、ユーザーへ過度に迎合せず、認識のずれ、不足、別の視点を提示できる状態を維持します。

三者間の対話と検証を繰り返し、判断精度、再利用性、整理能力が相互作用によって伸びる設計を目標にします。
