# HTML・CSSの箱と余白を図示する規約

HTML・CSSの箱、余白、Gridを説明する図の関係と数値を再評価するための確認先。基本の制作・形・色はGPT／Workに任せ、Codexは[説明図共通規約](./02_説明図共通規約.md)と[数値調整の規則](../../AGENTS.md#例示数値の置換)に従って整合を確認する。色調・固定パレット・親枠の形や線幅の指定は設けない。

## 親要素

- 親の範囲、子の箱、実際のCSSのborderが区別できるか確認する。説明用の枠・補助線・表示上のすき間を、実際のborder・padding・gapとして読ませていないかを見る。
- 親の寸法を変える例では、子の位置や利用できる幅が変更後の条件に合っているかを見る。元図が示す包含関係や省略の意味を保ち、枠の作り方を合わせ直さない。

## Gridの列・行・gap

- 列・行のトラック、そこへ置かれるGridアイテム、gap、未使用領域、空のトラックを取り違えていないか確認する。
- gapがトラック間の領域として示され、親の未使用領域やセル内の余りまでgapとして扱われていないかを見る。アイテムがトラックにまたがる場合は、その配置との対応を確かめる。
- 明示トラックと暗黙トラック、子が入っているかどうかの区別が図と説明で一致しているか見る。色・線種での区別方法を一律に指定しない。

## 領域色・外枠・要素の識別

- 制作側が選んだ色やラベルで、同じ要素・領域の対応を追えるか確認する。比較図で同じ対象が理由なく別のものとして扱われていないかを見る。青・赤・黄色などへの塗り替えは行わない。
- marginの指定値、相殺後の実際の間隔、重なり、移動する対象と量を区別する。矢印の対象・向き・両端が、その条件での配置結果と合っているかを見る。
- top／bottomなど指定する側を表す名前だけで移動方向を判断せず、作例の成立条件と実際の配置への影響を確認する。

## paddingと例示数値の関係

- paddingの範囲と実際の背景色の説明が、本文・コードに合っているか確認する。説明用の着色と、CSSで指定した背景色を区別し、特定の緑への変更を必須にしない。
- 比較条件や等しい値であることに意味がある場合は、その関係を保つ。例示値を切りのよい数値へ調整したら、計算結果・寸法・座標を同時にそろえ、結果を独立に丸めない。
- 親のpadding、子のmargin、gap、borderなど、数値が何に属するかを明確にする。可読性や関係を数値の同期だけでは保てない場合は、制作側へ戻す修正候補として報告する。
