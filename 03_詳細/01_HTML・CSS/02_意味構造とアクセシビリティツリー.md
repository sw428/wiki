# 02_意味構造とアクセシビリティツリー

主な基礎：[04_HTMLの意味と構造](../../02_基礎/01_HTML・CSS/04_HTMLの意味と構造/01_意味からHTML要素を選ぶ.md)。要素を選んだ後、「見出しやボタンの役割は、支援技術へどう伝わるのか」が気になったときに読む。

## 見た目の箱と、伝わる役割を分ける

```html
<div class="action">詳しく見る</div>
<button type="button" class="action">詳しく見る</button>
```

CSSで似た外見にしても、前者へボタンの意味や操作機能が自動で付くわけではない。ブラウザは表示のための構造だけでなく、役割・名前・状態などを支援技術へ伝えるためのアクセシビリティツリーも扱う。

| 確認したいもの | 対応する仕組み |
| --- | --- |
| 要素・文字・属性の構造 | DOM |
| スタイルシートやCSSルールの参照・操作 | CSSOM |
| 配置のために生成される箱の構造 | box tree |
| 支援技術へ伝える役割・名前・状態の構造 | アクセシビリティツリー |

これは一つのツリーが順番に変身する図ではない。表示側の計算と描画は[ブラウザの基本フロー](../../02_基礎/01_HTML・CSS/07_ブラウザ挙動と表示のズレ/01_ブラウザが表示を作る基本フロー.md#基本フロー)で扱う。

アクセシビリティツリーもDOMをそのまま複製したものではない。HTMLの意味やARIA属性、表示・非表示などが関わるため、「CSSはアクセシビリティに一切影響しない」とは捉えない。

## AOMは、ツリーそのものの別名として使わない

AOM（Accessibility Object Model）は、支援技術へ渡す情報の指定や参照を可能にする、Web標準・APIの拡張に関する取り組みを指す。ここで説明する「役割・名前・状態を持つ構造」は、アクセシビリティツリーと呼ぶ。

以前の基礎記事では「AOM / アクセシビリティツリー」を並べて同じもののように扱っていた。構造とAPIの話を混同しないため、この表現を訂正した。[AOMの説明](https://wicg.github.io/aom/explainer.html)を参照。

## 章の区切りとランドマークは同じではない

セマンティックHTMLは役割に合う要素を使う考え方。セクショニングコンテンツは `article / section / nav / aside` など文書の区切りに関わる分類。ランドマークは、支援技術で主要領域へ移動する目印になる役割である。

| HTML | ランドマークとの関係 |
| --- | --- |
| `main` | 主内容を示すmain |
| `nav` | navigation |
| `aside` | complementary |
| ページ全体の `header` | 条件を満たすとbanner |
| ページ全体の `footer` | 条件を満たすとcontentinfo |
| `section` | aria-labelまたはaria-labelledbyでアクセシブルな名前を持つとregion |
| `article` | 記事の役割を持つが、ランドマークではない |

header・footerが `article / aside / main / nav / section` の子孫なら、それぞれページ全体のbanner・contentinfoとしては扱われない。画面上の位置だけで決まる条件ではない。[WAIのランドマーク解説](https://www.w3.org/WAI/ARIA/apg/practices/landmark-regions/)を参照。

見出しを中へ置くことと、領域へ名前を付けることも別。すべてのsection・articleへ機械的にARIAを足すのではなく、領域を識別する必要があるかを確認する。

## 確認した役割を、元のHTMLへ戻す

調べたい要素について、表示上の形、HTMLの役割、支援技術へ渡る名前・状態を分ける。A11y（Accessibility）は読み上げだけでなく、キーボード操作なども含むため、ツリーの名前が正しいだけで操作の確認を終えない。
