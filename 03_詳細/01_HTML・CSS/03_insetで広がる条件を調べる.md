# 03_位置を指定しただけなのに、なぜ箱まで広がる？

この記事は、[メディア設計の「画像の上に文字を重ねる基本形」](../../02_基礎/01_HTML・CSS/11_メディア設計/03_画像の上に文字や部品を重ねる.md#画像の上に文字を重ねる基本形)で使う `inset: 0` のサイズ計算と、条件を変えたときの違いを掘り下げる。作り方を確認したいときは、リンク先の基礎へ戻る。

## 「位置だけ変わる」と思っていたら、大きさも変わった

例えば、画像の上に「お知らせ」という文字を置きたいとする。文字を入れたpに、上から・左からの位置を指定する。

> 位置を指定するのだから、文字の箱が移動するだけだと思うかもしれない。

ところが、上下左右の端をまとめて指定すると、**幅や高さを数値で書いていなくても、pの箱が画像の範囲いっぱいまで広がることがある**。

ここでいう「箱」は、HTMLのpなどが画面上で占める領域のこと。文字自体が大きくなる話ではない。

なぜなら、「左端をここ、右端をここ」と決めると、**その間の幅も決まる**から。高さも同じ。この計算が使われるのが、幅・高さを`auto`に任せている場合の一つ。

このページでは、「位置を決める指定が、どうして大きさにも関係するのか」を順に見る。CSSの名前では、`top`・`left`などと、それらをまとめる`inset`の話になる。

作り方から試したい場合は、[箱の中央に文字を重ねる](../../02_基礎/01_HTML・CSS/11_メディア設計/03_画像の上に文字や部品を重ねる.md#箱の中央に文字を重ねる)へ戻る。

## top・leftも位置の指定？

そう。ただし「座標」は、ページ全体の絶対的な座標というより、**基準となる領域の端からの距離**と考える。このページでは`position: absolute`の場合を扱う。

```css
.child {
  position: absolute;
  top: 0;
  left: 0;
}
```

`top: 0`は上端から0、`left: 0`は左端から0。余白が0なら左上にそろう。他のCSSで`right`・`bottom`が指定されていなければ、この2行で反対側の端まで広げる条件は付かない。

対して、左右の両端を指定し、幅が`auto`なら、その間を埋める幅が計算される場合がある。上下も同じように考えられる。

次の表は、普通のpやdivで、幅・高さが`auto`、余白が0、最小・最大サイズや縦横比などの追加制約がない場合。表に書いていない方向は`auto`とする。

| 指定 | 位置の条件 | サイズへの結果 |
| --- | --- | --- |
| `top: 0; left: 0;` | 上と左だけ決める | この指定だけでは全面を埋めない |
| `left: 0; right: 0;` | 左右の両端を決める | 横方向を埋める幅になる |
| `top: 0; bottom: 0;` | 上下の両端を決める | 縦方向を埋める高さになる |
| `inset: 0;` | 上下左右の端を決める | 横・縦の両方を埋めるサイズになる |

例えば、[練習例](../../02_基礎/01_HTML・CSS/11_メディア設計/03_画像の上に文字や部品を重ねる.md#箱の中央に文字を重ねる)の`.demo__text`で、`inset: 0`を**外して**`top: 0; left: 0;`に置き換えると違いを試せる。`inset: 0`を残したまま2行を足しても、`right: 0`・`bottom: 0`が残るので比較にならない。

## 幅を書いていなくても、両端の位置から大きさが決まる

### 省略形なのにサイズまで変わるのはなぜ？

`inset`が`top`・`right`・`bottom`・`left`をまとめて書く省略形であることは正しい。その説明に、**絶対配置では、位置とサイズを組み合わせて箱の大きさを決める**という仕組みが加わる。

位置指定とサイズ指定は、完全に独立して働くわけではない。両端の位置を決め、サイズを自動計算に任せると、その両端に収まるサイズが求められる。

この節は普通のpやdivが対象。余白・padding・borderは0、縦横比や最小・最大サイズなどの追加制約はないものとして、まず仕組みだけを見る。

### autoは「元の大きさを保つ」ではない

`width: auto`は、横幅をpxなどの値で直接決めず、その要素に適用されるレイアウトの規則で決める指定。`height: auto`も同様に高さを決める。

`auto`は「常に中身のサイズ」「常に100%」「今の大きさを維持」のどれかに固定された意味ではない。通常の配置か絶対配置か、両端が指定されているか、imgか、といった条件で計算方法が変わる。[絶対配置の自動サイズの仕様](https://www.w3.org/TR/css-position-3/#abspos-auto-size)を参照。

幅・高さの初期値は`auto`なので、他のCSSやHTML属性によるサイズ指定がなければ、わざわざ書かなくてもこの計算に入る。既存の`width: 200px`が効いている要素は、別の場所でwidthを省略してもautoには戻らない。

### 左から20px・右から30pxと決めると、幅は何pxになる？

次のコードを単独で試す。触る場所は、外側の`.area`と、その中の`.label`。

```html
<div class="area">
  <p class="label">お知らせ</p>
</div>
```

```css
.area {
  position: relative;
  width: 600px;
  height: 300px;
  background: #dceeff;
}

.label {
  position: absolute;
  inset: 10px 30px 30px 20px; /* 上・右・下・左 */
  width: auto;  /* 計算に任せることを明示。初期値もauto */
  height: auto;
  margin: 0;
  background: #ffd6a5;
}
```

この例では、左右について次の条件を同時に満たす必要がある。

```text
左の距離 + 子の幅 + 右の距離 = 基準の幅
    20px +    ?   +     30px = 600px

子の幅 = 600 - 20 - 30 = 550px
```

```text
外側の幅：600px
┌────────────────────────────────┐
│ 20px ┌─────────────────┐ 30px │
│      │ 子の幅：550px   │      │
│      └─────────────────┘      │
└────────────────────────────────┘
```

`width`を550pxと書いていなくても、左右の距離とautoの幅を合わせると550pxに決まる。これが「位置を指定したら横に広がった」の中身。

高さも、`300 - 上10 - 下30 = 260px`になる。オレンジのpの箱は550×260pxになるが、「お知らせ」という文字の大きさは変わらない。[幅の計算](https://www.w3.org/TR/CSS22/visudet.html#abs-non-replaced-width)と[高さの計算](https://www.w3.org/TR/CSS22/visudet.html#abs-non-replaced-height)に基づく例。

### 四方の隙間を0にすると、箱が全面まで広がる

上の`.label`の`inset`だけを`0`に変えると、上下左右の距離がすべて0になる。

```text
幅   = 600 - 左0 - 右0 = 600px
高さ = 300 - 上0 - 下0 = 300px
```

幅・高さの指定はautoのままでも、結果として外側と同じサイズになる。CSSが`width: 100%; height: 100%`へ書き換わったわけではない。

最初に小さい箱が描かれ、その後引き伸ばされるという二段階の処理を意味するわけでもない。ブラウザが配置に使うサイズを計算した結果を、「広がる」と表現している。

### autoでも広がらない場合を比べる

同じ例で、次の変更を1つずつ試す。各行は元のコードから変更する。

| 変更するところ | 結果と理由 |
| --- | --- |
| `right: auto`をinsetの後に追加 | 幅autoのままでも、右端が固定されなくなる。幅は内容と利用可能な空間をもとに決まり、必ず550pxを埋める条件ではなくなる |
| `bottom: auto`をinsetの後に追加 | 高さautoのままでも、下端が固定されなくなる。この例の高さは中の文字などから決まる |
| `width: auto`を`width: 200px`へ変更 | 横幅は200px。両端の距離と幅をすべて満たせないため、通常の左から右の書字方向では指定したright側の条件が調整される |
| `max-width: 400px`を追加 | 自動計算の幅にも上限がかかるので、550pxにはならない |

つまり、**autoだけで広がるのではなく、auto・両端の指定・要素の種類・サイズ制約を合わせて結果が決まる**。

<details>
<summary>padding・border・marginがある場合</summary>

先ほどの引き算は、それらが0の最小例。実際は、左右の距離に加えて、子のmargin・border・padding・内容の幅が基準の幅に収まるよう計算する。

そのため、箱の外側が領域を埋めても、内容部分の幅まで基準と同じとは限らない。`width: 100%`では`box-sizing`によってpaddingやborderがその幅の外へ加わる場合もあり、`inset: 0`と常に同じ結果にはならない。

## 「親いっぱい」の親はどれ？

基準になる領域の正式な名前が「包含ブロック」。この位置から上下左右の距離を計算する。

練習例では、直上のdivに`position: relative`を付けて基準にしている。常に直上のHTML要素が基準になるわけではない。祖先の`position`や`transform`などでも変わる。[基準領域の仕様](https://www.w3.org/TR/css-position-3/#def-cb)を参照。

この例のようなブロックの基準領域はpaddingを含む範囲になる。pに初期marginが残っていると、その分の隙間ができるので、練習では`margin: 0`にしている。

## 文字の箱は広がったのに、画像は同じ指定でも広がらない？

imgは画像データを表示する「置換要素」。幅・高さが`auto`の場合、画像の固有サイズや縦横比がサイズ計算に使われる。`inset: 0`だけでは、pと同じような全面のサイズになるとは限らない。[置換要素の絶対配置](https://www.w3.org/TR/CSS22/visudet.html#abs-replaced-width)を参照。

決めた枠を画像で埋めたいなら、**img自身の表示サイズも指定する**。外側に幅・高さと`position: relative`がある前提で、次をimgに書く。

```css
.demo__image {
  position: absolute;
  inset: 0;
  width: 100%;
  height: 100%;
  object-fit: cover;
}
```

`width`・`height`でimgの表示領域を決め、`object-fit`で画像の収め方を決める。`cover`では一部が切れる。切りたくないロゴや図まで一律にこの指定へ変えず、[画像の扱い方](../../02_基礎/01_HTML・CSS/11_メディア設計/00_メディア設計整理マップ.md)で目的を確認する。

## pの中のspanも広がる？

通常のインライン表示のspanは、pが大きくなっても文字の分だけの箱のまま。pに指定した`position`や`inset`が、spanへ自動で引き継がれることはない。

span自身にも`position: absolute; inset: 0`を指定すると、今度はspanを配置・サイズ計算する話になる。このときも幅・高さなどの条件を確認する。「親が広がればすべての子も同じ大きさ」というルールはない。

## DevToolsでの確認

まずElementsで、広げたい要素そのものを選ぶ。次にStylesで、`position`、`inset`、`width`、`height`、`margin`がどのルールから来たかを見る。

Computedのボックスモデルでは、実際の幅・高さ・余白を確認する。imgの場合は、画像の元サイズと画面上の表示サイズを混同しない。

質問するときは「どの要素を、どの領域いっぱいにしたいか」「その要素と基準側のCSS」「実際のサイズ」を一緒に示すと、原因を絞りやすい。
