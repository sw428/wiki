# ウィンドウの切り替えと並び順

ChromeやVS Codeを複数のウィンドウで使うときは、**アプリを選ぶ操作と、そのアプリの中のウィンドウを選ぶ操作を分けて考える。** 数字で呼び出しているつもりでも、その数字がタスクバー上のアプリ位置なのか、同じアプリ内のウィンドウの順番なのかで意味が変わる。

ウィンドウの順番を使って切り替える場合は、タブがどこから来たかより、元のウィンドウが残っているか、新しいウィンドウが作られたかを確認する。Chromeで報告された結果は、この見方で説明できる。

## まず、キーが何を選んでいるかを分ける

`Win`は、Windowsロゴの付いたキーを指す。次の表はWindows標準の操作である。

| 操作 | 選ぶ対象・起こること |
| --- | --- |
| `Win + 数字` | タスクバーの指定位置のアプリを起動する。起動中なら、そのアプリへ切り替える |
| Winを押したまま同じ数字を繰り返し押す | タスクバーの指定位置のアプリで、開いているウィンドウを巡回する |
| `Win + Ctrl + 数字` | タスクバーの指定位置のアプリで、最後にアクティブだったウィンドウへ切り替える |
| `Alt + Tab` | 開いているウィンドウを切り替える。Altを押したままTabを繰り返して選ぶ |

`Win + 数字`の数字は、同じアプリ内の各ウィンドウへ付けた固定番号ではない。タスクバー上のアプリ位置と、アプリ内のウィンドウの並び順を同じものとして扱わない。

標準動作の確認先は、[Microsoftのキーボードショートカット一覧](https://support.microsoft.com/ja-jp/accessibility/windows/keyboard-shortcuts-in-windows)。キーの割り当てを変更している場合は、その割り当て先も確認する。

同じアプリの複数ウィンドウを選ぶには、Winを押したまま同じ数字を繰り返し押し、目的のウィンドウを選んでからWinを離す。[Microsoft Pressのタスクバー操作の説明](https://www.microsoftpressstore.com/articles/article.aspx?p=3178893&seqNum=4)

このキー列をマウスのボタンから送る使い方は、[G600の割り当てとウィンドウ切り替え](../18_マウス/01_G600の割り当てとウィンドウ切り替え.md)に記録している。アプリを選ぶ数字と、ウィンドウを巡回するための押下回数を分けて考える。

## Chromeでは、タブの所属とウィンドウの存続を追う

Chromeでは、タブを既存の別ウィンドウへ移動したり、ウィンドウの外へドラッグして新しいウィンドウに分けたりできる。[Chrome公式ヘルプ](https://support.google.com/chrome/answer/2391819?hl=ja&co=GENIE.Platform%3DDesktop)

以下は、ユーザーから報告された操作結果を、ウィンドウとタブの関係が分かるよう模式化したもの。Codexが実機で再現した結果ではない。ウィンドウはP・Q・R・S、タブはx・y・zで区別する。図の左から右を、報告された並び順として読む。文字はウィンドウを追跡するための呼び名であり、Windows内部の識別番号ではない。

### タブを残して移動すると、元のウィンドウが残る

ウィンドウQにあるタブxだけをRへ移す。

```text
移動前：Q［x・y］ → R［z］
移動後：Q［y］   → R［x・z］
```

Qにはyが残るため、元のウィンドウQは存続し、今回の観察では並び順も変わらなかった。残るのがxかyかというタブの違いで、ウィンドウの順番を説明する必要はなかった。

### すべて移動して元のウィンドウが消えると、後続が前へ詰まる

今度はQのタブがxだけの状態で、xをRへ移す。

```text
移動前：Q［x］ → R［y］
移動後：R［x・y］
```

報告ではQが消え、RがQのあった順番へ繰り上がった。**Rは同じウィンドウとして残っていても、並び順としての番号は変わる。** そのため、「残ったウィンドウは必ず同じ番号を保持する」という表現は適切ではない。

ここからxとyのどちらを分離しても、報告された順番は次のようになった。

```text
R［残したタブ］ → 新しいウィンドウ［分離したタブ］
```

タブxが以前Qに入っていたことは、再分離後の順番には影響しなかった。今回の結果を説明するために、タブが元の順番を記憶していると考える必要はない。

### 後ろに別のウィンドウがある場合も、残ったもの同士の前後関係を追う

QのタブをすべてRへ移し、Qが消えた後、Rからタブを分離する。

```text
統合前：P → Q → R → S
統合後：P → R → S
分離後：P → R → S → 新しいウィンドウ
```

今回の報告では、残ったウィンドウ同士の前後関係が保たれ、消えたウィンドウの分だけ順番が詰まり、新しく分離したウィンドウが末尾に加わった。

この範囲では、タブの左右の並び、元の所属先、集まったタブの枚数、どのタブを分離したかを、ウィンドウの順番の決定条件として加える必要はなかった。ただし、この結果だけで、あらゆる環境で新しいウィンドウが必ず末尾になるとは断定できない。

## VS Codeでは、タブがなくなることとウィンドウが閉じることを分ける

VS Codeの通常のメインウィンドウは、既定では最後のファイルタブを閉じてもウィンドウ自体が残る。フォルダーを開いていないウィンドウについては、`window.closeWhenEmpty`で最後のエディターを閉じたときにウィンドウも閉じるかを設定でき、既定値は`false`である。[VS Code公式の設定定義](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/electron-browser/desktop.contribution.ts)

そのため、VS Codeでは「タブがなくなった」という結果だけで、Chromeの例と同じように元のウィンドウが消えたと判断しない。ウィンドウ自体が残っているかを確認する。

VS Codeで実際に呼び出し順が入れ替わる条件や、Chromeと同じ順番になるかは、この会話では未確認である。採用済みのキー割り当てを調べる場合は、[自分のVS Code環境のキーボードショートカット](../09_vscode/自分のvscode環境/03_キーボードショートカット.md)へ戻る。

## 順番が変わったときに確認すること

まず実際に押したキーと、切り替え先のウィンドウのタイトルを確かめる。タスクバーのプレビューの左右順を見た場合は、その順番とキーでの呼び出し順を分けて記録する。

タブを動かした場合は、移動元のウィンドウが残ったか、消えたか、新しいウィンドウが作られたかを確認する。タブ移動・ウィンドウを閉じる操作・新しいウィンドウを開く操作を一度に行わず、操作ごとに前後の順番を比べると、どこで変わったかを追いやすい。

## 複数タブをまとめて移して呼び出し先の用途をそろえる

Chromeを起動し直した後などに、ショートカットで開くウィンドウと、そこに置きたい作業用のタブが合わなくなった場合は、**用途ごとのタブをまとめて移し、呼び出し先と中身の対応を整理し直す。** ユーザーは、この方法なら短時間で整理できることを採用理由としている。所要時間を計測した結果ではない。

移動元と移動先は同じChromeプロフィールのウィンドウを使う。元のウィンドウを残して順番の変化を避けたい場合は、移動するタブとは別に新しいタブを残しておく。すべて移して元のウィンドウが消えると、後続の呼び出し先も変わり得る。

1. いつもの切り替え操作で実際に開くウィンドウを確認し、そこへ置く作業内容を決める。
2. 移動元でCtrlを押しながら、移したいタブの見出しをクリックして複数選択する。選択されたタブの表示を確かめる。
3. Ctrlを離し、選択中のタブのいずれかを右クリックして「タブを別のウィンドウに移動」から移動先を選ぶ。選択したタブをまとめて移動先のタブバーへドラッグする方法も使える。
4. 移動後に切り替え操作を再度実行し、想定したウィンドウとタブが開くかを確かめる。
5. 中身を入れ替える必要がある場合は、移動先に元からあるタブも同様に移し、各呼び出し先と用途の対応をそろえる。

Ctrlとクリックによる複数選択・一括移動は、[Chrome公式ヘルプの複数タブの操作](https://support.google.com/chrome/answer/2391819?hl=en&co=GENIE.Platform%3DDesktop)でも説明されている。ここでクリックするのはタブの見出しである。ページ内のリンクをCtrlでクリックすると、リンク先を新しいタブで開く操作になる。

この手順では、ショートカットが開く各ウィンドウに、用途に合うタブを配置する。タスクバー上のアプリ位置が変わっている場合は、先にアプリのアイコン位置を元のキーに合う位置へ戻す。ウィンドウが不足している場合は新しく用意し、その後で実際の呼び出し先を確認する。

この整理方法と組み合わせて、普段の切り替えを少ない操作で行うための判断を、[G600の割り当ての理由](../18_マウス/01_G600の割り当てとウィンドウ切り替え.md#この割り当てにした理由)にまとめている。

## このページのまとめ

- `Win + 数字`が参照するのは、タスクバー上のアプリ位置。同じアプリ内のウィンドウの固定番号ではない。
- Chromeの報告では、タブの元の所属より、ウィンドウが存続・消滅・新規作成されたかで並び順の変化を説明できた。
- ウィンドウ自体が残っていても、先行するウィンドウが消えると、並び順の番号は変わり得る。
- 呼び出し先と用途がずれた場合は、CtrlとクリックでChromeのタブを複数選択し、まとめて移して対応を整理し直す。元のウィンドウを残すかどうかも意識する。
- VS Codeで同じ並び順になるかは未確認。Chromeの観察結果を、すべてのアプリの保証された規則へ広げない。
