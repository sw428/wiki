# 02_読み込み後や幅変更で起きる位置ずれ

画像の読み込み後や画面幅の変更後に表示位置が動くときは、移動した結果だけでなく、その前にどの要素の高さが変わったかを調べる。

表示を作る工程の入口は[ブラウザの基本フロー](./01_ブラウザが表示を作る基本フロー.md#基本フロー)、画像の寸法を予約する実装は[画像の読み込み前に表示領域を予約する](../11_メディア設計/02_画像の読み込み前に表示領域を予約する.md)で扱う。

## 位置ずれにつながる用語

- Reflow：Layoutの再計算を指す通称。
- Layout Shift：すでに表示された要素の位置が、利用者の操作によらず移動する現象。
- CLS：Layout Shiftの累積を表す指標。
- Scroll Anchoring：要素の移動時に、閲覧位置を保とうとするブラウザの補正。

これらを一つの現象名として扱わない。要素の寸法が変わったこと、画面上の位置が動いたこと、スクロール位置が補正されたことを分ける。

## 画像が後から読み込まれる場合

画像の表示領域を先に確保していないと、次の順で位置が動くことがある。

1. 画像の高さが未確定のまま初期LayoutとPaintが行われる。
2. JavaScriptなどでスクロール位置が決まる。
3. 画像の読み込みが完了する。
4. 画像の寸法に合わせてLayoutが更新される。
5. 後続要素とスクロール位置が動いて見える。

この場合、JavaScriptの実行が単に遅いとは限らない。JavaScriptの後で画像の高さが確定したことが原因になり得る。

`img`の `width`・`height` 属性やCSSの `aspect-ratio` で比率を先に決めると、読み込み後の高さ変化を減らせる。どちらを使うかは画像の実装条件と一緒に判断する。

## 横幅の変更が縦方向へ影響する

`max-width`や左右の `padding`を変えると、文字が折り返す位置も変わる。行数が増減すれば要素の高さが変わり、その下のsectionやスクロール位置も動く。

```text
横幅が変わる
→ 文字の折り返しが変わる
→ 行数と要素の高さが変わる
→ 後続要素の位置が変わる
```

横方向の指定を変えた場合も、縦方向の結果まで確認する。[インラインと行の仕組み](../08_インラインと行の仕組み/01_文字の行間と高さを確認する.md)では、行数と高さの関係を詳しく扱う。

## スクロール時の見え方を分ける

スクロールは、描画済みの内容を合成して表示を更新できる場合がある。常にPaintをすべてやり直すわけではない。一方、新しく見える領域や高さの変化があれば、追加の描画やLayoutが必要になる場合がある。

Scroll Anchoringが働くと、ブラウザは表示中の内容を保とうとしてスクロール位置を補正する。補正が問題を起こしていることを確認した場合だけ、対象を限定して `overflow-anchor: none` を検討する。

```css
.portfolio__list {
  overflow-anchor: none;
}
```

## 原因別に対策を選ぶ

1. 画像や動画の領域を `width`・`height`、`aspect-ratio`で予約する。
2. 文字の折り返しや、後から高さが変わる要素を確認する。
3. 固定ヘッダーでページ内リンクの到達位置が隠れるなら、対象に `scroll-margin-top`を指定する。
4. Scroll Anchoringが原因と確認できた箇所だけ、`overflow-anchor`を調整する。
5. CSS側の高さ変化を抑えた後で、必要ならJavaScriptによる補正を検討する。

`content-visibility: auto`は画面外の描画負荷を抑える選択肢だが、位置ずれ全般を直す指定ではない。使う場合は `contain-intrinsic-size`による予約とブラウザ上の結果を確認し、対象を限定する。

## 確認の順番

1. 位置が動いた時刻と、その直前に読み込まれた画像・フォント・JavaScriptを確認する。
2. DevToolsで、動いた要素より前にある要素の高さを確認する。
3. 画面幅を変え、文字の折り返しと高さを比較する。
4. 寸法予約やCSSの変更を一つずつ試す。
5. 改善した変更だけを実装へ戻す。
