# 01_ブラウザが表示を作る基本フロー

背景付きの箱が横へ広がる、文字が折り返されて高さが増える、画像の読み込み後に位置が動く。こうした表示を調べるには、HTML・CSS・画面の間で何が起きるかを大まかに分ける。

このページでは、ブラウザがHTMLとCSSから表示を作る流れをたどる。工程名を暗記することより、「どの要素の、どの値や表示が変わったか」を対応させることを優先する。

## 基本フロー

HTMLとCSSは別々の入力として解析され、表示に必要な情報が組み合わされる。

```text
HTML ─→ DOM ───────────────┐
                            ├→ スタイル計算 → box tree → Layout
CSS  ─→ CSSルール・CSSOM ──┘                          ↓
                                                  Paint
                                                    ↓
                                                  Raster
                                                    ↓
                                                 Composite
                                                    ↓
                                                   画面
```

これは対象と処理の関係を追う概略図であり、通信・解析・画面更新の厳密な時刻表ではない。更新時は必要な工程から行われ、毎回すべてを最初から実行するわけではない。

### HTMLの構造とCSSの指定を合わせる

- DOMは、HTMLから作られた要素や文字の構造を、JavaScriptなどから参照・操作できる形にしたもの。
- [CSSOM](../../../05_参照/CSSOM.md)は、スタイルシートやCSSルールを参照・操作する仕組み。
- スタイル計算では、対象要素へどの宣言を使うかを決め、各プロパティの値を求める。

DOMがCSSOMへ変化するわけではない。HTML側の構造とCSS側の情報を区別し、表示を作る段階で組み合わせる。

### 計算値から箱の寸法が決まるまで

要素の `display` などに従って、配置に使う箱の構造であるbox treeが作られる。Layoutでは、その箱、文字、親や周囲の条件から寸法と位置を求める。

例えば `width: auto` は計算値の段階では `auto` でも、配置に使う幅はLayoutで決まる。このように残りの計算を解決した値を使用値（used value）と呼ぶ。

箱の種類を全部覚える必要はない。「どの要素の箱か」「幅や高さはどこから来たか」を確認できればよい。箱とボックスモデルの関係は[05](../05_ボックスとdisplay/06_要素とCSSの箱の関係.md)へ戻る。

### imgの幅はCSSOMだけで決まるのか

`img` を見ると、「画像だから `width` の扱いが違う」という結果が先に見える。では、その違いはCSSOMを作った時点ですでに判断されているのだろうか。

**CSSOMのスタイルシート・ルールを構築する段階で、`img` の最終表示幅が決まるわけではない。** HTMLから得た要素の情報と、要素に適用されたCSSの情報が、表示のための処理で組み合わされる。

例えば次のHTMLとCSSを考える。

```html
<img class="photo" src="sample.png" alt="">
```

```css
.photo {
  width: auto;
  max-width: 100%;
  height: auto;
}
```

| 情報・処理 | 何を扱っているか |
| --- | --- |
| DOM | `img` という要素と、`class`、`src` などの属性 |
| CSSルール・CSSOM | `.photo` に `width: auto` や `max-width: 100%` などの宣言があること |
| スタイル計算 | `img` に一致するルールを探し、カスケード・継承などを踏まえて各プロパティの値を求める |
| box tree・Layout | 要素が置換要素として扱われること、画像の固有寸法・比率、利用可能な幅、適用されたCSSの制約から、配置に使う寸法を求める |

```text
HTML → DOM：これは img 要素で、画像を参照している
CSS → CSSルール・CSSOM：.photo には幅に関する指定がある
                       ↓
スタイル計算：その img に適用されるCSSを解決する
                       ↓
box tree・Layout：要素の性質とCSSの制約を合わせる
                       ↓
実際に配置する幅・高さが決まる
```

例えば元画像が840 × 560pxで、親の利用可能な幅が420pxなら、上の指定では、ほかに寸法を変える条件がない場合、画像は420 × 280pxで配置される。元画像の比率を保ちながら、`max-width: 100%` で幅が制限されるためである。

重要なのは、CSSOMのルールに書かれた `width: auto` が、CSSOMを構築した瞬間に `420px` に書き換わるわけではないこと。**CSSで指定された値・計算値と、Layoutで配置に使う値は区別する。**

また、同じ `display: block; width: auto;` でも、通常フローの非置換ブロックと、画像を表す置換要素では幅の決め方が異なる。`display` だけでなく、どのような要素・内容を扱っているかも寸法計算に関係する。

ただし、CSSOMという言葉はスタイルシートのルールだけに限らない。`getComputedStyle()` のようなAPIも含まれ、APIで取得する `width` が使用値に相当するピクセル値になる場合がある。「CSSOM内のCSSルール」と「CSSOM APIで取得できる値」を同じものとして扱わない。

**整理すると、DOMは「何の要素か」、CSSルールは「何を指定したか」を伝え、スタイル計算とLayoutがそれらを組み合わせて表示を成立させる。**

置換要素の定義や `img` が画像を表示できない場合の例外は、[置換要素（img・input・video）](../../../05_参照/置換要素（img・input・video）.md) で確認する。

### 箱の配置から画面に見えるまで

- Paint：背景、枠線、文字などの描画指示と順序を作る。
- Raster：描画する内容をピクセルへ変換する。
- Composite：描画された部分を組み合わせて画面へ出す。

Paintを「その場ですべてのピクセルが画面に出る工程」とは考えない。内部のスレッドやレイヤー分割は、性能を調べる必要が出たときに公式資料で読み足す。

## 一つの要素で確かめる

[05のblockとinlineの比較](../05_ボックスとdisplay/05_blockとinlineの広がり方.md#背景の広がり方を比べる)から一つの要素を選び、次を確認する。

1. HTMLで対象の要素を見つける。
2. Stylesでその要素へ適用されるCSSを確認する。宣言の採用・不採用は[06の確認方法](../06_CSSカスケードとDevToolsの見方/01_DevToolsで適用されたCSSを確認する.md#最初の確認方法)を使う。
3. `padding`だけを一時的に変え、画面上の箱とボックスモデル図の変化を比べる。
4. 文字が折り返されたら、幅と行数と高さの変化を見る。[08の行数と高さ](../08_インラインと行の仕組み/01_文字の行間と高さを確認する.md#行数から結果として生じる高さ)へ進める。

これは各工程の実行時間を測定する手順ではなく、指定と表示を対応させるための確認である。
