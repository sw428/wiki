# 03_セレクタの詳細度を比べる

同じ要素の同じプロパティへ複数の宣言が当たり、セレクタの優先度を比べる必要がある場合は、詳細度を確認する。

DevToolsで宣言と最終値を探す操作は、[適用されたCSSを確認する](./01_DevToolsで適用されたCSSを確認する.md#最初の確認方法)へ戻る。ほかの優先条件が同じ場合の記述順は、[優先条件が同じときの記述順](./02_優先条件が同じときの記述順.md)で扱う。

## セレクタが違う場合は詳細度を見る

```css
.notice { color: tomato; }
div { color: royalblue; }
```

`div.notice` には両方が一致する。この条件では `.notice` の詳細度が高いため、後ろにある `div` では上書きされず、文字色は `tomato` になる。

詳細度は、セレクタの種類を次の桁に分け、左から比較する。

| セレクタ | 詳細度 | 入口用の覚え方 |
| --- | ---: | ---: |
| `#id` | `1-0-0` | 100 |
| `.class`、`[属性]`、`:hover`など | `0-1-0` | 10 |
| `div`、`p`、`::before`など | `0-0-1` | 1 |
| `*` | `0-0-0` | 0 |

`100 / 10 / 1 / 0` は入口用の覚え方であり、本当に点数を足す仕組みではない。実際は `ID - class類 - 要素類` の桁を左から比較する。classを多数並べてもIDの桁へ繰り上がらない。inline styleや `!important` も、この表へ点数として足さない。

### 点数風の計算と合わない疑似クラス

- `:where()` 自体と引数の詳細度は常に `0-0-0`。
- `:is()`、`:not()`、`:has()` は、疑似クラス1個分を足すのではなく、引数のうち最も高い詳細度を使う。

最初から暗記せず、単純な比較と結果が合わないときの確認先にする。

## 詳細度だけで説明できない場合

詳細度を確認しても結果を説明できない場合は、出所、`!important`、`@layer`などが関係している可能性がある。[カスケード全体の優先順位](./04_カスケード全体の優先順位.md)へ進む。
