# 02_優先条件が同じときの記述順

同じ要素の同じプロパティへ複数の宣言が当たっているとき、カスケード上のほかの優先条件が同じなら、ソース上の記述順を確認する。

DevToolsで宣言と最終値を探す操作は、[適用されたCSSを確認する](./01_DevToolsで適用されたCSSを確認する.md#最初の確認方法)へ戻る。

## 優先条件が同じなら後にある宣言が勝つ

カスケード上のほかの条件が同じなら、ソース上で後に現れる宣言が勝つ。

```css
p {
  color: red;
}

p {
  color: blue;
}
```

この場合は、後にある `color: blue` が使われる。

[一つの箱を作る例](../05_ボックスとdisplay/02_一つの箱を作る.md#htmlとcssを用意する)で試すなら、`style.css` の末尾に `.notice { color: tomato; }` を追記する。元の `.notice` と同じ条件で競合するため、後の文字色が使われる。Stylesの打ち消し線とComputedを確認したら、追記を取り除く。

## 複数のCSSファイルもHTML上の順番で並ぶ

別々に読み込んだスタイルシートは、HTMLにリンクした順番に並べたものとして扱われる。

```html
<link rel="stylesheet" href="reset.css" />
<link rel="stylesheet" href="style.css" />
```

ほかのカスケード条件が同じなら、後に位置する `style.css` の宣言が勝つ。ダウンロードが完了した速さで順番は変わらない。

reset CSSで土台を整え、その後にサイト固有のCSSを適用したい場合は、`reset.css`、`style.css` の順に書く。

## 記述順だけで説明できない場合

セレクタの詳細度を比較する必要がある場合は、[セレクタの詳細度を比べる](./03_セレクタの詳細度を比べる.md)へ進む。それでも結果を説明できない場合は、出所、`!important`、`@layer`などが関係している可能性がある。[カスケード全体の優先順位](./04_カスケード全体の優先順位.md)へ進む。
