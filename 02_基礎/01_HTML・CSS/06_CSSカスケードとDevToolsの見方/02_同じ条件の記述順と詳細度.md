# 02_同じ条件の記述順と詳細度

同じ要素の同じプロパティへ複数の宣言が当たっているときは、まずセレクタと条件が同じかを見る。同じなら記述順、違うなら詳細度を確認する。

DevToolsで宣言と最終値を探す操作は、[適用されたCSSを確認する](./01_DevToolsで適用されたCSSを確認する.md#最初の確認方法)へ戻る。

## 同じ条件なら後にある宣言が勝つ

カスケード上のほかの条件が同じなら、ソース上で後に現れる宣言が勝つ。

```css
p {
  color: red;
}

p {
  color: blue;
}
```

この場合は、後にある `color: blue` が使われる。

[一つの箱を作る例](../05_ボックスとdisplay/02_一つの箱を作る.md#htmlとcssを用意する)で試すなら、`style.css` の末尾に `.notice { color: tomato; }` を追記する。元の `.notice` と同じ条件で競合するため、後の文字色が使われる。Stylesの打ち消し線とComputedを確認したら、追記を取り除く。

## 複数のCSSファイルもHTML上の順番で並ぶ

別々に読み込んだスタイルシートは、HTMLにリンクした順番に並べたものとして扱われる。

```html
<link rel="stylesheet" href="reset.css" />
<link rel="stylesheet" href="style.css" />
```

ほかのカスケード条件が同じなら、後に位置する `style.css` の宣言が勝つ。ダウンロードが完了した速さで順番は変わらない。

reset CSSで土台を整え、その後にサイト固有のCSSを適用したい場合は、`reset.css`、`style.css` の順に書く。

## セレクタが違う場合は詳細度を見る

```css
.notice { color: tomato; }
div { color: royalblue; }
```

`div.notice` には両方が一致する。この条件では `.notice` の詳細度が高いため、後ろにある `div` では上書きされず、文字色は `tomato` になる。

詳細度は、セレクタの種類を次の桁に分け、左から比較する。

| セレクタ | 詳細度 | 入口用の覚え方 |
| --- | ---: | ---: |
| `#id` | `1-0-0` | 100 |
| `.class`、`[属性]`、`:hover`など | `0-1-0` | 10 |
| `div`、`p`、`::before`など | `0-0-1` | 1 |
| `*` | `0-0-0` | 0 |

`100 / 10 / 1 / 0` は入口用の覚え方であり、本当に点数を足す仕組みではない。実際は `ID - class類 - 要素類` の桁を左から比較する。classを多数並べてもIDの桁へ繰り上がらない。inline styleや `!important` も、この表へ点数として足さない。

### 点数風の計算と合わない疑似クラス

- `:where()` 自体と引数の詳細度は常に `0-0-0`。
- `:is()`、`:not()`、`:has()` は、疑似クラス1個分を足すのではなく、引数のうち最も高い詳細度を使う。

最初から暗記せず、単純な比較と結果が合わないときの確認先にする。

## この二つで説明できない場合

同じ条件なら記述順、セレクタが違うなら詳細度を確認する。それでも結果を説明できない場合は、出所、`!important`、`@layer`などが関係している可能性がある。[カスケード全体の優先順位](./03_カスケード全体の優先順位.md)へ進む。
