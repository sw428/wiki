# 03_表示条件とレイアウトを分ける

「SPで表示する」は存在条件であり、「右端へ置く」「横並びにする」は配置条件である。同じ要素へ両方を指定しても、判断とクラスの担当は分ける。

## 存在と位置を別々に書く

```html
<div class="site-header__menu u-sp-only">
  <button class="hamburger-button" type="button">メニュー</button>
</div>
```

```css
.site-header__menu {
  display: flex;
  align-items: center;
  justify-content: flex-end;
}
```

- `u-sp-only`: PC条件で非表示にする
- `site-header__menu`: 表示中の並びと位置を決める
- `hamburger-button`: ボタン自身の見た目と操作対象を持つ

表示制御Utilityへ`justify-content`やmarginを加えない。別の場所で同じUtilityを使ったとき、意図しない配置まで再利用されるためである。

## SP専用だからpositionが必要とは限らない

SP用ヘッダー行やメニューボタンでも、前後の要素の順番どおりに置くなら通常フローを先に検討する。

- 画像や別要素へ重ねる: `position`が候補
- 同じ行の端へ寄せる: FlexやGridが候補
- 上下のHTML順に置く: 通常フローが候補

`position: absolute`は通常フローから外れるため、周囲がその要素の高さを前提にできない。SP専用という名前だけを理由に絶対配置へしない。親子配置は[レイアウト整理マップ](../09_レイアウト/00_レイアウト整理マップ.md)で確認する。

## 表示条件と開閉状態も分ける

レスポンシブ表示と、クリックによるメニュー開閉は別の状態である。

| 状態 | 主な担当 |
| --- | --- |
| SP幅でメニューボタンを存在させる | media queryと表示制御Utility |
| ボタンを押す前はメニュー本文を閉じる | HTMLの初期状態とCSS・JS |
| 押した後に本文を開く | JSのclass・属性更新 |
| 開閉状態を支援技術へ伝える | `aria-expanded`など |

画面幅だけで切り替えるクラスへ、クリック後の開閉状態まで持たせない。開閉UIは[JSのUI実装パターン](../../02_JS/03_UI実装パターン.md#4役で見る最小記憶)で扱う。

## display noneで起きること

`display: none`になった要素と子孫はboxを生成しない。そのため、非表示中の要素へFlexや位置指定が残っていても、画面上の配置は作られない。

表示されたときに初めて、現在有効な`display`、Flex・Grid、寸法、位置指定から配置が計算される。「表示されたが位置が違う」場合は、非表示指定を外すだけでなく、表示時のレイアウト宣言を確認する。

## 4つを分けて確認する

1. 存在: SP/PCのどちらで表示するか。
2. boxの種類: 表示時の`display`は何か。
3. 配置: 通常フロー・Flex・Grid・positionのどれで置くか。
4. 操作状態: JSで開閉・選択状態を変えるか。

DevToolsでは、まず対象が`display: none`かを確認する。表示されているなら、次に親のレイアウトと対象の位置指定を見る。存在と配置を同時に直そうとせず、どこまで正常かを一段ずつ確認する。
