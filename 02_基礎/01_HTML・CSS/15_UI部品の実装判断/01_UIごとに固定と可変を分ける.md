# 01_UIごとに固定と可変を分ける

デザインをHTML/CSSへ落とすときは、最初に「何のUIか」を決める。見た目に近いプロパティを足す前に、崩れてほしくない条件と、内容に合わせて変わってよい部分を分ける。

## 最初に分けること

1. 何のUIか
   バナー、カード、CTA、ヒーロー、ラベル、一覧など。
2. 何を固定したいか
   比率、実寸上限、間隔、クリック範囲、切り抜き、文字位置など。
3. 何を可変にしたいか
   文字量、画像差し替え、画面幅、カード数、SP/PCの並びなど。
4. どこが責務を持つか
   親、枠、画像、テキスト、リンク、疑似要素のどこで制御するか。

「固定する」は、すべてをpxで固めるという意味ではない。崩れてほしくない条件を、担当するHTML要素とCSSへ明示するという意味で扱う。

## 固定する対象から逆引きする

| 固定したいもの | 主なCSS | 使う場面 |
| --- | --- | --- |
| 比率 | `aspect-ratio` | バナー、カード画像、動画枠 |
| 実寸上限 | `width` / `max-width` | ロゴ、画像ボタン、本文幅 |
| 最小操作範囲 | `min-height` / `padding` | ボタン、CTA、メニュー |
| 要素間隔 | `gap` / `margin` / `padding` | 一覧、カード内、セクション間 |
| 切り抜き | `object-fit` / `object-position` | 写真、MV、カード画像 |
| 重ねる基準 | `position: relative` / `absolute` | 画像上テキスト、バッジ、ピン |
| はみ出し制御 | `overflow: hidden` | 角丸画像、比率枠 |
| 下寄せ | `display: flex` / `margin-top: auto` | カードのボタン、日付、メタ情報 |

同じプロパティを複数の部品で使っても、固定する対象は同じとは限らない。たとえば`aspect-ratio`は、画像を小さくする指定ではなく、比率を持つ箱を作る指定である。

## 実装後の判断フロー

1. UIの名前と用途を言えるか確認する。
2. 固定する対象が、親・枠・画像・文字・リンクのどれか確認する。
3. 文字量、画像、項目数、画面幅を1条件ずつ変える。
4. 固定と可変がぶつかったら、文字が読めること、意味画像が切れないこと、操作できることを先に確認する。
5. 仕組みが分からなければ、対応する09〜14章へ戻る。

## 一言でいうと

作りたいUIを先に決め、崩れてほしくない条件を担当する箱へ置く。プロパティ名はその後に選ぶ。
