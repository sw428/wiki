# 03_主要なナビゲーションをnavで囲む

## このページの役割

`nav`は、ページ内にあるリンクを何でも囲むための要素ではない。

このページでは、

- どのリンク集を`nav`で囲むか
- 普通のリンク集とは何が違うか
- `ul`や`a`とはどう役割を分けるか

を整理する。

## この範囲の芯

`nav`は、ページ内やサイト内を移動するための**主要なナビゲーション**を表す。

```html
<nav>
  <ul>
    <li><a href="/">ホーム</a></li>
    <li><a href="/service/">サービス</a></li>
    <li><a href="/contact/">お問い合わせ</a></li>
  </ul>
</nav>
```

ここで役割を分けると、

```text
nav
→ この範囲がナビゲーションであることを表す

ul
→ リンク項目の一覧を表す

li
→ 一覧の1項目を表す

a
→ 実際の移動先を作る
```

`nav`だけでリンクが作られるわけではない。

## すべてのリンクをnavで囲むわけではない

ページにはさまざまなリンクがある。

```html
<p>
  詳しくは<a href="/guide/">利用ガイド</a>を確認してください。
</p>
```

この`a`は文章の中にある通常のリンクであり、それだけで`nav`にする必要はない。

```html
<nav>
  <ul>
    <li><a href="/">ホーム</a></li>
    <li><a href="/about/">会社情報</a></li>
    <li><a href="/service/">サービス</a></li>
  </ul>
</nav>
```

こちらは、利用者がサイト内の主要な場所へ移動するためのまとまりなので、`nav`として扱いやすい。

判断するときは、

> リンクがあるか

ではなく、

> このまとまり自体がナビゲーションとしての役割を持つか

を見る。

## navを使いやすい場所

代表的には次のようなものがある。

- グローバルナビゲーション
- ページ内の主要な目次
- [パンくずリスト](./13_パンくずをHTMLで組む.md)
- 前後の記事へ移動するナビゲーション

ただし、形だけで決めるのではなく、そのリンク群が何のために存在しているかを見る。

## 普通のリンク集との違い

複数のリンクが並んでいても、必ず`nav`になるわけではない。

```html
<ul>
  <li><a href="/company-a/">株式会社A</a></li>
  <li><a href="/company-b/">株式会社B</a></li>
  <li><a href="/company-c/">株式会社C</a></li>
</ul>
```

これが単なる関連企業の一覧なら、`ul`だけで意味を表せることがある。

一方、

```html
<nav>
  <ul>
    <li><a href="#overview">概要</a></li>
    <li><a href="#price">料金</a></li>
    <li><a href="#faq">よくある質問</a></li>
  </ul>
</nav>
```

のように、ページ内の主要な場所へ移動するためのまとまりなら`nav`を使える。

つまり、

```text
リンクの一覧
≠ 必ずnav

主要な移動手段としてのリンク群
→ navを検討する
```

と考える。

## navとulは役割が違う

`nav`と`ul`は置き換えるものではない。

```html
<nav>
  <ul>
    <li><a href="/">ホーム</a></li>
    <li><a href="/news/">お知らせ</a></li>
  </ul>
</nav>
```

それぞれ、

```text
nav
→ ナビゲーションという範囲の意味

ul
→ 順序を持たない項目の一覧

a
→ 移動
```

を担当している。

一つのHTMLの中で、それぞれ別の役割を重ねて表している。

## navはページ内に複数あってよい

`nav`は1ページに1つだけという要素ではない。

たとえば、

```text
ヘッダー
→ サイト全体のナビゲーション

本文
→ ページ内目次

フッター
→ 補助的なサイトナビゲーション
```

のように、複数のナビゲーションが存在することがある。

```html
<nav aria-label="サイト内">
  ...
</nav>

<nav aria-label="ページ内目次">
  ...
</nav>
```

複数の`nav`がある場合は、それぞれが何のナビゲーションなのか区別できる名前を付ける。

## headerの中にnavが入ることもある

よくある構造は次のようになる。

```html
<header>
  <a href="/">サイト名</a>

  <nav>
    <ul>
      <li><a href="/about/">会社情報</a></li>
      <li><a href="/service/">サービス</a></li>
    </ul>
  </nav>
</header>
```

ここでも、

```text
header
→ その範囲の導入やナビゲーションをまとめる

nav
→ その中のナビゲーション部分を表す
```

と役割を分ける。

`header`があるから`nav`が不要になるわけではない。

## 判断するときの見方

`nav`を使うか迷ったときは、

```text
リンクが複数あるか
```

だけでは判断しない。

次を見る。

```text
このリンク群は、
利用者がページやサイトの主要な場所へ
移動するためのまとまりか
```

そうであれば`nav`を検討する。

単なる文章中のリンクや、内容として並べているだけのリンク一覧なら、`nav`を使わないこともある。

## このページのまとめ

- `nav`は、ページやサイトの主要な場所へ移動するためのまとまりを表す
- 文章中のリンクや、複数のリンクがあるだけの一覧をすべて`nav`にするわけではない
- `nav`はナビゲーションの範囲、`ul`は一覧、`a`は移動先を担当する
- `nav`はページ内に複数置けるため、複数ある場合は区別できる名前を付ける
- `header`があっても、その中のナビゲーションを示す`nav`の役割はなくならない
- リンクの数や見た目ではなく、リンク群全体の役割から判断する
