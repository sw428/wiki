# 05_独立した内容をarticleで囲む

## このページの役割

`article`は、見た目がカードになっている要素を囲むためのものではない。

このページでは、

- どんな内容を`article`にするか
- `section`とは何が違うか
- 一覧の1件を`article`にするかどう判断するか

を整理する。

## この範囲の芯

`article`は、**その部分だけを切り出しても一つの内容として成立するまとまり**を表す。

たとえば記事一覧の1件なら、

```html
<article>
  <h2>新サービスを公開しました</h2>
  <p>新しいサービスについてお知らせします。</p>
</article>
```

この部分だけを取り出しても、

「一つのお知らせ」

として内容が成立する。

判断するときは、

> この範囲だけを別の場所へ移しても、一つの内容として読めるか

を見る。

## articleを使いやすい内容

代表的には次のようなものがある。

```text
ブログ記事
ニュース記事
お知らせ1件
投稿1件
コメント1件
商品レビュー
フォーラムの投稿
```

共通しているのは、

```text
ページ全体の一部分ではある
↓
その部分だけでも一つの内容として成立する
```

という点。

## sectionとの違い

`section`と`article`は、どちらも意味のあるまとまりを表す。

ただし判断軸が違う。

```text
section
→ 文書の中の一つの章・テーマ

article
→ 単独で切り出しても成立する内容
```

たとえば、

```html
<section>
  <h2>お知らせ</h2>

  <article>
    <h3>新サービスを公開しました</h3>
    <p>...</p>
  </article>

  <article>
    <h3>営業時間を変更しました</h3>
    <p>...</p>
  </article>
</section>
```

ここでは、

```text
section
→ 「お知らせ」という章

article
→ お知らせ1件
```

という役割になる。

## カードや一覧では、項目と独立性を分ける

見た目がカードでも、サービスの特徴を並べているだけなら、それぞれが独立した内容とは限らない。

```html
<ul>
  <li>
    <h3>高品質</h3>
    <p>...</p>
  </li>
  <li>
    <h3>低価格</h3>
    <p>...</p>
  </li>
</ul>
```

この場合は、一覧の1項目を表す`li`だけで足りる。

一方、各項目が一つの記事として成立するなら、`li`の中へ`article`を置ける。

```html
<ul>
  <li>
    <article>
      <h2>HTMLの基礎</h2>
      <p>HTMLの基本を解説します。</p>
      <a href="/html/">続きを読む</a>
    </article>
  </li>

  <li>
    <article>
      <h2>CSSの基礎</h2>
      <p>CSSの基本を解説します。</p>
      <a href="/css/">続きを読む</a>
    </article>
  </li>
</ul>
```

```text
ul
→ 一覧

li
→ 一覧の1項目

article
→ その項目の中にある独立した内容
```

カードの見た目や一覧の1件であることだけでは、`article`を使う理由にならない。また、`article`を使うから`li`が不要になるわけでもない。

カード一覧の1件へ`li`・`article`・`div`・`a`を組み合わせる判断は、[カード1件のHTMLを決める](./12_カード1件のHTMLを決める.md)で扱う。

## articleには見出しを持たせる

`article`は一つの内容として成立する範囲なので、何についての内容なのか分かる見出しを持つ構造が基本になる。

```html
<article>
  <h2>夏季休業のお知らせ</h2>
  <p>8月10日から8月15日まで休業します。</p>
</article>
```

このように、

```text
article
↓
その内容を表す見出し
↓
本文
```

として読む。

記事内に見出しがあることと、`article`自体へ`aria-labelledby`で名前を付けることは別の判断。通常の`article`へ一律に追加せず、支援技術へ伝わる名前やランドマークの条件は[意味構造とアクセシビリティツリー](../../../03_詳細/01_HTML・CSS/02_意味構造とアクセシビリティツリー.md#章の区切りとランドマークは同じではない)で確認する。

## articleの中にsectionを入れることもある

一つの記事の中に複数の章があるなら、`article`の中を`section`で分けられる。

```html
<article>
  <h1>HTMLの基本</h1>

  <section>
    <h2>HTMLとは</h2>
    ...
  </section>

  <section>
    <h2>要素とは</h2>
    ...
  </section>
</article>
```

構造としては、

```text
article
→ 一つの記事全体

section
→ その記事の中の各章
```

となる。

前半の「お知らせ」の例のように、`section`の中へ複数の`article`を置くこともできる。`section`と`article`は上下関係が固定されているわけではなく、内容の役割で決める。

記事の導入や補足をまとめる場合は、`article`の中に`header`や`footer`も置ける。担当範囲の決め方は[headerの担当範囲](./07_headerの担当範囲を決める.md)と[footerの担当範囲](./08_footerの担当範囲を決める.md)で扱う。

## 判断するときの見方

`article`を使うか迷ったら、

```text
この部分だけを切り出しても、
一つの内容として成立するか
```

を見る。

さらに、

```text
別ページに掲載しても成立するか
RSSや記事一覧の1件として扱えそうか
一つの投稿・記事・レビューとして名前を付けられるか
```

を考えると判断しやすい。

単にレイアウトのために囲いたいだけなら、`article`ではない。

章として分けたいなら、`section`を検討する。

一覧の1項目であることだけを表したいなら、`li`だけで足りることもある。

## このページのまとめ

- `article`は単独で切り出しても成立する内容を表す
- 見た目がカードだから`article`になるわけではない
- 一覧の1件だから必ず`article`になるわけでもない
- `section`は章やテーマ、`article`は独立した内容を表す
- `li`は一覧の1項目を表し、`article`とは役割が違う
- `article`には内容を表す見出しを持たせる
- `article`の中に`section`を置くことも、その逆もある
- 判断するときは「この部分だけで一つの内容として成立するか」を見る
