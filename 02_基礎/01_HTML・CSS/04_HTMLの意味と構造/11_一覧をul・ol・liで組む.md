# 11_一覧をul・ol・liで組む

## このページの役割

`ul`・`ol`・`li`は、縦並びや横並びを作るための要素ではない。

このページでは、

- どんな内容を一覧として扱うか
- `ul`と`ol`をどう使い分けるか
- `li`が何を表すか
- 見た目と文書構造をどう分けるか

を整理する。

## この範囲の芯

複数の項目を一つの一覧として扱うときは、

```text
順序に意味がない
→ ul

順序に意味がある
→ ol

一覧の1項目
→ li
```

と考える。

たとえばサービス一覧なら、

```html
<ul>
  <li>Web制作</li>
  <li>運用支援</li>
  <li>コンサルティング</li>
</ul>
```

この3項目は、並ぶ順番を入れ替えても一覧の意味が大きく変わらない。

そのため`ul`を使える。

## ulは順序に意味がない一覧

`ul`は、項目の順番そのものが中心ではない一覧に使う。

```html
<ul>
  <li>HTML</li>
  <li>CSS</li>
  <li>JavaScript</li>
</ul>
```

ここでは、

```text
HTML
CSS
JavaScript
```

という3項目が一覧であることが重要。

順番を入れ替えても、一覧そのものの意味は大きく変わらない。

このような場合は`ul`を考える。

## olは順序に意味がある一覧

`ol`は、項目の順番に意味がある一覧に使う。

```html
<ol>
  <li>フォームに入力する</li>
  <li>確認画面を開く</li>
  <li>送信する</li>
</ol>
```

この場合、

```text
1. 入力
2. 確認
3. 送信
```

という順序そのものが重要。

順番を入れ替えると意味が変わる。

そのため`ol`を使う。

## liは一覧の1項目

`li`は、`ul`や`ol`の中にある一つの項目を表す。

```html
<ul>
  <li>HTML</li>
  <li>CSS</li>
</ul>
```

ここでは、

```text
ul
→ 一覧全体

li
→ 一覧の1項目
```

という関係になる。

`li`は単独で「縦に並べる箱」として使うものではない。

## ul・olの直接の子はliにする

一覧の項目を組む通常のHTMLでは、`ul`や`ol`の直接の子に`li`を置く。

```html
<ul>
  <li>項目1</li>
  <li>項目2</li>
</ul>
```

カード用の`div`などが必要なら、`li`の中へ入れる。

```html
<ul>
  <li>
    <div class="card">
      <h3>タイトル</h3>
      <p>説明文</p>
    </div>
  </li>
</ul>
```

構造は、

```text
ul
└─ li
   └─ div
      ├─ h3
      └─ p
```

となる。

次のように、`ul`と`li`の間へ`div`を入れない。

```html
<ul>
  <div>
    <li>項目</li>
  </div>
</ul>
```

基本の順序は、

```text
ul・ol
↓
li
↓
その項目に必要な内容
```

と考える。

## 見た目でulやolを決めない

たとえば、画面上で横に3つ並んでいても、

```text
HTML   CSS   JavaScript
```

内容が一覧なら`ul`を使える。

```html
<ul class="skill-list">
  <li>HTML</li>
  <li>CSS</li>
  <li>JavaScript</li>
</ul>
```

CSSで、

```css
.skill-list {
  display: flex;
}
```

とすれば横並びにできる。

つまり、

```text
HTML
→ 一覧かどうかを決める

CSS
→ 縦並び・横並びなど見た目を決める
```

と分ける。

複数の項目をFlexやGridで配置する方法は、[FlexとGridで子要素を並べる](../09_レイアウト/01_FlexとGridで子要素を並べる.md)で扱う。

## 箇条書きの点が欲しいからulではない

`ul`を使う理由は、

```text
・を表示したい
```

ではない。

リストマーカーはCSSで変更できる。

```css
.skill-list {
  list-style: none;
}
```

として見た目から点を消しても、HTML上の構造は`ul`のまま。

逆に、

```text
点を表示したい
→ ul
```

と考えない。

判断するのは内容の関係。

## 数字を表示したいからolではない

`ol`も同じ。

```text
1
2
3
```

という数字を見せたいだけで`ol`を選ぶわけではない。

重要なのは、

> 順番を入れ替えたときに意味が変わるか

という点。

たとえばランキングなら、

```html
<ol>
  <li>商品A</li>
  <li>商品B</li>
  <li>商品C</li>
</ol>
```

順位そのものに意味があるので`ol`を使いやすい。

## 一覧ではないものを無理にulにしない

複数の要素が並んでいるだけでは、必ず一覧になるわけではない。

```html
<section>
  <h2>サービス</h2>
  <p>Web制作を行っています。</p>
  <p>運用支援にも対応しています。</p>
</section>
```

これは文章として説明しているだけなら、`ul`にする必要はない。

判断するときは、

```text
複数ある
→ ul
```

ではなく、

```text
これらは同じ種類の項目として
一つの一覧を作っているか
```

を見る。

## liの中には複数の要素を入れられる

`li`の中身は文字だけとは限らない。

```html
<ul>
  <li>
    <h3>ベーシックプラン</h3>
    <p>基本機能を利用できます。</p>
    <a href="/basic/">詳しく見る</a>
  </li>

  <li>
    <h3>プロプラン</h3>
    <p>すべての機能を利用できます。</p>
    <a href="/pro/">詳しく見る</a>
  </li>
</ul>
```

ここでは、一つの`li`が、

```text
プラン一覧の1項目
```

を表している。

その1項目の中に、

```text
見出し
説明
リンク
```

を持たせている。

## liだけで足りる場合がある

カード型の一覧でも、1件ずつが独立した記事ではないなら、`li`だけで十分な場合がある。

```html
<ul>
  <li>
    <h3>高品質</h3>
    <p>品質を重視しています。</p>
  </li>

  <li>
    <h3>低価格</h3>
    <p>価格を抑えています。</p>
  </li>
</ul>
```

この場合、

```text
ul
→ 特徴一覧

li
→ 特徴1件
```

で意味を表せる。

見た目がカードだから`article`を追加するわけではない。

カード1件へ`li`・`article`・`div`・`a`をどう組み合わせるかは、[カード1件のHTMLを決める](./12_カード1件のHTMLを決める.md)で扱う。

## articleと組み合わせることもある

一覧の1項目そのものが独立した内容なら、

```html
<ul>
  <li>
    <article>
      <h2>記事タイトルA</h2>
      <p>記事の概要です。</p>
    </article>
  </li>

  <li>
    <article>
      <h2>記事タイトルB</h2>
      <p>記事の概要です。</p>
    </article>
  </li>
</ul>
```

のように組み合わせることもできる。

ここでは、

```text
ul
→ 記事一覧

li
→ 一覧の1項目

article
→ その中にある独立した記事
```

と役割を分ける。

`article`を使う独立性の判断は、[独立した内容をarticleで囲む](./05_独立した内容をarticleで囲む.md)で扱う。

## 一覧の中に一覧を入れることもある

項目の中にさらに下位の一覧がある場合は、入れ子にできる。

```html
<ul>
  <li>
    フロントエンド
    <ul>
      <li>HTML</li>
      <li>CSS</li>
      <li>JavaScript</li>
    </ul>
  </li>

  <li>
    バックエンド
    <ul>
      <li>PHP</li>
      <li>Ruby</li>
    </ul>
  </li>
</ul>
```

構造としては、

```text
フロントエンド
├─ HTML
├─ CSS
└─ JavaScript

バックエンド
├─ PHP
└─ Ruby
```

となる。

一覧の階層があるなら、HTMLでもその親子関係を表す。

## navの中で一覧を使うこともある

ナビゲーションのリンク群を一覧として表す場合、

```html
<nav>
  <ul>
    <li><a href="/">ホーム</a></li>
    <li><a href="/about/">会社情報</a></li>
    <li><a href="/contact/">お問い合わせ</a></li>
  </ul>
</nav>
```

のように組める。

この場合、

```text
nav
→ ナビゲーション

ul
→ ナビゲーション項目の一覧

li
→ 1項目

a
→ 移動
```

と役割を分けている。

## パンくずではolを使いやすい

パンくずでは、

```text
ホーム
→ サービス
→ Web制作
```

のように、現在地までの順序に意味がある。

そのため、

```html
<ol>
  <li><a href="/">ホーム</a></li>
  <li><a href="/service/">サービス</a></li>
  <li>Web制作</li>
</ol>
```

のように`ol`を使いやすい。

パンくず全体の構造は、[パンくずをHTMLで組む](./13_パンくずをHTMLで組む.md)で扱う。

## 判断するときの見方

一覧として組むか迷ったら、

```text
これらは、
同じ種類の項目として
一つのまとまりを作っているか
```

を見る。

一覧なら、次に、

```text
順番を入れ替えても意味がほぼ変わらないか
```

を考える。

```text
変わらない
→ ul

変わる
→ ol
```

と判断する。

そして、

```text
その一覧の1項目
→ li
```

と考える。

## このページのまとめ

- `ul`と`ol`は一覧を表す
- `li`は一覧の1項目を表す
- `ul`・`ol`の直接の子には`li`を置き、必要な箱や内容は`li`の中へ入れる
- 順序に意味がなければ`ul`
- 順序に意味があれば`ol`
- 横並び・縦並びなどの見た目で決めない
- 箇条書きの点が欲しいから`ul`を使うわけではない
- 数字を表示したいだけで`ol`を使うわけではない
- `li`の中には見出し・文章・リンクなどを入れられる
- 一覧の1件が独立した内容なら`article`と組み合わせることもある
- 判断するときは「一覧か」「順番に意味があるか」を見る
