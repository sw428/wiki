# 12_カード1件のHTMLを決める

## このページの役割

カード型のデザインはよく使われるが、

```text
カード
→ article
```

と機械的に決めるものではない。

このページでは、

- カード一覧をどう組むか
- `li`だけで足りる場合
- `article`を使う場合
- `div`を追加する場合

を整理する。

## この範囲の芯

カードのHTMLは、見た目ではなく**その1件が何を表しているか**で決める。

基本は、

```text
一覧の1項目
→ li

その1件が単独でも成立する内容
→ liの中にarticleを検討

意味を追加せず、レイアウト用の箱が必要
→ divを検討
```

と考える。

## liだけで足りる場合

たとえば、サービスの特徴を3件並べる場合。

```html
<ul>
  <li>
    <h3>高品質</h3>
    <p>品質を重視して制作します。</p>
  </li>

  <li>
    <h3>低価格</h3>
    <p>必要な機能に絞って価格を抑えます。</p>
  </li>

  <li>
    <h3>短納期</h3>
    <p>素早い制作にも対応します。</p>
  </li>
</ul>
```

ここでは、

```text
ul
→ 特徴一覧

li
→ 特徴1件
```

だけで役割を表せる。

見た目がカードでも、`article`を追加する必要はない。

カード1件が、

```text
一覧の中の1項目として意味を持つ
```

だけなら、`li`で十分なことが多い。

たとえば、

- 特徴一覧
- 料金プラン一覧
- スタッフ一覧
- コース一覧
- バナー一覧

など。

一覧自体を`ul`と`ol`のどちらで表すか、`li`をどこへ置くかは、[一覧をul・ol・liで組む](./11_一覧をul・ol・liで組む.md)で扱う。

## articleを使う場合

カード1件が、その部分だけを切り出しても一つの内容として成立するなら、`article`を検討する。

たとえば記事一覧。

```html
<ul>
  <li>
    <article>
      <h2>
        <a href="/articles/html-basic/">
          HTMLの基本
        </a>
      </h2>

      <p>HTMLの基本を解説します。</p>
    </article>
  </li>

  <li>
    <article>
      <h2>
        <a href="/articles/css-basic/">
          CSSの基本
        </a>
      </h2>

      <p>CSSの基本を解説します。</p>
    </article>
  </li>
</ul>
```

ここでは、

```text
ul
→ 記事一覧

li
→ 一覧の1項目

article
→ 独立した記事1件
```

と役割を分けている。

`li`と`article`は二択ではない。`li`が一覧の1項目、`article`がその中の独立した内容を担当するため、必要なら役割を重ねる。見た目がカードかどうかだけでは`article`を追加しない。

`article`を使う独立性の判断は、[独立した内容をarticleで囲む](./05_独立した内容をarticleで囲む.md)で扱う。

## divは追加の箱が必要なときに使う

`li`の中には複数の要素を直接置ける。

```html
<li>
  <img src="course.jpg" alt="">
  <h3>Web制作コース</h3>
  <p>HTMLとCSSを学びます。</p>
  <a href="/course/">詳しく見る</a>
</li>
```

そのため、

```text
liの中には必ずdivを1つ置く
```

というルールはない。

`div`がなくても構造やCSSを作れるなら、そのままでよい。

一方、画像とは別に本文部分だけへ余白を付けたい場合は、範囲を作るために`div`を追加できる。

```html
<ul>
  <li>
    <img src="staff01.jpg" alt="">

    <div>
      <h3>山田 太郎</h3>
      <p>Webデザイナー</p>
    </div>
  </li>
</ul>
```

ここでは、

```text
ul
→ スタッフ一覧

li
→ スタッフ1件とカード全体

div
→ 見出しと説明へ共通の余白を付ける範囲
```

となる。

`div`は文書上の意味を追加しない。レイアウトや装飾に必要な範囲があるときに追加する。

## カード内の移動と操作を分ける

カードから詳細ページへ移動する範囲には`a`、その場でお気に入り登録などを行う範囲には`button`を使う。詳しい使い分けは、[リンクとボタンを使い分ける](./10_リンクとボタンを使い分ける.md)で扱う。

カード全体を押して詳細ページへ移動させるデザインでも、意味としてはリンク。

```html
<article>
  <a href="/article/">
    <h2>記事タイトル</h2>
    <p>記事の概要です。</p>
  </a>
</article>
```

ただし、リンクの中に別のリンクやボタンを入れない。

たとえば、

```text
記事タイトル
→ 記事詳細へ移動

お気に入りボタン
→ その場で状態を変更
```

のように複数の移動や操作があるなら、カード全体を一つのリンクで囲まず、それぞれの操作範囲を分ける。

まずHTMLでは、

```text
何が移動なのか
何が操作なのか
```

を分ける。

## 画像があるからfigureになるわけではない

カードに画像が入っていても、

```html
<li>
  <img src="staff.jpg" alt="山田太郎">
  <h3>山田 太郎</h3>
</li>
```

のように、通常の`img`でよい場合がある。

```text
カードに画像がある
→ figure
```

ではない。

`figure`は、自己完結した図版として扱うかどうかで判断する。詳しくは[図版をfigureでまとめる](./17_図版をfigureでまとめる.md)で扱う。

## 判断するときの見方

カード1件のHTMLを決めるときは、順番に見る。

```text
1. 複数件を一つの一覧として扱うか
   ↓
   Yes → ul・ol + li

2. その1件は単独でも成立する内容か
   ↓
   Yes → articleを検討

3. レイアウト用の追加の箱が必要か
   ↓
   Yes → divを検討

4. 移動や操作をどの範囲に持たせるか
   ↓
   aとbuttonの担当を分ける
```

つまり、

```text
カードという見た目
```

からHTMLを決めるのではなく、

```text
一覧か
独立した内容か
追加の箱が必要か
移動か操作か
```

を順番に判断する。

## このページのまとめ

- カードはHTML要素の名前ではない
- カード一覧なら、まず一覧として扱うかを見る
- 一覧の1件は`li`
- `li`だけで意味が足りることも多い
- 1件が単独でも成立するなら`article`を検討する
- `li`と`article`は別の役割なので組み合わせることもある
- `div`はレイアウトなどで追加の箱が必要なときに使う
- `li`の中に必ず`div`が必要なわけではない
- カード内の移動と操作は`a`と`button`へ分ける
- カードという見た目から要素を決めず、1件の役割から判断する
