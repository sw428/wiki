# 09_見出し階層を決める

## このページの役割

`h1`〜`h6`は、文字を大きくしたり小さくしたりするための要素ではない。

このページでは、

- 見出しレベルを何で決めるか
- `h1`〜`h6`の数字が何を表すか
- 見た目と文書階層をどう分けるか

を整理する。

## この範囲の芯

見出しの数字は、**文書内の階層**を表す。

```html
<h1>サービス紹介</h1>

<section>
  <h2>料金</h2>

  <section>
    <h3>個人プラン</h3>
  </section>
</section>
```

この構造は、

```text
サービス紹介
└─ 料金
   └─ 個人プラン
```

という階層を表している。

大事なのは、

> 文字をどのくらい大きくしたいか

ではなく、

> この見出しは文書構造のどの階層にあるか

で選ぶこと。

通常のWebページでは、ページを代表する見出しを`h1`とし、その下の章を`h2`、さらに下位の内容を`h3`以降で表すと構造を追いやすい。

## sectionやarticleの中でも考え方は同じ

`section`や`article`の中にも見出し階層を作れる。

```html
<article>
  <h2>新サービスを公開しました</h2>

  <section>
    <h3>サービスの特徴</h3>
    ...
  </section>
</article>
```

ここでは、記事タイトルの下に「サービスの特徴」がある。

`section`を作るたびに機械的に数字を一つ増やすのではなく、ページ全体の親子関係から見出しレベルを選ぶ。

## 下位へ進むときは、理由なくレベルを飛ばさない

次のように`h1`の直下を`h3`にすると、間にあるはずの階層が分かりにくくなる。

```html
<h1>サービス</h1>
<h3>料金</h3>
```

「料金」が`h1`直下の章なら、`h2`にする。

```html
<h1>サービス</h1>
<h2>料金</h2>
```

一方、`h3`の内容を終えて次の`h2`へ戻ることは、階層を飛ばすことではない。数字を機械的に連番にするのではなく、実際の親子関係と一致させる。

## 文字サイズや装飾から決めない

文字を小さくしたいという理由で、`h2`を`h4`へ変えない。文書構造として`h2`なら、見た目はCSSで調整する。

```html
<h2 class="title">料金</h2>
```

```css
.title {
  font-size: 1.5rem;
}
```

反対に、目立つ文字がすべて見出しになるわけでもない。

```html
<span>NEW</span>
```

この後の内容に名前を付けていないなら、装飾のためだけに`h1`〜`h6`を使わない。

## 見出しだけで構造を確認する

見出しだけを抜き出したときに、ページの構造を追えるか確認する。

```text
HTMLの基本
├─ HTMLとは
├─ 要素とは
│  ├─ 開始タグ
│  └─ 終了タグ
└─ 属性とは
```

親子関係が不自然なら、文字サイズではなく、内容同士の関係から見出しレベルを見直す。

## 判断するときの見方

どの見出しレベルを使うか迷ったら、

```text
この見出しの親となる見出しは何か
```

を確認し、その親子関係に合う見出しレベルを選ぶ。

文字サイズやデザインツール上の名称から決めない。

## このページのまとめ

- `h1`〜`h6`は文書の見出し階層を表す
- 文字サイズで見出しレベルを決めない
- 最上位から下位へ親子関係で考える
- `section`や`article`の構造と一緒に考える
- 下位へ進むときは理由なく見出しレベルを飛ばさない
- 強調したいだけの文字に見出し要素を使わない
- 見た目はCSSで調整する
- 見出しだけを追っても文書構造が分かる状態を目指す
- 判断するときは「この見出しの親は何か」を見る
