# 04_章をsectionで分ける

## このページの役割

`section`は、見た目を分けるための箱ではない。

このページでは、

- どんなまとまりを`section`にするか
- `div`とは何が違うか
- 見出しとどう組み合わせるか

を整理する。

## この範囲の芯

`section`は、文書の中にある**意味のあるまとまり**を表す。

```html
<section>
  <h2>サービス内容</h2>
  <p>提供しているサービスについて説明します。</p>
</section>
```

ここでは、

```text
section
→ 「サービス内容」という一つの章・まとまり

h2
→ そのまとまりの見出し
```

という関係になる。

大事なのは、

> デザイン上まとまって見えるか

ではなく、

> 文書として一つのテーマを持った範囲か

で判断すること。

## sectionは意味のある区切りに使う

たとえば次のページがあるとする。

```text
サービス紹介

特徴
料金
利用の流れ
よくある質問
```

それぞれが独立したテーマを持つなら、`section`で分けられる。

```html
<main>
  <h1>サービス紹介</h1>

  <section>
    <h2>特徴</h2>
    ...
  </section>

  <section>
    <h2>料金</h2>
    ...
  </section>

  <section>
    <h2>利用の流れ</h2>
    ...
  </section>

  <section>
    <h2>よくある質問</h2>
    ...
  </section>
</main>
```

このとき`section`は、CSSのレイアウト用ではなく、文書構造を分けている。

## 見出しと一緒に考える

`section`は、通常その範囲に何らかのテーマがある。

そのため、基本的には、

```text
section
↓
その範囲を説明する見出し
```

という関係で考える。

```html
<section>
  <h2>料金</h2>
  <p>料金について説明します。</p>
</section>
```

逆に、

```html
<section>
  <div>...</div>
</section>
```

のように、何のまとまりなのか説明できない場合は、本当に`section`が必要か確認する。

判断するときは、

> この範囲に名前を付けるなら何になるか

を考えると分かりやすい。

## divとの違い

`div`は、それ自体では文書上の意味を追加しない。

```html
<div class="cards">
  ...
</div>
```

これは、

```text
カードを横並びにする
幅を制御する
背景を付ける
```

など、主に実装上の都合でまとめるために使える。

一方、

```html
<section>
  <h2>講師紹介</h2>
  ...
</section>
```

は、「講師紹介」という文書上のまとまりを表している。

整理すると、

```text
section
→ 意味のある文書上の区切り

div
→ 意味を追加せず、必要な範囲をまとめる
```

となる。

## 見た目だけでsectionにしない

デザイン上、背景色が変わっていたり余白が大きく空いていても、それだけでは`section`にする理由にはならない。

```html
<div class="background-wrapper">
  ...
</div>
```

のように、装飾やレイアウトのためだけなら`div`でよいことがある。

逆に、見た目が続いていても、

```text
会社概要
↓
沿革
↓
アクセス
```

のように文書として別のテーマなら、それぞれを`section`に分けることができる。

つまり、

```text
見た目の境界
≠ HTML上のsectionの境界
```

と考える。

## sectionの中にsectionを入れることもある

文書構造としてさらに下位の章があるなら、`section`を入れ子にできる。

```html
<section>
  <h2>サービス</h2>

  <section>
    <h3>Web制作</h3>
    ...
  </section>

  <section>
    <h3>運用支援</h3>
    ...
  </section>
</section>
```

ここでは、

```text
サービス
├─ Web制作
└─ 運用支援
```

という文書階層を表している。

ただし、単にカードを3つ並べたいから`section`を3つ作る、という判断はしない。

## articleとの違い

`section`と`article`は、どちらも意味のある範囲を表す。

ただし判断軸が違う。

```text
section
→ 文書の中の一つの章・テーマ

article
→ 単独で切り出しても成立しやすい内容
```

たとえば、

```html
<section>
  <h2>お知らせ</h2>

  <article>
    <h3>新サービスを公開しました</h3>
    ...
  </article>

  <article>
    <h3>営業時間変更のお知らせ</h3>
    ...
  </article>
</section>
```

なら、

```text
section
→ 「お知らせ」というまとまり

article
→ お知らせ1件ごとの独立した内容
```

と分けられる。

`article`の詳しい判断は次のページで扱う。

## sectionにclassを付けてもよい

意味を持つ`section`でも、CSS用のclassを付けられる。

```html
<section class="service">
  <h2>サービス</h2>
  ...
</section>
```

```text
section
→ HTML上の意味

class
→ CSSやJavaScriptから分類・参照するための名前
```

なので、どちらか一方を選ぶ話ではない。

## 判断するときの見方

`section`を使うか迷ったら、まず次を見る。

```text
この範囲は、
文書の中で一つのテーマを持っているか
```

さらに、

```text
この範囲に見出しを付けるなら、
自然な名前を付けられるか
```

を考える。

意味のある章なら`section`を検討する。

レイアウトや装飾のために囲いたいだけなら、`div`を検討する。

## このページのまとめ

- `section`は文書内の意味のあるまとまりを表す
- 見た目の区切りだけで`section`を選ばない
- 基本的に、その範囲のテーマや見出しと一緒に考える
- `div`は意味を追加せず、実装上必要な範囲をまとめる
- `section`は入れ子にできる
- `article`とは「単独で成立するか」という判断軸が違う
- 判断するときは、配置ではなく文書内の役割を見る
