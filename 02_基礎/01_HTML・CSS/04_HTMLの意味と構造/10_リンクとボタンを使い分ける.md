# 10_リンクとボタンを使い分ける

## このページの役割

`a`と`button`は、見た目が似ていても役割が違う。

このページでは、

- `a`を使う場面
- `button`を使う場面
- 見た目ではなく動作から選ぶ考え方

を整理する。

## この範囲の芯

基本は、

```text
移動する
→ a

その場で操作する
→ button
```

と考える。

たとえば別ページへ移動するなら、

```html
<a href="/contact/">お問い合わせ</a>
```

その場でメニューを開くなら、

```html
<button type="button">
  メニューを開く
</button>
```

を使う。

## aは移動を表す

`a`は、別の場所へ移動するために使う。

```html
<a href="/about/">会社情報</a>
```

ここでは、

```text
現在のページ
↓
別のURL
```

へ移動する。

移動先は別ページだけとは限らない。

## ページ内移動にもaを使う

同じページ内の別の場所へ移動する場合も`a`を使う。

```html
<a href="#price">料金を見る</a>
```

```html
<section id="price">
  <h2>料金</h2>
</section>
```

これは、

```text
現在位置
↓
同じページ内の別の位置
```

への移動。

そのため`button`ではなく`a`として考える。

## 外部サイトへの移動にもaを使う

```html
<a href="https://example.com/">
  公式サイト
</a>
```

これも移動なので`a`を使う。

判断の中心は、

```text
同じサイトか
外部サイトか
```

ではなく、

```text
移動かどうか
```

を見る。

## buttonはその場の操作を表す

`button`は、現在の画面上で何かを実行する操作に使う。

```html
<button type="button">
  メニューを開く
</button>
```

たとえば、

```text
メニューを開く
モーダルを開く
表示を切り替える
内容をコピーする
お気に入りに追加する
```

など。

この場合、別の場所へ移動することが中心ではない。

## フォーム送信にもbuttonを使う

```html
<form>
  <input type="text" name="name">

  <button type="submit">
    送信する
  </button>
</form>
```

ここでは、

```text
入力内容を送信する
```

という操作を行う。

そのため`button`を使う。

## 見た目で選ばない

たとえば、デザイン上はどちらも同じボタンのように見えることがある。

```text
[ 詳しく見る ]

[ メニューを開く ]
```

しかし役割は違う。

```html
<a class="button" href="/service/">
  詳しく見る
</a>
```

```html
<button class="button" type="button">
  メニューを開く
</button>
```

どちらもCSSで同じ見た目にできる。

つまり、

```text
見た目がボタン
→ button
```

ではない。

```text
何をする要素か
→ HTMLを決める
```

と考える。

## aをbutton代わりに使わない

たとえば、

```html
<a href="#" class="menu-button">
  メニュー
</a>
```

をJavaScriptでクリックしてメニューを開く実装は作れる。

ただし、この要素の本来の役割が、

```text
移動
```

ではなく、

```text
メニューを開く
```

なら`button`の方が役割に合う。

```html
<button type="button" class="menu-button">
  メニュー
</button>
```

とする。

## buttonでページ移動しない

逆に、

```html
<button type="button">
  会社情報を見る
</button>
```

をJavaScriptで別ページへ移動させることもできる。

ただし役割が移動なら、

```html
<a href="/about/">
  会社情報を見る
</a>
```

とする方が自然。

```text
JavaScriptで実現できるか
```

ではなく、

```text
その要素の意味として何をしているか
```

を見る。

## CTAでも役割で決める

CTAは見た目が大きなボタンになることが多い。

たとえば、

```text
無料体験はこちら
```

を押して申込ページへ移動するなら、

```html
<a href="/trial/">
  無料体験はこちら
</a>
```

を使う。

一方、

```text
無料体験フォームを開く
```

という操作でモーダルを開くなら、

```html
<button type="button">
  無料体験フォームを開く
</button>
```

を使う。

同じような見た目でも、動作によって要素が変わる。

## hrefがあるからaではなく、移動だからa

判断を逆にしない。

```text
hrefを書ける
→ aにする
```

ではなく、

```text
移動させたい
→ aを使う
→ hrefに移動先を書く
```

と考える。

同じように、

```text
JavaScriptを付けたい
→ button
```

でもない。

`a`にもJavaScriptを使うことはある。

大事なのは役割。

## buttonのtypeを確認する

`button`には`type`がある。

```html
<button type="button">
  開く
</button>
```

```html
<button type="submit">
  送信
</button>
```

フォームの中では、`type`を省略すると既定で送信ボタンになる。

そのため、単なる操作ボタンなら、

```html
<button type="button">
```

と役割を明示しておくと分かりやすい。

## aの中にbuttonを入れない

次のような構造にはしない。

```html
<a href="/service/">
  <button type="button">
    詳しく見る
  </button>
</a>
```

`a`と`button`はどちらも利用者が操作する要素なので、重ねて使わない。

移動なら、

```html
<a href="/service/">
  詳しく見る
</a>
```

操作なら、

```html
<button type="button">
  詳しく見る
</button>
```

のように、一つの役割を一つの要素に担当させる。

## カード全体をリンクにする場合

記事カードなど、カード全体を押すと詳細ページへ移動する場合は、`a`を使う。

```html
<article>
  <a href="/article/html-basic/">
    <h2>HTMLの基本</h2>
    <p>HTMLの基本を解説します。</p>
  </a>
</article>
```

実装方法によってリンク範囲は変わるが、役割としては、

```text
記事詳細へ移動
→ a
```

になる。

カードだから`button`にするわけではない。

## JavaScriptが必要かどうかで決めない

よくある混同として、

```text
a
→ HTMLだけ

button
→ JavaScript用
```

と考えない。

これは役割の違いではない。

```text
a
→ 移動

button
→ 操作
```

が基本。

JavaScriptを使うかどうかは、そのあとに決まる。

## キーボード操作も考えやすくなる

役割に合った要素を使うと、ブラウザがその要素に合った操作方法を持っている。

たとえば、

```text
a
→ リンクとして扱われる

button
→ ボタンとして扱われる
```

ため、キーボード操作や支援技術でも役割が伝わりやすい。

見た目だけを合わせるより、最初から役割に合う要素を選ぶ方が扱いやすい。

## 判断するときの見方

`a`と`button`で迷ったら、

```text
押したあと、
利用者は別の場所へ移動するのか
```

を見る。

移動するなら、

```text
a
```

を検討する。

移動せず、その場で何かを実行するなら、

```text
button
```

を検討する。

最初に見るのは、色や形ではなく動作。

## このページのまとめ

- `a`は移動を表す
- `button`はその場の操作を表す
- 別ページだけでなくページ内移動も`a`
- メニューやモーダルを開くなら`button`
- フォーム送信には`button`を使う
- 見た目がボタンでも、移動なら`a`
- `a`をJavaScript操作用のボタン代わりにしない
- `button`をページ移動用にしない
- `a`と`button`を入れ子にしない
- JavaScriptを使うかどうかではなく、役割で決める
- 判断するときは「移動か、操作か」を見る
