# 06_補足内容をasideで分ける

## このページの役割

`aside`は、画面の横側に置くための要素ではない。

このページでは、

- どんな内容を`aside`にするか
- `section`や`div`とは何が違うか
- ページ全体に対する補足と、記事内の補足をどう考えるか

を整理する。

## この範囲の芯

`aside`は、**周囲の主な内容とは少し離れた、補足的な内容**を表す。

```html
<article>
  <h1>HTMLの基本</h1>

  <p>HTMLは文書の構造や意味を表す。</p>

  <aside>
    <h2>補足</h2>
    <p>HTMLという名前はHyperText Markup Languageの略。</p>
  </aside>
</article>
```

ここでは、

```text
article
→ 主な内容

aside
→ その内容に関連する補足
```

という関係になる。

大事なのは、

> 横に配置されているか

ではなく、

> 主な内容から少し外れても成立する補足か

で判断すること。

## asideは配置ではなく役割で決める

`aside`という名前から、

```text
画面の右側
→ aside
```

と考えない。

たとえば、右側に配置されていても、

```html
<div class="sidebar">
  <nav>
    ...
  </nav>
</div>
```

のように、単にレイアウト上サイドバーになっているだけなら、外側が必ず`aside`になるわけではない。

逆に、本文の途中に表示されていても、

```html
<aside>
  <h2>関連情報</h2>
  <p>この内容に関連する補足です。</p>
</aside>
```

のように補足的な内容なら`aside`を使える。

つまり、

```text
画面上の位置
≠ asideを使う理由
```

となる。

## 主内容と補足内容を分ける

たとえば記事の中に次の内容があるとする。

```text
CSSのボックスモデルについて説明する本文

関連する豆知識

参考になる別の記事

用語の補足
```

本文を理解するための中心部分ではなく、なくても本文そのものは成立する内容なら、`aside`を検討できる。

```html
<article>
  <h1>CSSのボックスモデル</h1>

  <p>ボックスモデルは...</p>

  <aside>
    <h2>関連用語</h2>
    <p>content boxやborder boxという呼び方も使われます。</p>
  </aside>
</article>
```

判断するときは、

> この補足を一度外しても、主な内容は成立するか

を見ると分かりやすい。

## sectionとの違い

`section`も`aside`も意味のある範囲を表す。

ただし役割が違う。

```text
section
→ 主な文書構造の中にある一つの章・テーマ

aside
→ 主内容に関連する補足的な内容
```

たとえば、

```html
<section>
  <h2>料金</h2>
  <p>料金について説明します。</p>
</section>
```

は、ページの主要な章なので`section`。

一方、

```html
<aside>
  <h2>料金に関する補足</h2>
  <p>キャンペーン期間中は割引があります。</p>
</aside>
```

のように、中心の説明とは別の補足なら`aside`を検討できる。

## divとの違い

`div`は、それ自体では意味を追加しない。

```html
<div class="aside-layout">
  ...
</div>
```

これは単にレイアウト用の箱として使える。

一方、

```html
<aside>
  <h2>関連記事</h2>
  ...
</aside>
```

は、

「ここは主内容とは別の補足的な内容です」

という意味を追加する。

整理すると、

```text
aside
→ 補足という意味を持つ

div
→ 意味を追加せず範囲をまとめる
```

となる。

## articleの中にasideを置ける

`aside`は記事全体に対する補足として使える。

```html
<article>
  <h1>JavaScriptの非同期処理</h1>

  <p>非同期処理では...</p>

  <aside>
    <h2>実行タイミングの注意</h2>
    <p>setTimeoutの待ち時間は、処理が完了する時刻を保証するものではありません。</p>
  </aside>
</article>
```

この場合、

```text
article
→ 記事本体

aside
→ その記事に関連する補足
```

として読む。

## ページ全体に対するasideもある

`aside`は`article`の中だけで使うものではない。

```html
<main>
  ...
</main>

<aside>
  <h2>関連記事</h2>
  ...
</aside>
```

のように、ページ全体の主内容に関連する補足として使うこともできる。

たとえば、

```text
関連記事
記事本体から離して読める著者紹介
関連リンク
補足的な案内
```

などが候補になる。

ただし、その内容が本当に補足なのかはページごとに判断する。

## 関連しているだけではasideとは限らない

主内容と関係があるからといって、何でも`aside`にするわけではない。

たとえば、

```html
<section>
  <h2>利用方法</h2>
  ...
</section>
```

がページの中心的な説明なら、それは補足ではなく主内容。

```text
関連している
↓
aside
```

ではなく、

```text
主内容に必要な中心部分か

それとも

主内容から少し外れた補足か
```

を見る。

## asideの中にも見出しを置ける

`aside`が何についての補足なのか分かるように、見出しを持たせることがある。

```html
<aside>
  <h2>関連記事</h2>

  <ul>
    <li><a href="/html/">HTMLの基本</a></li>
    <li><a href="/css/">CSSの基本</a></li>
  </ul>
</aside>
```

ここでは、

```text
aside
→ 補足的なまとまり

h2
→ その補足の内容を示す

ul
→ 関連記事の一覧

a
→ 移動
```

と役割を分けている。

## navと組み合わせることもある

補足エリアの中にナビゲーションが入る場合もある。

```html
<aside>
  <h2>関連ページ</h2>

  <nav aria-label="関連ページ">
    <ul>
      <li><a href="/html/">HTML</a></li>
      <li><a href="/css/">CSS</a></li>
    </ul>
  </nav>
</aside>
```

このとき、

```text
aside
→ 補足的な範囲

nav
→ その中のナビゲーション
```

という別々の役割を持つ。

`aside`があるから`nav`が不要になるわけではない。

## 判断するときの見方

`aside`を使うか迷ったら、次を見る。

```text
この内容は、
周囲の主な内容と関係しているか
```

そのうえで、

```text
この部分を取り除いても、
主な内容そのものは成立するか
```

を考える。

成立するなら、補足として`aside`を使える可能性がある。

ただし、

```text
右側にある
カードになっている
背景色が違う
```

といった見た目だけでは判断しない。

## このページのまとめ

- `aside`は主内容に関連する補足的な内容を表す
- 画面の横側にあるから`aside`になるわけではない
- `section`は主な章、`aside`は補足という役割の違いがある
- `div`は意味を追加せず、実装上の範囲をまとめる
- `article`の中にも外にも`aside`を置ける
- 関連しているだけで、何でも`aside`になるわけではない
- 判断するときは「これを外しても主内容は成立するか」を見る
