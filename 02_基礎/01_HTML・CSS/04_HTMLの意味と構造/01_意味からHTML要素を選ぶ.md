# 01_意味からHTML要素を選ぶ

## このページの役割

同じ大きな文字でも、ページの題名なら見出し、本文を強調したいだけなら別の要素を選ぶ。

HTMLでは「どう見えるか」より先に、**その内容が文書の中で何を担当するか**を決める。

このページでは、小さなHTML例から、役割に合う要素を選ぶ基本を確認する。

タグ・内容・要素の読み方が曖昧なら、[タグ・内容・要素を区別する](../01_HTMLの土台/03_タグ・内容・要素を区別する.md)で確認できる。

## 同じ見た目でも、HTMLの役割は違う

次の2つは、CSSで同じ文字サイズや余白にできる。

```html
<div class="title">サービス紹介</div>

<h2 class="title">サービス紹介</h2>
```

`div` は汎用のまとまり。

`h2` は、その内容が見出しであることを表す。

`class="title"` という名前だけでは、`div` が見出しになるわけではない。

| 決めること | 担当 |
| --- | --- |
| 見出し、段落、一覧、リンクなどの役割 | HTMLの要素と構造 |
| 文字サイズ、色、余白、配置 | CSS |
| 操作を受けて表示や状態を変える処理 | JavaScript |

内容の役割をHTML要素と構造で表す考え方を、セマンティックHTMLという。

たとえば、サービス紹介という一つのまとまりなら、次のように書ける。

```html
<section>
  <h2>サービス紹介</h2>
  <p>
    制作から公開後の更新まで支援します。
  </p>
  <a href="./service/">
    サービスの詳細を見る
  </a>
</section>
```

ここでは、

```text
section
→ 意味のある区切り

h2
→ その区切りの見出し

p
→ 説明の段落

a
→ 別の場所へ移動するリンク
```

という役割を持つ。

背景色、文字サイズ、横並び、余白などの見た目はCSSで調整する。

HTMLの要素から画面上の箱が作られる工程は、[ブラウザが表示を作る基本フロー](../07_ブラウザ挙動と表示のズレ/01_ブラウザが表示を作る基本フロー.md#基本フロー)で扱う。

それぞれの具体的な使い分けは、後続の記事で扱う。

## `div`・`span`を使う場面

`div` や `span` を使ってはいけないわけではない。

配置や装飾などのためにまとめたいだけで、追加する意味がないときに使う。

たとえば、見出しと説明を配置上まとめたいだけなら、次のように書ける。

```html
<div>
  <h2>サービス紹介</h2>
  <p>
    制作から公開後の更新まで支援します。
  </p>
</div>
```

この `div` は、新しい意味を追加していない。

```text
div
→ 複数の要素を意味を追加せずまとめる

span
→ 文中などの一部分を意味を追加せずまとめる
```

背景や幅を調整する箱が必要という理由だけで、`section` や `article` などの意味を持つ要素へ変える必要はない。

## ページ全体も役割から考える

要素を選ぶ考え方は、小さな部品だけでなくページ全体でも同じ。

```html
<header>
  <a href="/">サイト名</a>

  <nav aria-label="サイト内">
    <a href="/service/">サービス</a>
    <a href="/contact/">お問い合わせ</a>
  </nav>
</header>

<main>
  <h1>私たちのサービス</h1>

  <section>
    <h2>制作支援</h2>
    <p>企画から公開までを支援します。</p>
  </section>
</main>

<footer>
  <p>&copy; 2026 サイト名</p>
</footer>
```

この例では、

```text
header
→ その範囲の導入やナビゲーションをまとめる

nav
→ 主要なナビゲーション

main
→ ページ固有の主内容

section
→ 意味のある区切り

footer
→ その範囲に関する著者・著作権・関連リンクなどをまとめる
```

という役割を持つ。

ここでは各要素の細かい条件まで覚える必要はない。

`main`、`nav`、`section`、`article`、`aside`、`header`、`footer` の具体的な判断は、02以降で一つずつ扱う。

見出し階層は09、リンクとボタンの使い分けは10で扱う。

## 位置やデザインツールの名前から決めない

HTML要素は、画面上の位置だけでは決めない。

たとえば、

```text
右側にある
→ aside
```

とは限らない。

```text
一番上にある
→ header
```

とも限らない。

```text
カード型に見える
→ article
```

とも限らない。

位置や形はCSSで変えられるため、HTMLではその内容が何を担当しているかを見る。

Figmaなどのレイヤー名・グループ名も同じ。

たとえば、デザイン上のグループが `header` と名付けられていても、それだけでHTMLの `header` を使うとは決まらない。

```text
Figmaの名前
→ デザインデータ内での整理名

HTML要素
→ 文書内で実際に担当する意味
```

レイヤー名は実装意図を考える材料にはなるが、最終的には実際の内容から判断する。

## 自分のHTMLで選択理由を確認する

作っているページから一部分を選び、その要素を使った理由を言葉にしてみる。

たとえば、

```text
ページ固有の主内容だからmain

意味のある区切りだからsection

独立した内容だからarticle

別ページへ移動するからa
```

のように、内容の役割から説明する。

反対に、

```text
上にあるからheader

右側だからaside

カードだからarticle

背景色を付けたいからsection
```

のように、大きさ、位置、見た目だけが理由になっていたら、HTMLの要素選びとCSSの指定を分け直す。

すべてを暗記して判断する必要はない。

本文や参照ページを確認しながら、

```text
この内容は文書の中で何を担当しているか
```

を説明できればよい。
