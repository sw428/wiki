# 01\_意味からHTML要素を選ぶ

同じ大きな文字でも、ページの題名なら見出し、本文を強調したいだけなら別の要素を選ぶ。HTMLでは「どう見えるか」より先に、**その内容が文書の中で何を担当するか**を決める。

このページでは、小さなHTML例から、役割に合う要素と見出しの階層を選ぶところまでを扱う。タグ・要素の読み方が曖昧なら、[タグと要素を分ける例](../01_HTMLの土台/01_タグと要素からHTMLを読む.md#タグと要素を分ける)で確認できる。

## 同じ見た目でも、HTMLの役割は違う

次の2つは、CSSで同じ文字サイズや余白にできる。

```html
<div class="title">サービス紹介</div>
<h2 class="title">サービス紹介</h2>
```

`div` は汎用のまとまり。`h2` は見出しであることと、その階層を示す。`class="title"` という名前だけでは、`div` が見出しになるわけではない。

| 決めること                           | 担当             |
| ------------------------------------ | ---------------- |
| 見出し、段落、一覧、リンクなどの役割 | HTMLの要素と構造 |
| 文字サイズ、色、余白、配置           | CSS              |
| 操作を受けて表示や状態を変える処理   | JavaScript       |

役割に合うHTMLを書くことを、セマンティックHTMLという。見た目だけでは分からない見出しや操作の意味を、ブラウザや支援技術にも伝える土台になる。

`div` や `span` を使ってはいけないわけではない。配置や装飾のためにまとめたいだけで、追加する意味がないときに使う。

## まず一つの章を、見出しと本文で作る

サービス紹介という一つの主題があり、その中に説明と詳細ページへのリンクがあるなら、次のように書ける。これはページの主見出し `h1` の下へ置く例。

```html
<section class="service">
  <h2 class="service__title">サービス紹介</h2>
  <p class="service__description">制作から公開後の更新まで支援します。</p>
  <a class="service__link" href="./service/">サービスの詳細を見る</a>
</section>
```

- `section` は「サービス紹介」という主題のまとまり。
- `h2` はその章の見出し、`p` は説明の段落。
- `a` は別ページへ移動するリンク。

HTMLには、この関係を書く。背景色を付ける、横並びにする、余白を広げるといった指定はCSSへ書く。

背景や幅を調整する箱が欲しいだけなら、`section` を増やす必要はない。

```html
<div class="service__inner">
  <h2 class="service__title">サービス紹介</h2>
  <p class="service__description">制作から公開後の更新まで支援します。</p>
</div>
```

この `div` は配置用のまとまりであり、新しい章の意味を追加していない。

## ページ全体では、どの範囲の役割かを見る

一つの章を作れたら、その章がページのどこに属するかを考える。

```html
<header>
  <a href="/">サイト名</a>
  <nav aria-label="サイト内">
    <a href="/service/">サービス</a>
    <a href="/contact/">お問い合わせ</a>
  </nav>
</header>

<main>
  <h1>私たちのサービス</h1>
  <section>
    <h2>制作支援</h2>
    <p>企画から公開までを支援します。</p>
  </section>
</main>

<footer>
  <p>&copy; 2026 サイト名</p>
</footer>
```

この例では、`header` がサイトの導入、`nav` が主要な移動先、`main` がページ固有の主内容、`footer` がページ全体の締め情報を担当する。

| 判断したい役割                     | 候補      |
| ---------------------------------- | --------- |
| ページの主内容                     | `main`    |
| その範囲の導入・見出しなど         | `header`  |
| 主要なナビゲーション               | `nav`     |
| 一つの主題を持つ区切り             | `section` |
| 単独で読める記事や投稿             | `article` |
| 周囲の主内容に対する補足           | `aside`   |
| その範囲の著者情報・関連リンクなど | `footer`  |
| 配置のためだけのまとまり           | `div`     |

位置だけでは決めない。右側に置くから `aside`、最上部だから `header`、カード型だから `article` とは限らない。記事の中にも、その記事の導入として `header` を置ける。

Figmaなどのレイヤー名も判断材料であり、HTML要素の指定ではない。`header` と名付けられた画像グループでも、配置用のまとまりなら `div` が候補になる。

範囲の分け方で迷ったら、[ページと記事の骨組み](./02_ページと記事の骨組み.md)で、ページ全体と記事内の例を比べる。

## 見出しの数字は、文字の大きさではなく階層

```html
<h1>サービス案内</h1>
<h2>制作支援</h2>
<h3>公開までの流れ</h3>
<h2>運用支援</h2>
```

「制作支援」と「運用支援」は同じ階層。「公開までの流れ」は制作支援の中の小見出しなので、一段下の `h3` にする。

判断する順は、**見出しかどうか → どの見出しの下か → 見た目をCSSで調整**。小さく見せたいことを理由に、`h2` の次を `h4` にしない。章題でない通常の文章なら `p` などを選ぶ。

同じ `h2` でも、文字サイズや装飾はクラスで変えられる。

## リンクとボタンは押した結果で分ける

角丸の四角に見えても、ページ移動ならリンク、開閉などの操作ならボタンを使う。

```html
<a class="button-link" href="./staff/">スタッフ一覧を見る</a>
<button type="button">メニューを開く</button>
```

| 押した結果                          | 要素                   |
| ----------------------------------- | ---------------------- |
| 別URLや同じページ内の位置へ移動する | `a href="..."`         |
| フォームを送信する                  | `button type="submit"` |
| メニューの開閉や表示切替を実行する  | `button type="button"` |

リンクなら、新しいタブで開く、リンク先をコピーするといった操作も保てる。ボタンにはキーボードで操作できる基本機能がある。ただし、メニューを開く処理まで自動で付くわけではなく、JavaScriptなどで実装する。

`div` にボタンらしいクラス名や `role="button"` を付けるだけでは、キーボード操作などは揃わない。まず適切なHTML要素を選び、その上で必要な名前や状態を補う。[ボタンの操作と名前の要件](https://www.w3.org/WAI/ARIA/apg/patterns/button/)を参照。

開閉する部品を実装するときは、[UI実装の属性と最小例](../../02_JS/03_UI実装パターン.md#4役で見る最小記憶)へ進む。

## 自分のHTMLで、要素を選んだ理由を確かめる

作っているページから一部分を選び、「章だから `section`」「移動だから `a`」のように役割を説明する。大きさや座標だけが理由になっていたら、要素選びとCSSの指定を分け直す。本文やAIを見ながら確認できればよい。

具体的な内容を組むときは、必要な例へ進む。

- [一覧とカードのHTML](./03_一覧とカードのHTML.md)：一覧全体と1件分、パンくず、日付を組む。
- [図版と段落のHTML](./04_図版と段落のHTML.md)：画像を段落に含めるか、説明付きの図版として扱うかを選ぶ。
- [連絡先と住所のHTML](./05_連絡先と住所のHTML.md)：`address` と改行・段落の役割を分ける。

文字を画像へまとめる判断は[文字を画像にする前に確認する](../10_画像と背景/05_文字を画像にする前に確認する.md)、クラスの命名は[BEMとクラス命名](../../07_設計/CSS設計/01_BEMとクラス命名.md#クラスを付ける要素を選ぶ)で扱う。
