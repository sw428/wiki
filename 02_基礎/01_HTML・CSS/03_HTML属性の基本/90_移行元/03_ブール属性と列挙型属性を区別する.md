# 03_ブール属性と列挙型属性を区別する

属性の状態は、すべて`"true"`と`"false"`で切り替えるわけではない。属性の存在で決まるブール属性と、決められたキーワードから選ぶ列挙型属性を分ける。

## ブール属性は存在すれば真になる

代表例には`required`、`disabled`、`checked`、`selected`、`readonly`、`multiple`がある。

```html
<input required>
<input required="">
<input required="required">
```

上の三つは、いずれも`required`属性が存在するため真として扱われる。HTML構文上、ブール属性へ書ける値は空文字列か、属性名と大文字・小文字を区別せず一致する値。

```html
<input required="false">
```

`"false"`はブール属性の有効な値ではない。さらに属性自体は存在するため、偽にはならず必須状態として扱われる。偽にするには属性を外す。

```html
<!-- 必須 -->
<input required>

<!-- 必須ではない -->
<input>
```

JavaScriptでは、対応するブール型のDOMプロパティを使える場合がある。

```js
input.required = true;
input.required = false;
```

## 列挙型属性は有効なキーワードから選ぶ

列挙型属性は、仕様で決められたキーワードを状態へ対応させる。属性がない場合、空の場合、不正な値の場合の既定状態は属性ごとに異なる。

```html
<button type="button">送信しないボタン</button>
<input type="email">
<div contenteditable="false">編集できない領域</div>
```

`contenteditable="false"`は、属性が存在しても編集不可になる。ブール属性の規則は使わない。

## `contenteditable`はHTML属性値とDOMプロパティを分ける

| HTMLでの指定 | 状態 |
| --- | --- |
| `contenteditable="true"` | 編集できる |
| `contenteditable=""`または`contenteditable` | True状態になる |
| `contenteditable="false"` | 編集できない |
| `contenteditable="plaintext-only"` | 書式なしのテキストだけ編集できる |
| 属性を省略 | 親の編集可否を継承する |
| 無効な値 | 親の編集可否を継承する |

以前の説明では`inherit`をHTMLへ書ける有効なキーワードとして扱っていたが、これはHTML属性の状態とDOMプロパティの値を混同した説明だった。

```html
<div contenteditable="inherit">...</div>
```

HTML属性では`inherit`は無効な値であり、結果としてInherit状態になる。継承させる意図なら属性自体を省略する。

一方、JavaScriptの`element.contentEditable`プロパティは`"inherit"`を取得・設定できる。このプロパティへ`"inherit"`を設定すると、HTMLの`contenteditable`属性が取り除かれる。

```js
element.contentEditable = "inherit";
```

同じ名前に見えるHTML属性とDOMプロパティでも、受け取る値と操作結果を分けて確認する。

## 判断手順

1. その属性がブール属性か確認する。
2. ブール属性なら、偽にするとき属性を外す。
3. 列挙型属性なら、有効なキーワードとmissing・invalid・emptyの既定状態を確認する。
4. JavaScriptから変更するときは、対応するDOMプロパティが何を反映するか確認する。

## 一言でいうと

ブール属性は付けるか外すかで表し、列挙型属性はその属性に定義された値と既定状態を確認する。
