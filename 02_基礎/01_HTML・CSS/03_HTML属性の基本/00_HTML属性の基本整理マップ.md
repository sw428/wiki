## 反映先と確認順

1. 01は人間向け概要とし、属性一覧を暗記させず、参照先・識別・状態・関係など現在の役割を言葉にする入口とする。
2. 引用符、大文字・小文字など属性名と属性値の構文は02へ分ける。個別属性の有効値や省略時の扱いは対応する本文、`contenteditable`属性とDOMプロパティの違いは[03_詳細](../../../03_詳細/01_HTML・CSS/01_contenteditable属性とcontentEditableプロパティを区別する.md)、ブール属性に対応するDOMプロパティの操作は[DOMとイベント](../../02_JS/02_DOMとイベント.md#ブール属性に対応するプロパティ)で確認する。
3. `id`と`class`の命名方針は[CSS設計](../../07_設計/CSS設計/01_BEMとクラス命名.md)、セレクタの対象確認は[14](../14_セレクタと構造依存/00_セレクタと構造依存整理マップ.md)へ分担する。
4. `role`と`aria-*`は属性の使い方を05に残し、要素選択は[04](../04_HTMLの意味と構造/01_意味からHTML要素を選ぶ.md)、アクセシビリティツリーの仕組みは[03_詳細](../../../03_詳細/01_HTML・CSS/02_意味構造とアクセシビリティツリー.md)へつなぐ。
5. `data-*`は標準属性で表せないページ固有のデータに使う。標準の意味やブラウザ動作を置き換える用途へ広げない。
6. `tabindex`の`0`、負の値、正の値は、フォーカスへの参加方法を比較する一つの判断として07にまとめる。
7. 更新時は、属性名の構文、属性値の規則、その属性が作る意味・動作を分ける。ブール属性の規則を列挙型属性へ当てはめない。
