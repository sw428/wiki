# 04_ブール属性と列挙型属性を区別する

HTML属性の状態は、すべて`"true"`と`"false"`で切り替えるわけではない。

属性が**存在するかどうか**で状態が決まるブール属性と、決められた**属性値**によって状態が決まる列挙型属性を分けて考える。

## ブール属性は存在すれば真になる

代表的なブール属性には、`required`、`disabled`、`checked`、`selected`、`readonly`、`multiple`などがある。

```html
<input required>
```

`required`属性が存在するため、この入力欄は必須として扱われる。

HTMLでは、次の書き方も同じく真になる。

```html
<input required>
<input required="">
<input required="required">
```

いずれも`required`属性が存在している。

## `"false"`と書いても偽にならない

ブール属性は、`"true"`と`"false"`という値で状態を切り替えるものではない。

```html
<input required="false">
```

`"false"`はブール属性の有効な値ではない。

さらに`required`属性自体は存在しているため、この入力欄は必須として扱われる。

偽にする場合は、属性を外す。

```html
<!-- 必須 -->
<input required>

<!-- 必須ではない -->
<input>
```

つまりブール属性では、

```text
属性がある
→ 真

属性がない
→ 偽
```

と考える。

## 列挙型属性は決められた値から選ぶ

列挙型属性は、その属性に定義されたキーワードを指定して状態を決める。

```html
<button type="button">ボタン</button>
<input type="email">
<div contenteditable="false">編集できない領域</div>
```

`type`や`contenteditable`では、指定した属性値に意味がある。

そのため、

```html
<div contenteditable="false">
```

は、属性が存在していても編集不可になる。

ブール属性のように、

> 属性が存在する = 真

とは考えない。

## `contenteditable`で違いを見る

`contenteditable`では、値によって状態が変わる。

| HTMLでの指定 | 状態 |
| --- | --- |
| `contenteditable="true"` | 編集できる |
| `contenteditable=""`または`contenteditable` | 編集できる状態になる |
| `contenteditable="false"` | 編集できない |
| `contenteditable="plaintext-only"` | 書式なしのテキストだけ編集できる |
| 属性を省略 | 親の編集可否を継承する |
| 無効な値 | 親の編集可否を継承する |

このように、列挙型属性では属性が存在するかだけを見るのではなく、**どの値が指定されているか**を確認する。

HTML属性とJavaScriptのDOMプロパティで使える値の違いは、[contenteditable属性とcontentEditableプロパティを区別する](../../../03_詳細/01_HTML・CSS/01_contenteditable属性とcontentEditableプロパティを区別する.md)で確認する。

## 省略時や不正な値の扱いも属性ごとに違う

列挙型属性では、

- 属性がない場合
- 値が空の場合
- 不正な値が指定された場合

にどう扱われるかも、属性ごとに決められている。

そのため、新しい属性を使うときは「列挙型だからこの動作になる」と一括して覚えるのではなく、その属性で有効な値と省略時の動作を確認する。

## 判断するときの見方

属性の状態を確認するときは、まずその属性がどちらなのかを見る。

```text
ブール属性
→ 属性が存在するかを見る

列挙型属性
→ どの値が指定されているかを見る
```

ブール属性なら、偽にするときは属性を外す。

列挙型属性なら、その属性で使える値と、省略・空・不正な値の場合の扱いを確認する。

## 一言でいうと

ブール属性は付けるか外すかで状態を表し、列挙型属性はその属性に定義された値によって状態を表す。
