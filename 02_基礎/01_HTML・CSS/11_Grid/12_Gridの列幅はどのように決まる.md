# Gridの列幅はどのように決まる？ ― `1fr`と`max-content`の計算の違い

Gridでは、親要素の幅を確認してから列幅を決め、その中に子要素を配置すると考えがちです。

しかし、`max-content` を指定すると、子要素の内容によって列幅が変わります。

では、ブラウザは列幅が決まっていない段階で、どうやって子要素の内容を調べているのでしょうか。

ここで重要なのは、**子要素の内容に必要な幅を調べることと、子要素の最終的な幅を決めることは別の処理**だという点です。

## ブラウザは何を基準に列幅を決めるのか

まず、Gridコンテナの幅や、子要素をどの列に配置するかを確認します。

その後、`grid-template-columns` に指定された値をもとに、列幅を計算します。

このとき、`1fr` と `max-content` では、列幅を決めるために参照する情報が異なります。

### `1fr` の場合
```css
.parent {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
}
```

`1fr` は、親の利用可能な空間を列に分配する指定です。

ブラウザは親の幅やgapを考慮して、各列にどれだけの空間を割り当てられるか計算します。

ただし、`1fr` には子要素の内容に由来する最小幅の制約もあるため、内容が大きければ列幅の計算に影響することがあります。

つまり、**親の空間を分配することが基本ですが、子の内容をまったく見ないわけではありません。**

### `max-content` の場合
```css
.parent {
  display: grid;
  grid-template-columns: repeat(3, max-content);
}
```

`max-content` は、子要素の内容に必要な幅を基準に列幅を決める指定です。

ブラウザは、各列に配置される子要素の内容を調べます。

文章であれば、通常の折り返しを行わずに表示したときに必要な幅を求めます。

同じ列に複数の子要素がある場合、その中で最も大きな幅を必要とするものが列幅の基準になります。

そのため、短い文章しかない列は狭く、長い文章がある列は広くなります。

**列幅が先に決まって文章が収まるのではなく、文章に必要な幅を調べた結果から列幅が決まる**という違いがあります。

## 列幅が決まった後、子要素はどうなるのか

ここまでの計算で決まったのは、子要素を配置するための列の幅です。

子要素自身の最終的な幅は、それとは別に決まります。

ここでは、`justify-items: normal` の場合で考えます。

通常の `div` のように、幅が `auto` で、伸長を妨げる条件がなければ、`normal` は `stretch` と同じように働きます。

その結果、子要素の箱は割り当てられた列の幅いっぱいに広がります。

つまり、`max-content` で内容の幅を基準に列を作った場合でも、**列幅を決める処理と、その列に合わせて子要素の箱を広げる処理は区別されます。**

## Gridの配置は「親 → 行・列 → 子」で考える

ここまでを見ると、`1fr` と `max-content` では、ブラウザが列幅を決めるために参照する情報が異なることが分かります。

しかし、これはGridの配置構造そのものが変わるという意味ではありません。

Gridの空間は、基本的に次の3段階で考えられます。

1. **親：配置するための空間を持つ**

   Gridコンテナが、行や列を作るための基準となります。
2. **行・列：子要素を配置する領域を作る**

   親の中に行や列が構成され、子要素をどの領域に置くかが決まります。
3. **子：割り当てられた領域に収まる**

   子要素は、その領域をもとに最終的な大きさや位置が決まります。

ここでいう「親 → 行・列 → 子」は、**ブラウザがすべての数値をこの順番で確定するという意味ではなく、Gridの空間を外側から内側へ理解するための考え方**です。

## 配置の構造と、計算の順序は別

`max-content` では、列幅を決めるために子要素の内容を先に調べます。

しかし、それは子要素自身の最終的な幅を先に決めて、その周囲にGridの列を作っているということではありません。

あくまで、列幅を求めるために子要素の内容を参照しています。

`1fr` でも、必要に応じて子要素の最小幅を参照します。

つまり、**Gridの空間を「親 → 行・列 → 子」と捉えることと、列幅の計算で子要素の内容を参照することは矛盾しません。**

実際のブラウザでは、指定された値や配置条件によって、必要な情報や計算の順序が異なり、サイズを再計算する場合もあります。

それでも、配置を理解するときは、まず親の空間があり、その中に行や列が構成され、子要素が割り当てられた領域に収まる、という関係を基本にできます。

## まとめ

Gridのサイズ計算は、指定によって参照する情報が変わります。

- `1fr` は、親の利用可能な空間を分配することが基本。
- `max-content` は、子要素の内容に必要な幅を基準にする。

しかし、どちらも親の中に行や列を作り、その領域に子要素を配置するという構造は共通しています。

**「親の空間 → 行・列の領域 → 子要素」という配置の関係を基本にして、幅が想定と異なるときに、その指定が何を参照して計算しているかを考える。**

このように配置の構造と計算の仕組みを分けて捉えると、`1fr` や `max-content` だけでなく、ほかのGridのサイズ指定も理解しやすくなります。
