# 04_構造依存から明示クラスへ切り替える

nth系や兄弟結合子は、DOM上の位置や関係そのものに意味があるときに使える。順番ではなく「大きいカード」「注目項目」などの役割を表したい場合は、明示クラスの方がHTML変更後も意図を追いやすい。

## 順番ではなく役割をクラスへ出す

```html
<article class="c-blog-card c-blog-card--large">カード1</article>
<article class="c-blog-card c-blog-card--large">カード2</article>
```

```css
.c-blog-card--large {
  grid-column: span 3;
}
```

この指定は「先頭から2枚」ではなく、「largeという差分を持つカード」を選ぶ。HTMLの順番が変わっても、クラスを付けたカードの役割は維持される。

## 明示クラスへ切り替える条件

次の場合は、順番セレクタよりmodifierなどの明示クラスを検討する。

- カード一覧に広告、見出し、空状態、バナーなどが混ざる可能性がある。
- 1枚目・2枚目という位置より、「大きいカード」「注目カード」という意味を示したい。
- CMSやJavaScript生成で並び順が変わる可能性がある。
- 後から別の人がHTML構造を変更する前提がある。
- 別の一覧でも同じ役割を再利用したい。

反対に、先頭2件だけ強調するなど、順番そのものが仕様であれば`:nth-child()`で表す方がHTMLへ同じクラスを繰り返さずに済む。

## 構造依存をゼロにすることが目的ではない

HTMLとCSSは、要素・属性・親子関係を使って接続する。構造への依存そのものをなくすのではなく、変更される可能性と変更時の影響を読める範囲へ抑える。

| 条件 | 選び方の候補 |
| --- | --- |
| 同じ項目が連続し、2個目以降だけ区切る | `A + A` |
| 直下には同種のカードだけが並び、先頭2枚を広げる | `:nth-child(-n + 2)` |
| 同じタグ種類の中の順番を使う | `:nth-of-type()` |
| 対象セレクタへ一致する兄弟内の順番を使う | `:nth-child(An+B of S)` |
| 順番に依存しない役割差分を示す | modifierなどの明示クラス |

どの方法も常に安全というわけではない。HTMLへ要素が追加された場合、並び替えられた場合、クラスを付け忘れた場合をそれぞれ考え、今回の変更条件に合うものを選ぶ。

## 実装後の確認

1. セレクタへ一致する要素をDevToolsで確認する。
2. 項目を1つ追加し、意図した要素へ指定が移るか確認する。
3. 見出しや広告など、混在し得る要素を仮に入れて確認する。
4. 順番が変わっても残すべき意味なら、明示クラスへ切り替える。
5. 部品の実装方法そのものを選び直す場合は[UIごとに固定と可変を分ける](../15_デザインパターンとCSS設計判断/01_UIごとに固定と可変を分ける.md)へ戻る。

## 一言でいうと

位置が仕様なら順番セレクタ、役割が仕様なら明示クラスを候補にする。将来の変更条件をHTMLで試してから決める。
