# 03_画像の読み込み前に表示領域を予約する

画像の寸法が分かる前に周囲の文章を配置すると、画像の読み込み後に高さが増え、後続の内容が動くことがある。画像の比率またはデザイン上の枠を先に伝え、読み込み前から場所を確保する。

## HTMLの寸法属性で画像比率を伝える

```html
<img
  class="card__image"
  src="./img/card.jpg"
  alt=""
  width="800"
  height="450"
>
```

```css
.card__image {
  display: block;
  width: 100%;
  height: auto;
}
```

`img`の`width` / `height`属性は寸法情報を持ち、レンダリングでは比率の計算にも使われる。CSSで表示幅を変えても、2値から得られる比率により、画像データを取得する前から高さを見積もれる。

属性値は実画像の寸法、または少なくとも縦横比と一致する値を使う。補完機能が入れた数値をそのまま信用せず、素材を確認する。

## デザイン上の枠はCSSで予約する

元画像の比率ではなく、正方形やカード固有の比率へ切り抜くなら、枠へ`aspect-ratio`を指定する。

```css
.card__media {
  aspect-ratio: 4 / 3;
  overflow: hidden;
}

.card__image {
  width: 100%;
  height: 100%;
  object-fit: cover;
}
```

| 予約したいもの | 主な方法 |
| --- | --- |
| 画像本来の比率 | `img`の`width` / `height`属性 |
| 選ばれる画像候補ごとの比率 | `picture`内の`source`と`img`の寸法属性 |
| デザイン上の表示枠 | CSSの`aspect-ratio`、必要なら高さ・最小高さ |

同じ比率を理由なくHTMLとCSSへ二重管理しない。HTMLは素材の寸法、CSSは素材と異なるデザイン上の枠、という役割で分ける。

## Attributes Styleと最終表示を分ける

DevToolsのStylesで寸法属性が`img[Attributes Style]`などとして見える場合がある。これはCSSファイルへ同じ宣言を書いたことを示さない。

- Styles: どの宣言や属性が候補になったか
- ComputedまたはLayout: 最終的に使われた幅と高さ
- HTML属性から得た比率: 読み込み前の領域予約へ使われ得る情報

属性由来の幅・高さに打ち消し線があっても、「属性が完全に無意味」とは限らない。最終寸法と比率予約を分けて確認する。

## 実際の移動を確認してから直す

1. どの要素がいつ動いたかを確認する。
2. 動く前後の画像枠の幅・高さを確認する。
3. HTMLの寸法属性、適用中の`aspect-ratio`、親の幅を確認する。
4. 選択画像が変わる場合は`currentSrc`と候補ごとの比率を確認する。
5. 修正後に同じ読み込み条件と画面幅で再確認する。

画像以外にも、Webフォント、後から挿入されるUI、広告やiframeなどが位置移動の原因になり得る。画像の寸法属性を足しただけでページ全体の原因を解決したと判断しない。現象の分け方は[読み込み後や幅変更で起きる位置ずれ](../07_ブラウザ挙動と表示のズレ/90_移行元/02_読み込み後や幅変更で起きる位置ずれ.md)へ戻る。

修正順は「カード枚数が多いから」だけで固定しない。実際の移動量、画面上部か、影響を受ける範囲、再現頻度を観測し、影響の大きい原因から直す。

## よくある混同

- `aspect-ratio`を書けば最大幅も決まる: 幅や上限は別に必要
- 2倍画像を使えば表示領域も2倍になる: 表示幅はHTML/CSS、候補選択は`srcset`
- `object-fit`で読み込み前の高さが決まる: 先に要素または親の箱が必要
- `width` / `height`属性を書けば画面上も固定寸法になる: CSSとレイアウトで最終寸法は変わる

## 初期認識と現在の判断

元の本文では、「HTMLの寸法属性とCSSを併用する」「CLSを抑えるために比率を先に予約する」を確度の高い認識としていた。この判断は維持する。

一方、「カード一覧、Grid、ヒーローの順で直す」という並びは固定ルールにしない。現在は、実際の移動量・画面上の位置・影響範囲を観測して優先順位を決める。
