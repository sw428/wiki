# 04_画像読み込み前後の表示領域を確認する

読み込み前の領域予約が効いているか確認するときは、HTML属性、CSS、最終的なレイアウト結果を分けて見る。

## Attributes Styleと最終表示を分ける

DevToolsのStylesで寸法属性が`img[Attributes Style]`などとして見える場合がある。これはCSSファイルへ同じ宣言を書いたことを示さない。

- Styles: どの宣言や属性が候補になったか
- ComputedまたはLayout: 最終的に使われた幅と高さ
- HTML属性から得た比率: 読み込み前の領域予約へ使われ得る情報

属性由来の幅・高さに打ち消し線があっても、「属性が完全に無意味」とは限らない。最終寸法と比率予約を分けて確認する。

## 実際の移動を確認してから直す

1. どの要素がいつ動いたかを確認する。
2. 動く前後の画像枠の幅・高さを確認する。
3. HTMLの寸法属性、適用中の`aspect-ratio`、親の幅を確認する。
4. 選択画像が変わる場合は`currentSrc`と候補ごとの比率を確認する。
5. 修正後に同じ読み込み条件と画面幅で再確認する。

画像以外にも、Webフォント、後から挿入されるUI、広告やiframeなどが位置移動の原因になり得る。画像の寸法属性を足しただけでページ全体の原因を解決したと判断しない。現象の分け方は[読み込み後や幅変更で起きる位置ずれ](../07_ブラウザ挙動と表示のズレ/02_読み込み後や幅変更で起きる位置ずれ.md)へ戻る。

修正順は「カード枚数が多いから」だけで固定しない。実際の移動量、画面上部か、影響を受ける範囲、再現頻度を観測し、影響の大きい原因から直す。

## よくある混同

- `aspect-ratio`を書けば最大幅も決まる: 幅や上限は別に必要
- 2倍画像を使えば表示領域も2倍になる: 表示幅はHTML/CSS、候補選択は`srcset`
- `object-fit`で読み込み前の高さが決まる: 先に要素または親の箱が必要
- `width` / `height`属性を書けば画面上も固定寸法になる: CSSとレイアウトで最終寸法は変わる
