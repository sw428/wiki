# 対象メールクライアントで表示を確認する

HTMLメールは、製品名だけで動作を決めつけず、実際に配信対象とする環境を決めて確認する。

## 対象環境を決める

GmailやOutlookという製品名だけで動作を固定せず、必要に応じて次の違いを含めて対象を決める。

- Web版、Windows版、Mac版、iOS版、Android版などのアプリ
- OSと版
- 組織や利用者の設定
- 配信サービスやテンプレートの制約
- PC幅とSP幅
- 画像表示・非表示
- 通常表示とダークモード

通常のWebページで成立した実装をそのまま流用せず、配信先で必要な環境を先に決める。

## 実装と確認を往復する

1. 対象メールクライアントと配信サービスの条件を確認する。
2. 公式の対応情報から、使用するHTML要素とCSS宣言の候補を絞る。
3. 見た目を固定する画像と、読ませるHTMLテキスト・リンクを分ける。
4. 画像非表示でも、最低限の内容と移動先が分かるか確認する。
5. PC/SP、画像表示・非表示、ダークモードで確認する。
6. 対象環境へ実際にテスト配信し、表示とリンク操作を確認する。

対応表は候補を絞る根拠になるが、送信処理によるHTMLの書き換え、利用者設定、実際の内容量まで含む最終表示はテスト配信で確認する。

画像非表示時の確認内容は[画像が表示されなくても内容と導線を残す](./04_画像が表示されなくても内容と導線を残す.md)で扱う。

## 優先する結果を決める

- 短いキャンペーンメールでは、見た目を固定する画像の比重を高くする場合がある。
- 重要通知、長文、取引情報、操作が必要なメールでは、HTMLテキストと明示的なリンクを優先する。
- 通常のWebページで使えるCSSでも、対象環境で成立しなければ別の方法を検討する。
- すべての環境を同じ見た目にすることより、対象環境で内容と操作が失われないことを優先する。

## 確認先

- [Gmail - CSS Support](https://developers.google.com/workspace/gmail/design/css)
- [Gmail Help - Turn images on or off](https://support.google.com/mail/answer/145919)
- [Microsoft Support - Block or unblock automatic picture downloads](https://support.microsoft.com/en-us/outlook/block-or-unblock-automatic-picture-downloads-in-classic-outlook-email-messages)
- [W3C WAI - Images of Text](https://www.w3.org/WAI/tutorials/images/textual/)

## 一言でいうと

HTMLメールは、対象環境を具体化し、対応表で候補を絞ってから実際のメールで確認する。
