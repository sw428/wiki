# 03_対象メールクライアントで表示を確認する

HTMLメールの実装前に、どのメールクライアント、OS、画面幅を対象にするか決める。すべての環境を暗記するのではなく、今回必要な対象を絞り、公式の対応表と実際の配信結果を確認する。

## 最初に対象環境を決める

少なくとも次を確認する。

- Gmail、Outlookなどの製品名
- Web版、Windows版、Mac版、iOS版、Android版などのアプリ
- 必要に応じた版や組織の管理設定
- 配信サービスやテンプレートの制約
- PC幅とSP幅
- 画像表示・非表示
- 通常表示とダークモード

同じ製品名でも、アプリと設定が違えば画像やCSSの扱いが同じとは限らない。

## 実装と確認の順番

1. 対象メールクライアントと配信サービスの条件を確認する。
2. 見た目を固定する画像と、読ませるHTMLテキスト・リンクを分ける。
3. 画像非表示でも最低限の内容と移動先が分かるか確認する。
4. 画像内文字が必要なら、周囲のHTMLとの重複を見て`alt`を決める。
5. PC/SP、画像表示・非表示、ダークモードで確認する。
6. 対象クライアントへ実際にテスト配信し、表示とリンク操作を確認する。

CSS対応表は実装候補を絞る根拠になるが、最終表示の保証ではない。送信処理によるHTML書き換え、利用者設定、画像取得、実際の内容量を含むため、テスト配信まで行う。

## 適用範囲と例外

- 見た目を強く固定したい短いキャンペーンメールでは、画像の比重を高くする場合がある。
- 重要通知、長文、取引情報、操作が必要なメールでは、HTMLテキストと明示的なリンクを優先する。
- 通常のWebページで使えるCSSでも、対象メールクライアントが未対応なら別の方法を検討する。
- すべてのクライアントを同じ見た目にすることより、対象環境で内容と操作が失われないことを優先する。

## 一言でいうと

対象環境を先に決め、公式の対応情報で候補を絞り、画像非表示を含む実際のテスト配信で確認する。
