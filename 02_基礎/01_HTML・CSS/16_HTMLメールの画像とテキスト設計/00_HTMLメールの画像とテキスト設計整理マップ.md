# HTMLメールの画像とテキスト設計整理マップ

Codex用。HTMLメールで見た目を画像へ任せる判断、画像非表示時の内容と`alt`、対象メールクライアントでの確認を分ける。人間向けの入口は[01_HTMLメールで画像と実テキストを分ける](./01_HTMLメールで画像と実テキストを分ける.md)。

## この章の入口

- 画像へ任せる部分とHTMLへ残す内容を分ける: [01_HTMLメールで画像と実テキストを分ける](./01_HTMLメールで画像と実テキストを分ける.md)
- 画像が表示されなくても内容と導線を残す: [02_画像非表示と代替テキストに備える](./02_画像非表示と代替テキストに備える.md)
- 対象クライアントを決めて実際に確認する: [03_対象メールクライアントで表示を確認する](./03_対象メールクライアントで表示を確認する.md)

- この章: HTMLメールという別媒体で、画像、実テキスト、リンク、クライアント差を扱う
- [HTML文書の骨格](../02_HTML文書の骨格/01_最小のHTML文書を作る.md): 通常のWebページで`head`と`body`を分ける基本形。CSS・JavaScriptの読み込みは[03](../02_HTML文書の骨格/03_CSSとJavaScriptを読み込む.md)

- [画像と背景](../10_画像と背景/00_画像と背景整理マップ.md): Webページで意味画像、装飾背景、画像形式、文字画像を選ぶ
- [メディア設計](../11_メディア設計/00_メディア設計整理マップ.md): Webページ上の画像・動画の表示寸法や候補を実装する

## 整理時に保つ関係

1. HTMLメールを通常のWebページと同じHTML/CSS対応範囲で考えない。
2. 画像中心の構成には見た目を固定しやすい利点があるが、本文・重要事項・操作導線まで画像だけへ焼き込む根拠にはしない。
3. 画像が読み込まれない状態でも、何の案内か、重要事項、移動先が分かるようにする。
4. `alt`は画像の目的と周囲のHTMLから決める。長い本文を画像化してよい理由にはしない。
5. GmailやOutlookという製品名だけで動作を固定せず、アプリ、OS、版、設定、配信サービスを含む対象環境を決めて確認する。
6. PC/SP、画像非表示、ダークモード、リンク操作を実際のメールで確認する。
