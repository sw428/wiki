# 04_要素の入れ子と親子関係を読む

## このページの役割

HTMLでは、要素の中に別の要素を入れて構造を作る。

このページでは、HTMLを見たときに、

```text
どの要素の中に
どの要素が入っているか
```

を読み取り、親・子・兄弟という関係を区別する。

## 要素の中に別の要素を入れられる

たとえば、次のHTMLがある。

```html
<section>
  <h2>料金</h2>
  <p>月額料金を紹介します。</p>
</section>
```

`section`要素の中に、`h2`要素と`p`要素が入っている。

構造だけを見ると、次のようになる。

```text
section
├─ h2
└─ p
```

このように、ある要素の中へ別の要素を入れる構造を入れ子として見ることができる。

ただし、どの要素でも自由に入れられるわけではない。このページでは入れ子の読み方に絞り、役割に合う要素と組み合わせは[意味からHTML要素を選ぶ](../04_HTMLの意味と構造/01_意味からHTML要素を選ぶ.md)で扱う。

## 外側が親、直接入っている要素が子

先ほどのHTMLでは、`section`の中へ`h2`と`p`が直接入っている。

```text
section  ← 親
├─ h2    ← 子
└─ p     ← 子
```

`section`は`h2`と`p`の親で、`h2`と`p`は`section`の子になる。

親・子は、要素の種類そのものではなく、**HTML内での位置関係**を表している。

## 同じ親を持つ要素は兄弟

`h2`と`p`は、どちらも`section`の直接の子。

```text
section
├─ h2
└─ p
```

このように同じ親を持つ要素同士は、兄弟として見ることができる。

```text
h2 と p
→ 兄弟
```

## 入れ子はさらに深くできる

要素の中の要素へ、さらに別の要素を入れることもできる。

```html
<section>
  <div>
    <p>お知らせです。</p>
  </div>
</section>
```

構造は次のようになる。

```text
section
└─ div
   └─ p
```

ここでは、`section`と`div`、`div`と`p`がそれぞれ直接の親子関係になる。

`p`は`section`の中には入っているが、間に`div`があるため、`section`と`p`は直接の親子関係ではない。

この場合、`section`から見た`p`は子ではなく、さらに内側にある要素として見る。

## 見た目ではなくHTMLの構造を見る

親・子・兄弟は、画面上でどこに表示されているかではなく、HTMLでどの要素の中に書かれているかによって決まる。

たとえばCSSによって表示位置を変えても、HTMLソースを書き換えなければ親子関係は変わらない。

見た目の位置と、HTML上の親子関係は分けて考える。

## インデントすると構造を読みやすい

入れ子になったHTMLは、階層に合わせてインデントすると関係を確認しやすい。

```html
<section>
  <div>
    <h2>料金</h2>
    <p>月額料金を紹介します。</p>
  </div>
</section>
```

これを構造として見ると、

```text
section
└─ div
   ├─ h2
   └─ p
```

となる。

HTMLを読むときは、

```text
開始タグを見る
↓
その中に何が入っているかを見る
↓
終了タグがどこにあるかを見る
```

と追うと、入れ子を確認しやすい。

## 一言でいうと

要素の中に別の要素を入れると階層ができ、直接外側にある要素が親、直接内側にある要素が子、同じ親を持つ要素同士が兄弟になる。
