# 06_通常フローと余白の関係を確認する

FlexやGridを指定していない箱も、配置規則がないわけではない。通常フローではblockやinlineの規則に従って並び、隣り合う縦marginが相殺する場合がある。

## 通常フローを基準にする

横書きの通常フローでは、block-levelの箱は主に縦へ並び、inline-levelの箱や文字は行の中を進む。親の利用可能幅の中で文字が折り返し、内容量から高さが結果として決まりやすい。

通常の内容を持つ箱は、まず`height: auto`のまま扱う。文字や子要素の量とpaddingなどから必要な高さを作り、高さ自体が要件になる場合だけ`height`や`min-height`を検討する。

FlexやGridは、通常フローとは異なるFlex/Gridのレイアウト文脈を親の中へ作る。指定を追加する前と後を比べると、どの規則で動いたかを切り分けやすい。

## 反復要素と別ブロックの余白を分ける

```css
.article-list {
  display: grid;
  gap: 16px;
}

.section {
  margin-block-end: 48px;
}
```

- 同じ一覧内の反復間隔: 親の `gap`
- 次の別ブロックまでの距離: ブロック間のmargin
- 枠線や背景と中身の距離: 親のpadding

親で一覧を束ねられない既存HTMLでは、隣接兄弟へmarginを付ける方法もある。

```css
.article + .article {
  margin-block-start: 16px;
}
```

各項目へ一律の `margin-bottom` を付けると、最後にも余白が残る。`gap` と外側marginを同じ目的で重ねない。

## marginの相殺は発生箇所を見る

通常フローのblock間では、次の縦marginが相殺することがある。

1. 隣接する兄弟の下marginと上margin
2. 親の上端・下端と、最初・最後の子のmargin
3. border、padding、inline内容、高さなどを持たない空のblock自身の上下margin

止め方は発生箇所で違う。

- 親子の相殺: 親のborderやpaddingで隣接を分ける、または親に `display: flow-root` を使う
- Flex/Grid内: Flex/Gridアイテムのmarginは互いに相殺しない
- `overflow` で新しいblock formatting contextを作る方法: clippingやscroll container化など別の副作用も確認する
- 隣接兄弟: borderやpaddingを別要素へ足すだけでなく、余白を片側へ集める、親をFlex/Gridにして `gap` を使うなど、構造に合う方法を選ぶ

「margin相殺を止める指定一覧」から選ぶのではなく、どの二つのmarginが接しているかをDevToolsで確認する。

## tableは表データの意味を保つ

行と列の対応に意味があるデータは、まずHTMLの `table` を使う。幅が苦しい場合も、すぐGrid/Flexへ置き換えず、横スクロール、折り返し、列幅、表示項目の設計を検討する。

`table-layout: fixed` は列幅計算を固定レイアウト方式へ変えるが、レスポンシブ対応そのものではない。内容の欠けやoverflowを別に確認する。

表に見えるだけで行列のデータ関係がないカード一覧なら、Flex/Gridを選べる。意味構造は[HTMLの意味と構造](../04_HTMLの意味と構造/01_意味からHTML要素を選ぶ.md)へ戻る。

## floatは文章の回り込みとして扱う

floatは箱を通常フローから外して左右へ寄せ、後続のインライン内容を側面へ回り込ませる。ページ全体やカード一覧の新規レイアウトにはFlex/Gridを優先し、floatは主に次で扱う。

- 文章を図版の横へ回り込ませる
- 既存のfloatレイアウトを保守する

floatした子を親の高さへ含めたい場合は、親の `display: flow-root` などでblock formatting contextを作る方法を検討する。`clear` は先行floatの横へ置かれないよう、後続blockを下へ送る指定である。

## 当時の認識と現在の判断を分ける

旧本文には「Gridは親が全権、子は駒」という高確度の初期認識があった。親がトラックと自動配置を決める入口としては有効だが、子も `grid-column`、最小サイズ、内容量などで結果へ関与する。

現在は次のように使う。

- 一覧全体の列・行・反復間隔は親から確認する
- 子自身の寸法や配置指定も確認する
- 見た目差と意味差を分け、同じ一覧ならまずHTML骨格を保つ
- 例外を加える前に、通常フローまたは親のレイアウト規則を特定する
