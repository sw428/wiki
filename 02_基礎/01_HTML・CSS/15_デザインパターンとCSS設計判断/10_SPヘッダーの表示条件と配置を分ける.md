# 10_SPヘッダーの表示条件と配置を分ける

SPヘッダーやハンバーガーボタンでは、「SPだけ存在する」という条件と、表示された後にどこへ置くかを分ける。表示制御クラスへ位置や余白を持たせない。

## 通常フローで置く基本形

```html
<div class="site-header__menu u-sp-only">
  <button class="hamburger-button" type="button" aria-label="メニューを開く">
    <span class="hamburger-button__line"></span>
    <span class="hamburger-button__line"></span>
    <span class="hamburger-button__line"></span>
  </button>
</div>
```

```css
.site-header__menu {
  display: flex;
  justify-content: flex-end;
}

.hamburger-button {
  display: grid;
  place-content: center;
  gap: 6px;
  width: 44px;
  height: 44px;
  padding: 0;
  border: 0;
  background: transparent;
}
```

- 存在条件: `u-sp-only`などの表示制御クラス
- 表示後の位置: `.site-header__menu`の通常フローやFlex
- 操作範囲: `.hamburger-button`自身の寸法・padding
- 線の配置: ボタン内部のGridと`gap`

## 重ねるか通常フローかを選ぶ

- 写真の上へ重ねるデザイン: 基準親を`position: relative`とし、メニューを絶対配置する。
- 写真より前のヘッダー行や色付き帯: HTML上でMVより前に置き、通常フローとFlexで配置する。
- SPだけ表示する: 位置とは別に表示条件を指定する。

SP版でヘッダー全体に横paddingを入れたくない場合は、`.site-header`全体ではなく、実際に余白が必要な内側の行へ持たせる。

表示制御の実装は[SPとPCで表示する要素を切り替える](../13_表示制御/01_SPとPCで表示する要素を切り替える.md)、開閉状態と`aria-expanded`は[JSのUI実装パターン](../../02_JS/03_UI実装パターン.md)へ分担する。

## 確認する条件

1. SPのどの幅で存在するか。
2. MVへ重ねるか、その前へ通常フローで置くか。
3. ボタン自身の操作範囲が確保されているか。
4. 開いたメニューの状態名と表示が同期するか。
5. キーボード操作、フォーカス、閉じる操作を確認したか。

## 一言でいうと

SPだけという条件、ヘッダー内の位置、ボタン内部、開閉状態を別々の担当へ分ける。
