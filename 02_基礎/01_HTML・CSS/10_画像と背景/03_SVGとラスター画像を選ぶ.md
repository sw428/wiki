# 03_SVGとラスター画像を選ぶ

SVGかPNGかを拡張子の好みだけで決めず、素材が図形か画素の集まりか、透過・画質・容量・更新方法をどうしたいかで選ぶ。

## ベクターとラスターを見分ける

| 種類 | 中身 | 向く素材 |
| --- | --- | --- |
| SVG | 線、図形、座標、塗りなどを記述する。ラスター画像を内部へ埋め込むこともできる | ロゴ、アイコン、線画、図形、アウトライン文字 |
| ラスター画像 | 幅と高さを持つ画素の集まり | 写真、質感、複雑な色変化 |

SVGは二次元のベクター表現に向くが、SVGという外枠の中へJPEGやPNGを入れることもできる。拡張子が `.svg` であることと、中の素材がすべてベクターであることは同じではない。

## ラスター形式を用途で選ぶ

| 形式 | 主な判断材料 |
| --- | --- |
| PNG | 透過や可逆圧縮が必要、ピクセル表現をそのまま保ちたい |
| JPEG | 透過不要の写真を一般的な制作・配信環境で扱う |
| WebP / AVIF | 対応環境と制作フローを確認し、写真などをより効率よく配信したい |

形式名だけで画質や容量は確定しない。書き出し品質、画像寸法、透過、素材の種類で結果が変わるため、実ファイルを同じ表示寸法で比較する。既存の配信基盤やCMSが変換・フォールバックを担当する場合は、その仕様も確認する。

## 写真をSVGにしてもベクターにはならない

写真は細かな色の変化を多数の画素で表す。SVGへ変換する方法はあるが、処理内容を分けて考える。

- 写真を輪郭抽出してベクター化する: 多数のpathと塗りが必要になり、見た目・容量・描画負荷が写真向け形式より適するとは限らない
- 写真をSVGの `image` 要素へ埋め込む: 中身はラスターのままで、拡大に強い図形へ変わらない

したがって「写真をSVGにすると必ず巨大になる」とは断定しない。写真には通常、写真向け圧縮形式を使う方が目的に合う、と判断する。

## 書き出す前の確認順

1. ロゴ・アイコン・線画か、写真・質感か。
2. 透過が必要か。
3. 拡大縮小時に線や文字の輪郭を保つ必要があるか。
4. HTML/CSSから色や内部部品を変更するか。
5. 表示寸法に対して画像データが過大でないか。
6. 対象ブラウザ、CMS、画像変換、納品条件が対応するか。
7. 実際の画質とファイルサイズを比較したか。

画像データのピクセル寸法、HTMLの寸法属性、画面上の表示寸法は別の値である。表示寸法と比率は[レスポンシブ画像設計の選び方](../12_レスポンシブ画像設計/01_レスポンシブ画像設計の選び方.md)、読み込み前の領域とCLSは[画像の読み込み前に表示領域を予約する](../11_メディアの表示枠と重ね配置/03_画像の読み込み前に表示領域を予約する.md)へ分ける。
