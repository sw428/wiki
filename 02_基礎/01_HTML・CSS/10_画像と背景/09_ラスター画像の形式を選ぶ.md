# 09_ラスター画像の形式を選ぶ

PNG・JPEG・WebP・AVIFは、透過、写真かどうか、画質、容量、配信環境を見て選ぶ。

ロゴ・アイコン・線画など、線や図形で表せる素材は、先に[SVGとラスター画像を選ぶ](./08_SVGとラスター画像を選ぶ.md)で素材の中身を確認する。ここでは、ラスター画像を使う場合の形式を選ぶ。

## ラスター形式を用途で選ぶ

| 形式 | 主な判断材料 |
| --- | --- |
| PNG | 透過や可逆圧縮が必要、ピクセル表現をそのまま保ちたい |
| JPEG | 透過不要の写真を一般的な制作・配信環境で扱う |
| WebP / AVIF | 対応環境と制作フローを確認し、写真などをより効率よく配信したい |

実際の素材では、次の条件から候補を選ぶ。

| 用途 | 形式の候補 | 選ぶ条件 |
| --- | --- | --- |
| メインビジュアルやスタッフの写真 | JPEG / WebP | 背景透過が不要な写真。表示時の画質と容量を比較する |
| 背景透過の人物切り抜き | PNG / WebP | 透過を保ち、人物の輪郭の見え方を確認する |
| 質感や細かな色変化のある装飾イラスト | PNG / WebP | 透過の必要性と、圧縮による見た目の変化を確認する |
| 文字や細線のある画面のスクリーンショット | PNG / 可逆WebP | 文字や細線を圧縮によって崩したくない |

この表は用途から選び始めるための候補であり、AVIFなどを除外するものではない。形式名だけで画質や容量は確定しないため、最後に実ファイルを比較する。

OGP画像として書き出す場合は、JPEGやPNGを候補にしつつ、掲載先が受け付ける形式・寸法・容量条件を別途確認する。Webページ内で表示できることだけでは、掲載先で使えるとは判断しない。

## WebPは透過と圧縮方法を分けて考える

WebPは、写真に使う非可逆圧縮と、画素情報を保つ可逆圧縮に対応し、どちらでも背景透過を扱える。

- 非可逆圧縮：画像情報の一部を省いて容量を減らす。写真では候補になるが、画質の設定によって細部の見え方が変わる。
- 可逆圧縮：画素情報を保って圧縮する。文字や細線を保ちたいスクリーンショットなどで候補になる。

そのため、「透過が必要ならPNG」「文字や細線があるならPNG」だけで固定せず、WebPの圧縮方法も確認する。詳しい対応は[Google公式のWebP解説](https://developers.google.com/speed/webp)で確認できる。

ただし、PNGやJPEGをWebPへ変換すれば必ず軽くなるわけではない。元画像の内容や書き出し設定によっては容量が増えるため、変換前後の見た目とファイルサイズを比較する。[Google公式FAQ](https://developers.google.com/speed/webp/faq)でも、変換後に容量が増える条件が説明されている。

## 書き出す前の確認順

1. **使用先の条件を確認する。** 対象ブラウザ、CMS、画像変換、納品条件が対応するかを確認する。配信基盤やCMSが変換・フォールバックを担当する場合は、その仕様も調べる。
2. **素材の中身を見る。** 線や図形をベクターで扱えるならSVG、写真や質感ならラスター画像を候補にする。拡大縮小時の輪郭や、HTML/CSSから内部の色・部品を変更する必要性も、リンク先のSVG側の判断と合わせて確認する。
3. **透過の必要性を確認する。** ラスター画像で透過が必要ならPNGやWebPなどを候補にし、透過に対応しないJPEGを外す。
4. **圧縮による変化を許容できるか決める。** 文字や細線を保ちたい場合はPNGや可逆WebP、透過不要の写真ではJPEGや非可逆WebPを比較する。透過が必要な写真でも、見た目の変化を許容できれば非可逆WebPを候補にできる。
5. **実際の表示寸法で画質と容量を確認する。** 画像データの寸法が過大でないかを確かめ、同じ表示寸法で文字・輪郭・写真の細部とファイルサイズを比較する。書き出し品質や画像寸法も結果に影響する。

画像データのピクセル寸法、HTMLの寸法属性、画面上の表示寸法は別の値である。表示寸法と比率は[レスポンシブ画像設計の選び方](../12_レスポンシブ画像設計/01_レスポンシブ画像設計の選び方.md)、読み込み前の領域とCLSは[画像の読み込み前に表示領域を予約する](../11_メディアの表示枠と重ね配置/03_画像の読み込み前に表示領域を予約する.md)へ分ける。

## このページのまとめ

- 形式は、素材の中身、使用先の対応、透過、圧縮による見た目の変化から選ぶ。
- WebPは透過と可逆・非可逆圧縮に対応する。透過の必要性と圧縮方法は別々に確認する。
- WebPへの変換だけで容量削減を保証せず、実際の表示寸法で画質と容量を比較する。
