# 05_文字を画像にする前に確認する

ロゴや固定された図版では、文字をアウトライン化したSVGが必要な場合がある。一方、見出し、本文、一覧、リンク、ボタンをページごと画像へまとめると、文書構造・読み上げ・操作・更新・折り返しをHTMLで扱いにくくなる。

## ページの役割はHTMLへ残す

- HTMLへ残す: 見出し階層、本文、一覧、リンク先、ボタンやフォームの操作
- SVGや画像を候補にする: ロゴ、アイコン、固定図版、見た目そのものが内容になる表現
- CSSへ任せる: 背景、余白、単純な線や形、レスポンシブ配置

SVGを `img` で読み込んだ場合、内部に文字の形が見えても、HTMLの見出し・段落・一覧・リンクとしてページ構造へ置いたことにはならない。変更、折り返し、読み上げ、選択、操作が必要な内容はHTMLを優先する。

## LPかどうかだけで決めない

LPにも広告からの流入を主に受けるもの、検索や継続的な情報提供を重視するものがある。「LPなら文字を画像にしてよい」「LPならSEOを考えなくてよい」と一括りにしない。

| 観点 | HTMLテキスト・要素を優先する理由 | 画像・SVGを候補にする場面 |
| --- | --- | --- |
| 意味・検索 | 文書構造と周辺文脈をDOMへ残せる | ロゴや固定図版など、見た目自体が内容の一部 |
| アクセシビリティ | 文字拡大、色変更、読み上げへ対応しやすい | 同等の内容をaltや周囲のHTMLで伝えられる固定表現 |
| 操作 | リンク、ボタン、フォームを通常のHTML要素として持てる | 操作を持たない装飾・図版 |
| レスポンシブ | 折り返しや部分的な配置変更がしやすい | 常に一体で拡大縮小する部品 |
| 更新・保守 | 文言や構造を部分的に直せる | 更新頻度が低く、表現を固定したい部品 |
| 案件仕様 | 意味と操作を保ちながら実装方法を選べる | 指定フォントや支給アウトライン素材を使う部品 |

案件仕様でアウトラインSVGを使う場合も、条件は対象部品へ適用する。ページ全体を一枚の画像へまとめる根拠にはしない。

## アウトライン文字のaltを決める

文字をアウトライン化すると、見た目は文字でもHTMLテキストではなく図形になる。画像の用途と、周囲に同じ内容があるかを確認する。

- 画像内にしか文字がない: `alt` で同等の内容を伝える
- 同じ文字が周囲のHTMLにある: 画像は装飾として `alt=""` を検討し、読み上げの重複を避ける
- 画像がリンクやボタンの内容である: 見た目ではなく操作の目的や移動先を伝える
- 複雑な図版で短いaltだけでは足りない: 周囲の本文や説明への参照も用意する

```html
<h2 class="course-heading">
  <img
    src="./img/course-heading.svg"
    alt="仲間と頑張る グループ講習"
    width="320"
    height="80"
  >
</h2>
```

この例では、画像の代替テキストが見出し内容を伝える。別に同じ見出しテキストを置く設計なら、画像側を装飾として扱い `alt=""` にする。

## 判断順

1. この文字はロゴ・固定図版か、見出し・本文・操作名か。
2. HTMLの実テキストで実装できない条件は何か。
3. 画像がなくても同じ意味と操作が伝わるか。
4. 周囲のHTMLとaltが同じ内容を二重に読ませないか。
5. 文字拡大、ズーム、狭い幅、ダークモードなどで読めるか。
6. 文言変更時にどの素材とHTMLを直すか明確か。

意味に合う要素は[HTMLの意味と構造](../04_HTMLの意味と構造/01_意味からHTML要素を選ぶ.md)、図版の囲み方は[図版と段落](../04_HTMLの意味と構造/04_図版と段落のHTML.md)へ戻る。
