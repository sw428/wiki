# 箱の大きさが予想と違うときの確認順

箱が思ったより広い、あるいは狭いときに、paddingやmarginを手当たり次第に変更しても原因が見つからないことがあります。**どの寸法が違っているかを確かめてから、変更するCSSを選びます。**

## 1. まず調べたい要素を選ぶ

DevToolsのElementsで、見た目の場所ではなく**対象の要素そのもの**を選びます。Computedで使われている`display`・`width`・`height`を確認し、予想した箱と一致しているかを見ます。

指定したはずのCSSが効いていない場合は、Stylesへ戻って、どの宣言が適用されたか確認します。これは[適用されたCSSを確認する](../06_CSSカスケードとDevToolsの見方/01_DevToolsで適用されたCSSを確認する.md)で扱う問題です。

## 2. どの領域が広いのか確認する

次にBox Modelを見ます。`content`が広いのか、左右の`padding`や`border`を含めた結果が広いのかを分けます。

たとえば`content`が360pxで左右のpaddingが20pxずつなら、borderのない箱の横幅は400pxです。**実際の外幅とcontent幅を同じ数値として読まない**ことが大切です。

CSSファイルに幅が書かれていなくても実寸が表示される理由は、[書いた値と実際の寸法](./07_CSSに書いた値と実際の寸法を分ける.md)で確認できます。`display: inline`の箱などは通常ブロックと同じように幅を決めないため、箱の種類も合わせて見ます。

## 3. その寸法は何を基準に決まるか

`width`・`height`が`auto`か、`%`か、固定した長さかを調べます。

- `auto`の場合：親の利用可能な幅や内容などから決まる条件を見る。
- `%`の場合：その割合の**基準となる箱**を見る。高さの割合は、基準の高さを決定できるかも関わる。
- 長さを指定している場合：`box-sizing`を含め、どの領域を指定した値なのかを見る。

`%`の基準は[パーセント指定と包含ブロック](./08_パーセント指定と包含ブロック.md)で、DOMの親と寸法の基準になる箱が異なる場合は[DOM上の親と包含ブロック](./10_DOM上の親と包含ブロックを区別する.md)で確認します。

## 4. 最小・最大サイズと親の配置規則を確認する

`min-width`・`max-width`・`min-height`・`max-height`が、最終的な大きさを制限していないかを見ます。

さらにFlexやGridの子であれば、子自身の指定だけでなく、**親がどのような配置の枠を作っているか**を確認します。例えばGridの列が広くなっているのに子のpaddingだけを変更しても、求める解決にはならない場合があります。

## どこで調べるか迷ったら

| 見つかった違い | 次に調べること |
| --- | --- |
| CSSの指定が効いていない | Stylesで採用された宣言を見る |
| `width`より外幅が大きい | `box-sizing`、padding、borderを見る |
| 子の幅指定がなくても広い | 親幅・Flex/Gridの整列・内容を見る |
| `%`の値が予想と違う | 包含ブロックの寸法を見る |
| ある幅以上に伸びない／縮まない | `min-*`・`max-*`を見る |

**一度に変更するCSSは一つだけ。** どの箱のどの領域が違うかを確かめてから、必要な指定に進みます。
