# 箱の大きさが予想と違うときの確認順

箱の大きさが予想と違うときは、見た目から原因を決めず、DevToolsで順に確認する。

## 1. 対象と使われた宣言を確定する

DevToolsで、見た目ではなく調べたい要素そのものを選ぶ。

まずComputedで実際に使われた `display`、`width`、`height` を見る。どの宣言が採用されたか分からない場合は、Stylesへ戻り、[適用されたCSSと上書き](../06_CSSカスケードとDevToolsの見方/01_DevToolsで適用されたCSSを確認する.md)を確認する。

## 2. 箱の種類と実際の寸法を見る

`display` を確認し、その箱に `width` や `height` がどう適用されるかを見る。inlineの箱は、通常フローのblockと同じ感覚では読めない。

次にボックスモデル図で `content / padding / border / margin` を分ける。CSSに書いた `width` と外側の寸法が違うときは、[書いた値と実際の寸法](./07_CSSに書いた値と実際の寸法を分ける.md)を照合する。

## 3. 値の基準と制限を確認する

`width` や `height` が `auto`、`%`、長さのどれかを確認する。

`%` なら、継承ではなく、[包含ブロックを基準にした割合計算](./08_パーセント指定と包含ブロック.md)として見る。高さの場合は、その基準となる高さを割合計算できる状態かも確認する。

続いて `min-width`、`max-width`、`min-height`、`max-height` によって、最終的な使用サイズが制限されていないかを見る。

## 4. 親側のレイアウト規則を確認する

DOM上の親と包含ブロックが同じとは限らないため、どの箱が基準を作っているかを[DOM上の親と包含ブロックを区別する](./10_DOM上の親と包含ブロックを区別する.md)で確かめる。

FlexやGridの中にある場合は、子の指定だけでなく親の配置指定も確認する。ここまでの各段階で観測した値をつなぐと、「余白が広いように見える」といった印象から原因を決めつけずに切り分けられる。
