# 01_HTMLメールで画像と実テキストを分ける

HTMLメールは、複雑な見た目を画像で固定する利点がある。一方で、重要な文言、日時、価格、注意事項、操作導線は、画像が表示されなくてもHTMLテキストとリンクで伝わるようにする。

## Webページと同じ前提にしない

メールクライアントは、通常のブラウザーと同じ範囲のHTML/CSSを必ず処理するわけではない。たとえばGmailは多くのCSSセレクタ・プロパティ・メディアクエリを扱うが、未対応のものは無視される場合がある。

通常のWebページで成立した実装をそのまま流用せず、配信先で必要な環境を先に決める。

## 画像中心の構成が選ばれる理由

- 複雑な文字装飾やレイアウトを、1つの見た目として固定しやすい。
- キャンペーン部分全体を、1つのリンク面として扱いやすい。
- クライアント間でCSSの解釈が違っても、画像内の見た目は比較的保ちやすい。

これは、見た目を固定したい部分へ画像を使う理由である。本文やCTAまで画像だけにする理由ではない。

## 画像とHTMLの分担

| 内容 | 優先する形 |
| --- | --- |
| 件名、重要なお知らせ、日時、価格、注意事項 | HTMLテキスト |
| 申し込み・詳細ページへの導線 | 目的が分かるHTMLリンク |
| キャンペーンのキービジュアル、複雑な装飾 | 画像を候補にする |
| 画像内にしかない短い文言 | 同等の内容を`alt`で補う |
| HTMLですでに同じ内容を伝えている装飾画像 | `alt=""` |

最初に、メール1通を画像非表示で見た場合も、何の案内か、重要な条件は何か、どこから操作するかが分かるか確認する。

## 分けて実装する例

```html
<p>期間限定キャンペーンのお知らせ</p>
<p>申込期限は2026年9月30日です。</p>

<a href="https://example.com/campaign">
  <img
    src="https://example.com/images/campaign.jpg"
    alt="キャンペーン詳細を見る"
    width="600"
    height="300"
  />
</a>
```

重要事項は画像の外へ実テキストで置く。画像リンクの`alt`は色や形ではなく、リンクの目的が分かる内容にする。画像の目的別の判断は[画像非表示と代替テキストに備える](./02_画像非表示と代替テキストに備える.md)で扱う。

## 一言でいうと

見た目を固定したい部分には画像を使えるが、読ませる内容と操作導線はHTMLにも残す。
