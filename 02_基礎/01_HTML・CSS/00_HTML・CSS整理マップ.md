### 章フォルダと01・03の扱い

- HTML・CSSの各番号は一つのカテゴリを表し、同名の章フォルダにまとめる。01〜15の移行が完了した。章フォルダ内は内容を整理するときに作成し、空フォルダだけを先に作る運用にはしない。
- 章フォルダ内は `00_<カテゴリ名>整理マップ.md` をCodex用の内部ルーター、`01_...md` を人間向けの入口、`02_...md` 以降を個別テーマとする。トップのこのマップからは人間向け入口と内部マップを区別してつなぐ。

## 認知アプローチ（知識に至る手順）

「正解を暗記する」のではなく、次の順で認知を積み上げる。

1. 現象を言語化する
「何がズレたか」「どこで破綻したか」を見た目で書き出す。
2. 基準箱を特定する
font box / [行ボックス](../../05_参照/行ボックス.md) / border box / flex item box のどれが効いているか切り分ける。
3. 時系列で分解する
[DOM](../../05_参照/DOM.md) などの要素ツリー + CSSルール → cascade / inheritance → box tree → Layout → Paint → 画像確定 → 再Layout のどこで変化したかを見る。[CSSOM](../../05_参照/CSSOM.md) はCSSルールを参照・操作する仕組みとして分ける（[状態変化](../../05_参照/状態変化.md)）。
4. 変更対象を分離する
核（コンポーネント）と文脈（レイアウト）を分け、触ってよい層だけ触る。
5. 仮説を1つだけ試す
`width/height`、`aspect-ratio`、`min-width: 0` などを1つずつ当てて差分確認する。
6. 判断理由を残す
「なぜ採用したか」を短く残し、次回の再学習コストを下げる。

## ベース原理セット（2026-05-02 追記）

対話ログで再現性が高かった判断軸を、入口に固定する。

1. 見た目ではなく役割で決める
   要素名・クラス名・構造は「何をしているか」で決める。
2. 外側と内側を分ける
   外側（配置）と内側（整列/見え方）を混ぜない。
3. 構造と余白を分ける  
   `grid/flex` は構造、`margin/gap/padding` は間隔として扱う。
4. 親を先に疑う  
   子がズレたときは、まず親の `display` / 幅 / 既存余白を確認する。
5. 全体ルールを先に作る  
   先に全体、あとで例外（例: `grid-column: 1 / -1`）の順で作る。
6. 表示は要素でなく条件で切る  
   `span` / `div` より「SP/PCどちらで存在させるか」を先に決める。
7. 知っていると使えるを分ける  
   用語理解より「条件付きで再現できるか」を到達基準にする。
