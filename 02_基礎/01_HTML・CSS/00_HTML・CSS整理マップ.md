## HTML・CSS固有の反映ルール

### 人間向け実装例

- 一般知識記事では、主題の理解に不要な案件名・業種・人物種別へ依存するクラス名を避け、`card`、`card-list`、`button`など役割が分かる一般的な名前を使う。具体的な文脈が判断材料になる記事や、案件固有のケース記録では一般化しない
- CSSの責務を説明するときは、その宣言が直接決める値と、親のレイアウトや他の指定から決まる値を分ける。「幅を決める」のように、実際には別の仕組みが決めている責務を持たせない

### カンプからレスポンシブ挙動を判断する

SP・PCなど離れた基準幅のカンプ寸法だけで、実装方法を断定しない。基準幅で同じ寸法になっていても、比率に連動する値、一定に保つ値、ブレークポイントで切り替える値では、中間幅の結果が異なる。

カンプからレスポンシブ実装を判断するときは、中間幅で値をどう変化させたいかを確認し、比率連動・固定値・ブレークポイント切替を区別する。画像、レイアウト、余白、文字サイズなど、基準幅の間で変化する対象に共通して適用する。

## 章フォルダと01・03の扱い

- HTML・CSSの各番号は一つのカテゴリを表し、同名の章フォルダにまとめる。章フォルダは本文が必要になったときに作り、空フォルダだけを先に作らない。
- 章フォルダ内は `00_<カテゴリ名>整理マップ.md` をCodex用の内部ルーター、`01_...md` を人間向けのカテゴリ概要、`02_...md` 以降を個別テーマとする。01ではカテゴリの目的、選択肢と判断軸、各ページの簡易概要、次に読む先を示し、詳しい説明を一つ目の個別テーマとして抱え込まない。トップのこのマップからは人間向け入口と内部マップを区別してつなぐ。
- 現在の01が最初の個別テーマを兼ねる既存章は、一括改稿せず、その章を扱うときに人間向け概要と02以降へ順次分ける。
- 箱・画像・レンダリングのように複数カテゴリへ関わる内容は、主な疑問に答える章へ正本を置き、ほかの章からリンクする。フォルダ化を理由に本文を重複させない。
- [スニペット](./スニペット/00_スニペット整理.md)は採用した入力支援の正本、imgは本文用画像として分ける。知識を読む順には数えない。
- 01_前提知識には、05に対応する[widthが箱ごとに決まる流れ](../../01_前提知識/01_HTML・CSS/05_ボックスとdisplay/01_widthが箱ごとに決まる流れ.md)がある。ほかの章も、既存本文や短い参照カードでは説明を追えない前提だけを必要時に抽出する。
- 03_詳細の[inset記事](../../03_詳細/01_HTML・CSS/03_insetで広がる条件を調べる.md)は、現在11の[画像の上に文字や部品を重ねる](./11_メディアの表示枠と重ね配置/03_画像の上に文字や部品を重ねる.md)が主な戻り先。分野名と主な基礎への相互リンクをそろえ、番号合わせのために本文を複製しない。
- 16は通常のWebページと同じ実装章ではなく、HTMLメール固有の媒体条件を扱う章として保持する。メール制作の必要時に選んで読み、Web制作の必修の最終章とは扱わない。

### 配置が近くても混ぜない説明

- 01〜04は、要素を読む入口・ファイルの骨格・属性の操作・意味から要素を選ぶ判断を分担する。
- 05は箱の種類と寸法・余白、08は行や文字の整列、09は親子配置。同じ「中央」「余白」でも対象が異なる。
- 06は宣言の採用と値の確認、14は主にnth系や兄弟要素の選び方。14をCSSの全入門として扱わない。
- 10は意味画像・装飾背景・形式、11は読み込み前の領域・重ね方・動画、12はレスポンシブ画像、15は部品の用途からの判断。別記事としての役割を残す。
- 07は表示の工程と観測、04は意味構造との区別。共通のDOM・box treeという用語だけでは重複と判断しない。
- 13は「表示するか」と「表示時の並び」を分ける。16はメール固有の媒体条件であり、Web制作の必修の最終章ではない。
