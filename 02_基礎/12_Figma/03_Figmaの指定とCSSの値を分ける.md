# 03_Figmaの指定とCSSの値を分ける

Figmaで確認した指定は、CSSで採用する値と同じとは限らない。元の指定を先に残し、変換や表示調整は実装側の判断として分ける。

## どの段階の値かを分ける

| 段階 | 確認すること |
| --- | --- |
| Figmaの指定 | 選択した文字レイヤーやスタイルに、どの値・単位・Autoが指定されているか |
| JSONの値 | 書き出しツールが、その情報のうち何をどの形式で残したか |
| CSSの値 | 元の指定を踏まえ、ブラウザでは何を指定したか |
| ブラウザの結果 | 指定したCSSで、実際にどう表示されたか |

JSONはカンプの全情報ではない。書き出す対象や形式によって、直接指定された値が含まれなかったり、表現が変わったりする。JSONに値が見当たらないときは「Figmaでも未指定」と決めず、元のレイヤーやスタイルを確認する。

## 行の高さで見る

たとえばFigmaで、文字サイズが18px、行の高さが27pxと明示されていたとする。元の指定は`27px`である。

CSSでは、文字サイズに行の高さを連動させたいなら、単位なしの倍率を検討する。

```css
.text {
  font-size: 18px;
  line-height: 1.5;
}
```

この文字サイズでは`18px × 1.5 = 27px`相当になる。ただし、`1.5`は文字サイズに連動する倍率で、固定の`27px`とは意味が違う。行の高さを固定する判断なら、CSSも`line-height: 27px`にする。どちらを採用しても、Figmaの元指定が`1.5`だったことにはしない。

Figmaで行の高さがAutoなら、元の指定はAutoのまま記録する。CSSでは`line-height: normal`から試せるが、Figmaとブラウザの見た目が必ず一致するわけではない。

フォントファイルには、基準線より上の高さを表すアセンダー、下の深さを表すディセンダーなどのフォントメトリクスがある。使うフォントファイルが違えば、Autoや`normal`で得られる行の高さや、行の中での文字の見え方も変わり得る。固定の`27px`を指定した場合、その値自体は変わらないが、文字の見え方は変わり得る。

表示を見てCSSを調整しても、Figmaの元指定まで変更しない。行の高さの計算や`normal`の挙動は[文字の行間と高さを確認する](../01_HTML・CSS/08_インラインと行の仕組み/01_文字の行間と高さを確認する.md)で確認する。

## このページのまとめ

- Figmaの指定、JSONの値、CSSの値、ブラウザの結果を分ける。
- JSONにない値を、Figmaでも未指定だったと決めない。
- CSSで倍率への変換や表示調整をしても、Figmaの元指定は書き換えない。
