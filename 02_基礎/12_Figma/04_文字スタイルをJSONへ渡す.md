# 04_文字スタイルをJSONへ渡す

Figmaの文字指定をGPTへ渡してCSSを考えるときは、スタイル名を見分ける目印にし、元の指定値はFigmaと書き出したJSONで確認する。プラグインがCSSを決めるわけではない。

## 今回の受け渡し方

```text
Figmaの文字レイヤー
→ Text Styles Generatorで文字スタイルを整理
→ Design TokensでJSONを書き出す
→ GPTへ元の指定とJSONを渡す
→ CSSを決め、ブラウザでカンプと比較する
```

Design TokensのJSONは、スタイル化されていない文字レイヤーを含め、カンプの全指定を必ず収集するものではない。まず対象の文字レイヤーと生成されたスタイルが一致するか確認し、JSONにない値を未指定と決めない。元の指定、JSON、CSS、表示結果の区別は[Figmaの指定とCSSの値を分ける](./03_Figmaの指定とCSSの値を分ける.md)で扱う。

## 名前には基本値と必要な差分を入れる

今回の命名では、文字サイズと太さを基本にし、通常と違う行の高さや文字間隔が明示されている場合だけ差分を足す。Figmaの文字スタイルに用途名が登録されており、基本値だけでは区別できないときは、元の固有名を一般名へ置き換えて最後に付ける。

```text
20-bold                 → 20px・Bold・行の高さはAuto
20-bold-lh20-heading    → 20px・Bold・行の高さ20px・登録した用途名heading
20-regular-lh30-5       → 20px・Regular・行の高さ30.5pxを明示
30-bold-ls5             → 30px・Bold・文字間隔に別の指定がある
```

`lh`は`line-height`（行の高さ）、`ls`は`letter-spacing`（文字間隔）の略。`30-5`は、名前の中で小数点のある`30.5`を表す書き方。ここでの`heading`はフォントファミリー名ではなく、Figmaの文字スタイルに登録した用途名を一般化した例。

この運用では、行の高さがAutoなら名前に`lh`を付けない。Figmaで20pxと明示されている場合だけ`lh20`を付け、Autoと区別する。`lh20`はCSSに必ず`line-height: 20px`と書く指示ではなく、Figmaの元指定を見分ける目印。CSSで固定値を保つか倍率へ変えるかは実装時に判断する。

`ls5`も含め、名前だけから単位やFigmaの全指定を復元しない。値と単位は元の文字スタイルで確認する。ブラウザで行の高さを調整しても、Figmaのスタイル名を実装後の値に合わせて変更しない。

複数ページで文字指定を共有する場合、CSSのクラス名は`.t-20-bold`のように`t-`を付ける。Figmaの全スタイルを機械的にクラス化するわけではない。用途名クラスとの役割分担は[CSS設計のタイポグラフィ用クラス](../07_設計/CSS設計/01_BEMとクラス命名.md#タイポグラフィ用クラスの扱い)で扱う。

## JSONでAutoが残ったか確認する

今回共有されたOriginal形式の書き出し例には、次の情報があった。

```json
{
  "lineHeight": {
    "value": "normal",
    "type": "string",
    "unit": "auto"
  }
}
```

この運用では当面`Original (deprecated)`で書き出し、対象スタイルのJSONに`unit: "auto"`が残るか確認する。`value: "normal"`だけを見て、Figmaの元指定がAutoだったと推定しない。形式やプラグインの版が変われば、同じ確認をやり直す。Originalは旧形式であり、どの環境でもAutoを保持するという一般則にはしない。

## CSSは元指定と分けて決める

FigmaでAutoなら、CSSでは`line-height: normal`から試し、ブラウザでカンプと比較する。合わない場合はCSS側を調整するが、Figmaの元指定はAutoのまま残す。

Figmaで行の高さが20pxと明示されていたなら、元の指定は`20px`である。文字サイズも20pxのとき、CSSの`line-height: 1`は同じ20px相当になるが、固定長を倍率へ変える実装判断である。固定値を保つなら`line-height: 20px`を使う。どちらを採用しても、Figmaの指定が`1`だったことにはしない。
