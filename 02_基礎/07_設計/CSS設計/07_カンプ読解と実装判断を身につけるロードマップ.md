# カンプ読解と実装判断を身につけるロードマップ

カンプから意図したレスポンシブ挙動を読めない、読めてもCSSの候補を選べない、実装した結果を確かめられない、といった問題は、止まっている工程ごとに扱う。まず一つの不足を特定し、何を習得するか、何ができれば次へ進めるかを決める。

同時に、習得途中でも仕事の結果と質を確保するため、資料・仕様の明示・レビューなどの補完策を用意する。個人の習得と制作の品質確保を並行して進め、判断結果を共通規約へ戻す。

両者の仕事の起点と、判断がずれる構造は[カンプ設計とCSS設計で仕事の認識がずれる理由](./06_カンプ設計とCSS設計で仕事の認識がずれる理由.md)で扱う。このページでは、そこから不足工程を見つけ、習得と実務の確認をどう進めるかを整理する。

## 問題が止まっている工程を特定する

画像設計を題材にすると、必要な判断を次のように分けられる。すべてを最初から学び直すのではなく、実際に説明や判断が止まった工程から扱う。

| 工程 | 確認すること | 不足している場合に取り組むこと |
| --- | --- | --- |
| 観察 | 元画像、マスク、表示領域の寸法・比率を区別して説明できるか | 選択するレイヤーと測る対象をそろえ、元画像と表示範囲を比較する |
| 読解 | 情報と規約から想定する挙動を絞り、根拠と未確定部分を分けられるか | 候補を支持する情報と反例を照合し、追加の仕様が必要な条件を見つける |
| CSS設計 | 読み取った挙動を実現する構造・指定・条件を選べるか | 必要なCSSの仕組みと、指定が成立する条件を確かめる |
| 検証 | 基準幅と中間幅で、意図した挙動になっているか確認できるか | 幅変更時の高さ、見える範囲、周囲の配置を予想と比較する |
| 共有 | 同じ情報から、他の担当者も同じ表示規則を選べるか | 判断の根拠、表現の意味、判断範囲、追加確認の条件を規約へ残す |

例えば観察できていても、マスクをどの挙動の根拠として読むか分からなければ、次の課題は読解である。CSSの書き方を何度も練習するだけで、その読解が身についたとは判断できない。

反対に、どの挙動が必要かは説明できていても、そのCSSを組めなければ、実装方法と成立条件を学ぶ必要がある。問題のある工程と、練習する工程を合わせる。

## 一つの対象で、判断をつなぐところまで練習する

最初は、元画像と表示枠の関係を正しく説明する。画像レイヤー全体の寸法を、マスクで見えている範囲の寸法として扱っていないか確認する。

次に、[比率固定と高さ固定の幅変更後の違い](../../01_HTML・CSS/12_レスポンシブ画像設計/05_高さで表示領域を作る.md#比率で作る場合との違い)を理解する。基準幅だけでは同じに見えても、幅を変えたときの高さと切り抜き範囲が違うことを、資料や最小例を使って確認する。

そこからカンプを読み、どの情報がどの候補を支持するかを説明する。指定されたこと、自分が推定したこと、まだ決まっていないことを分け、読めない条件には追加の仕様が必要だと判断する。

候補を選んだ後は、その挙動をCSSで実現して幅を変える。予想と結果が違ったら、観察・読解・CSS設計・検証のどこへ戻るかを決める。

次へ進む目安は、資料やWikiを参照しながらでも、対象、根拠、選んだ方法、確認結果、残る不確実さを説明できることである。すべてを暗記してから実務へ進む条件にはしない。確認を受けながら進められる範囲と、自分で判断できる範囲を区別する。

## 習得期間中の品質を、別の仕組みで確保する

一度に完成した能力を求めず、原因となる判断を一つずつ習得する。ただし、習得途中であることだけを理由に、仕事の要求を曖昧にしてよいわけではない。

必要な水準に達するまでの期間は、個人やチームで不足を補う方法を決める。どの判断に補完が必要か、その判断が未確認のまま納品へ進まないように、担当と確認箇所を明確にする。

| 個人が進めること | 個人・チームで用意する補完策 |
| --- | --- |
| 測定対象や判断方法を一つずつ習得する | 判断に必要な資料、表示意図、仕様を用意する |
| 根拠を説明しながら、具体例で判断を試す | 重要な読解と実装方針を、経験者と照合する |
| 間違った理由を特定し、次の判断を修正する | 不一致を納品前に見つける確認工程を設ける |
| 支援を受けずに判断できる範囲を増やす | 到達を確認した範囲から、補助やレビューの量を調整する |

補完策は、本人が何を学ぶかを曖昧にしたまま、誰かが毎回代わりに直す仕組みにしない。直した根拠を本人へ返し、その後の判断が変わったかを確認する。

## 到達条件を、実際にできることとして置く

「頑張る」「次は気をつける」「改善する」という宣言だけでは、どの工程が変わったか判断できない。今回の対象に必要な、観察できる到達条件を選ぶ。

画像設計なら、例えば次のように確認する。

- 元画像と表示領域を分け、どこがマスクで隠れているか説明できる。
- 比率固定と高さ固定で、幅変更後の高さと見える範囲がどう違うか予想できる。
- カンプの情報と共有規約から、候補を選んだ根拠を説明できる。
- 推定できる部分と、追加の仕様確認が必要な部分を分けられる。
- 選んだCSSが意図した挙動を実現するか、中間幅で確かめられる。
- 別の例でも適用条件を確認し、同じ判断を使えるか説明できる。

到達条件は、すべての制作に一律の試験として課すものにはしない。今回止まった工程を確認するために必要なものを使い、練習・支援下での実務・支援を減らした実務の結果を区別して見る。

## 個人の判断を、共通規約へ育てる

最初から完成した規約を作る必要はない。仮の規約を使って判断を照合し、伝わらなかった表現、読み違えた条件、判断できなかった情報を修正する。

例えば高さを保つ意図なら、その意図をどの表示枠・寸法・注記で伝えるかをそろえる。比率を保つ場合との違いを、デザイナーもコーダーも同じ基準で読めるか確かめる。静止カンプから決められない挙動は、必要な追加仕様として明示する。

規約に残す対象は、意図した挙動、それを伝える表現、実装者が判断する範囲、追加確認が必要な条件、表示結果の確認方法である。同じ挙動を実現するCSSが複数ある場合は、規約として固定する必要がある部分と、実装側に選択を残す部分を分ける。

規約があると、情報は渡されていたのか、読解が不足していたのかを調べやすくなる。個人が判断できるようになると、規約の曖昧さや不足も見つけやすくなる。個人の習得と規約の更新を並行して進める。

規約を作った時点で完了とせず、必要な担当者が同じ条件で意図した挙動を選び、実装と確認へつなげられるかを確かめる。その結果を次の担当者にも使える判断基準として残す。

## このページのまとめ

- 止まっている工程を特定し、その工程に必要な判断を一つずつ習得する。
- 資料を使って対象・根拠・方法・結果を説明できることを含め、必要な到達条件を置く。
- 個人の習得と仕事の品質確保を並行して進め、習得期間中は資料やレビューで不足を補う。
- 改善の宣言ではなく、実際に判断や成果物が変わったかを確認する。
- 規約の仮整備と習得を並行し、双方の判断結果から共通基準を更新する。
