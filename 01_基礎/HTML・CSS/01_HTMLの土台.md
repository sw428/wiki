# 01_HTMLの土台

## 目的

- `display` やボックスモデルへ入る前に、HTMLが何としてブラウザに読まれるかを整理する。
- 「タグ」「要素」「属性」「テキストノード」「DOM」を混同せずに読める状態にする。

## まず持つ地図

HTMLは、見た目を直接作る文字列ではなく、ブラウザに解析されてDOMツリーになる元データ。

```txt
書いたHTML
-> ブラウザが解析する
-> 必要に応じて補正される
-> DOMツリーになる
-> JSやCSSの処理対象になる
```

この時点で、HTMLに書いた文字はそのまま一枚の文章として扱われるのではなく、要素ノードやテキストノードなどに分かれる。

## DOMは複数種類のノードからなるツリー

HTMLソースをブラウザが解析すると、DOMツリーが作られる。DOMには要素とテキストだけでなく、`Document`、`DocumentType`、コメントなどのノードもある。

```txt
HTMLソース
-> HTMLパーサーが解析する
-> DOMツリー
   ├─ Document
   ├─ DocumentType
   ├─ Element
   ├─ Text
   └─ Comment など
```

最初から全種類を覚える必要はなく、普段は要素ノードとテキストノードを中心に見る。

たとえば次のHTML。

```html
<p>こんにちは <strong>重要</strong></p>
```

DOM上では、ざっくり次のように見る。

```txt
p要素ノード
├─ テキストノード「こんにちは 」
└─ strong要素ノード
   └─ テキストノード「重要」
```

`こんにちは`の後ろに書いた空白も、テキストノードの内容に含まれる。タグ間や文字の前後に書いた空白も、DOM上ではテキストノードになる場合がある。実際の表示時に空白がどうまとめられるかは、[05_インラインと行の仕組み](./05_インラインと行の仕組み.md)で扱う。

## タグと要素は同じではない

タグは、HTML内で要素を作るための印。

```html
<p>こんにちは</p>
```

この場合は次のように分ける。

```txt
<p>        -> 開始タグ
こんにちは -> 内容
</p>       -> 終了タグ

全体      -> p要素
```

正確には「タグを書く」というより、タグで要素を作る。

## HTMLは見た目ではなく構造・意味を持たせる

HTMLの基本的な責務は、コンテンツの構造と意味を表すこと。見た目の調整は基本的にCSSが担当する。

たとえば、`h1` は「大きくしたい文字」ではなく、ページの主見出しという意味を持つ。

```html
<h1>ページの主見出し</h1>
```

大きさを変えたい場合はCSS側で指定する。

```css
h1 {
  font-size: 32px;
}
```

## 属性は開始タグに書く

属性は、要素に追加情報・機能・参照先を与えるもの。

```html
<img src="image.jpg" alt="説明">
<a href="#section">移動</a>
<input type="text">
```

この場合、

- `src`: 画像ファイルの場所
- `alt`: 代替テキスト
- `href`: リンク先
- `type`: 入力欄の種類

という追加情報を要素に与えている。

属性の詳しい分類や `id` / `class` / `role` / `data-*` の使い分けは、[03_HTML属性の基本](./03_HTML属性の基本.md) で扱う。

## 置換要素は通常の要素内部とは別の内容で表示される

置換要素は、要素内部を通常の子要素やテキストとして描画する代わりに、画像・動画・フォーム部品などの内容で表示される要素。

代表例:

- `img`
- `input`
- `video`
- `iframe`

たとえば次のHTML。

```html
<img src="photo.jpg" alt="">
```

これはHTMLの中に画像そのものが書かれているのではなく、`src` で指定した画像ファイルに置き換わって表示される。

そのため、画像はテキストとは違い、置換要素として扱う。

```css
img {
  width: 100%;
  height: auto;
}
```

## void要素は終了タグを持たない

void要素は、終了タグを持たない要素。

代表例:

- `img`
- `input`
- `br`
- `hr`
- `meta`
- `link`

基本は次のように書く。

```html
<img src="image.jpg" alt="">
<input type="text">
```

次のようには書かない。

```html
<img></img>
<input></input>
```

`img` は void要素でもあり、置換要素でもある。
ただし、この2つは別の分類。

- void要素: 終了タグを持たない
- 置換要素: 通常の要素内部とは別の内容で表示される

| 要素 | void要素 | 置換要素 |
|---|---|---|
| `img` | はい | はい |
| `br` | はい | いいえ |
| `video` | いいえ | はい |
| `div` | いいえ | いいえ |

## ブラウザが暗黙で要素を補うことがある

書いたHTMLと、ブラウザが作ったDOMは完全に同じとは限らない。

たとえば、`tbody` を書いていない場合でも、ブラウザがDOM上で補うことがある。

```html
<table>
  <tr>
    <td>内容</td>
  </tr>
</table>
```

DevTools上では、次のように見えることがある。

```html
<table>
  <tbody>
    <tr>
      <td>内容</td>
    </tr>
  </tbody>
</table>
```

つまり、次の順で考える。

```txt
書いたHTML
-> ブラウザが解析する
-> 必要に応じて補正する
-> DOMになる
```

## DOMはJavaScriptから操作できる構造

DOMは、HTMLドキュメントの構造とコンテンツをブラウザが扱える形にしたデータ表現。

JavaScriptの次の処理は、HTML文字列を直接見ているのではない。

```js
document.querySelector(".button");
```

ブラウザが作ったDOMツリーから、条件に合う要素を探している。

## 認識

- HTMLは、ブラウザに解析されてDOMツリーになる。
- DOMツリーには、要素ノードやテキストノードなど複数種類のノードがある。
- タグは要素を作るための印で、要素そのものとは少し違う。
- 属性は、要素へ追加情報・機能・参照先を与える。
- HTMLは見た目ではなく、構造と意味を担当する。
- 置換要素とvoid要素は別の分類として見る。

## 一言でいうと

HTMLは見た目を作る前に、ブラウザがDOMとして読むための構造と意味を作る。
