# 06_画像と背景

## 目的

- `<img>` と `background-image` の役割差を混同せずに判断できるようにする。
- 「背景が見えない」時に、画像URLだけを疑わず、まず描画先の `box` 面積を確認できるようにする。
- `SVG` とラスター画像の形式選定を、再利用しやすい判断軸で固定する。
- 外部SVGをファイルとして使う範囲と、SVGを分ける制御単位を判断できるようにする。
- `mask-image` を、背景画像や `object-fit` と混同せずに使えるようにする。

## 最初に押さえる結論

1. `<img>` はHTML文書内に画像要素として配置する。意味のある画像なら内容を `alt` で伝え、装飾だけなら `alt=""` とする。
2. `background-image` は既にある box への背景描画で、画像自体は box を作らない。
3. 背景が見えない時は、まず「背景を描く box に面積があるか」を確認する。
4. `mask-image` は画像を表示する指定ではなく、要素の見える形を抜く指定。

## 背景画像と描画先のbox

- `background-image` は、既存要素の `box` に背景として描画される。
- 背景画像は DOM に意味を追加しない。
- 背景画像は要素サイズ（面積）を作らない。
- そのため、要素側に `width` / `height` / `padding` / テキストなどの面積がないと見えにくい。

| 観点 | `<img>` | `background-image` |
|---|---|---|
| 役割 | HTML文書内に画像を配置する | 既存要素の背景を描画する |
| DOM上の扱い | 要素として存在する | 新しい要素は増えない |
| 意味の伝達 | 内容に応じて `alt` を使い分ける | 画像自体の代替テキストは持たない |
| box面積への寄与 | 自身が描画対象になる | 背景画像だけでは面積を作らない |

## 背景が見えない時の確認順

1. 背景を描く要素に面積があるか（`width` / `height` / `padding` / テキスト）
2. `display: inline` の空要素になっていないか
3. 画像URLが正しいか
4. `background-size` / `background-position` が意図どおりか

補足:
- `display: block` / `inline-block` は面積を作りやすいが、高さ指定も内容もないと高さ `0` になり得る。

## 装飾背景の描画ルール

| プロパティ | 意味 |
|---|---|
| `background-size: cover` | 要素全体を覆う（比率維持、切り取りあり） |
| `background-size: contain` | 要素内に収める（比率維持、余白あり） |
| `background-position` | 切り取り時にどこを見せるかを決める |

## `mask-image` と背景画像の違い

`background-image` は「何を背景として塗るか」を決める。
`mask-image` は「要素のどの部分を見せるか」を決める。

見た目はどちらも画像を使うので混ざりやすいが、責務は逆に近い。

| 観点 | `background-image` | `mask-image` |
|---|---|---|
| 主な役割 | 背景として画像を表示する | 画像の透明度や形で見える範囲を決める |
| 表示内容・色 | 背景画像側が持つ | マスク対象となる要素側が持つ |
| よく使う場面 | 装飾背景、模様、写真背景 | 単色アイコン、形抜き、フェード表現 |
| 意味 | DOM上の意味は追加しない | DOM上の意味は追加しない |
| 注意点 | box に面積がないと見えない | マスク対象となる要素に面積と表示内容が必要 |

### 単色アイコンで使う例

アイコン画像の「形」だけを借りて、色はCSSで変えたい時に使う。

```css
.icon-mask {
  display: inline-block;
  width: 24px;
  height: 24px;
  background-color: currentColor;
  mask-image: url("../img/icon-arrow.svg");
  mask-repeat: no-repeat;
  mask-position: center;
  mask-size: contain;
}
```

この場合、`icon-arrow.svg` は表示する画像そのものというより、見える形を決める型として使っている。
実際に見える色は `background-color: currentColor` 側が持つ。

### 背景をグラデーションで消す例

端だけ少しずつ透明にしたい時は、マスクにグラデーションを使う。

```css
.fade-image {
  background-image: url("../img/photo.jpg");
  background-size: cover;
  background-position: center;
  mask-image: linear-gradient(to bottom, #000 70%, transparent 100%);
}
```

この例では、写真は `background-image` が表示している。
`mask-image` は、その背景を含む要素全体の見える範囲を下方向へ薄く消している。

### 何をしているか

- `mask-image`: どの画像・グラデーションをマスクとして使うかを決める。
- `mask-size`: マスク画像を要素内でどう収めるかを決める。
- `mask-position`: マスク画像をどこに置くかを決める。
- `mask-repeat`: マスクを繰り返すかを決める。
- `background-color`: 単色アイコンでは、マスク越しに見える色になる。

`mask-image` は「画像を縮小する」「画像を枠に収める」指定ではない。
画像の収まりは `object-fit` / `background-size`、見える形の制御は `mask-image` と分ける。

### 使う判断基準

- 単色アイコンの色をCSSで変えたい: `background-color` + `mask-image` が候補。
- SVGやPNGの形だけ借りたい: `mask-image` が候補。
- 画像の端をフェードさせたい: グラデーションの `mask-image` が候補。
- 写真や商品画像をそのまま見せたい: `img` / `background-image` を優先する。
- 写真を枠に収めたい: `object-fit` / `aspect-ratio` / `background-size` を優先する。
- 意味のあるアイコンなら、マスクだけで終わらせず、テキストや `aria-label` など意味の伝達も別に考える。

## `<img>` と `background-image` の選択基準

- 意味画像として読ませる必要があるなら、原則として `<img>` を使う。
- 見た目の演出・装飾なら `background-image` が候補になる。
- 装飾目的でも、文書内の画像要素として配置する必要がある場合は `<img alt="">` を使える。
- 同じ見た目でも、意味の有無で選択を分ける。

補足:
- `object-fit` / `aspect-ratio` を使った「枠の安定化」は 10 側で扱う。

仕様確認先: [HTML Standard - Requirements for providing text to act as an alternative for images](https://html.spec.whatwg.org/multipage/images.html#alt)

## `SVG` とラスター画像の使い分け

| 形式 | 向くもの |
|---|---|
| `SVG` | ロゴ、アイコン、線画、ベクター図形、アウトライン化された文字 |
| `PNG` | 透過や可逆圧縮が必要なラスター素材、ピクセル表現を固定したい素材 |
| `JPEG` | 透過を必要としない写真 |
| `WebP` / `AVIF` | 写真やラスター画像を、対応環境と制作フローに合わせて効率よく配信したい場合 |

写真では通常、写真向けの圧縮形式を優先し、`PNG` の常用は避ける。形式名だけで決めず、透過の要否、画質、ファイルサイズ、対応環境、更新フローを合わせて判断する。

### 写真をSVGにしない理由

写真は、細かな色の変化を多数のピクセルで表すラスター画像である。SVGへ書き出せることと、写真がベクター画像へ変わることは分けて考える。

- 写真を輪郭抽出してベクター化する:
  - 多数のパスと塗りが必要になり、写真向けの圧縮形式よりデータ量と描画処理が増えやすい。
- 写真をSVGの `image` 要素へ埋め込む:
  - 中身はPNGやJPEGなどのラスター画像のままであり、写真部分が拡大に強いベクターへ変わるわけではない。
  - SVGという外枠を付けても、写真をSVGにする利点はほとんど増えない。

したがって「写真をSVGにすると必ず巨大になる」と断定するのではなく、写真には通常SVGの利点がなく、写真向けの圧縮形式の方が用途に合うと判断する。

仕様確認先: [SVG 2 - Embedded Content](https://svgwg.org/svg2-draft/embedded.html)

### 書き出したSVGを外部ファイルで使う

Figmaなどから書き出したSVGを `<img>` で使う場合は、SVG文書全体を `.svg` ファイルとして保存し、HTMLから参照する。

```html
<img
  src="./img/catch-copy.svg"
  alt="画像が伝える内容"
  width="320"
  height="80"
>
```

SVG内部に多数の `path` があっても、個数を理由にHTMLへ1つずつ転記しない。書き出されたSVGには、描画を担当する `path` 以外にも、次の情報が含まれ得る。

- 外側の `svg` と `viewBox`
- `defs` 内のグラデーションや再利用定義
- `clipPath`、`mask`、`filter`
- `g` のグループ化や座標変換
- `id` を使った参照関係

`path` だけを抜き出すと、座標系、表示範囲、色、マスク、参照関係が失われる可能性がある。内部要素をCSSやJavaScriptから直接操作する必要がないなら、書き出し済みSVGを外部画像としてそのまま使う方が境界を保ちやすい。

`<img src="icon.svg">` として読み込んだ外部SVGは、通常、HTML側のCSSからSVG内部の個々の `path` を直接指定して変更しない。SVG内部の色をHTML側の状態に合わせて変える、個別のパスを操作するなど、内部DOMへ触る必要がある場合はインラインSVGを検討する。その場合も `path` だけでなく、必要な `svg`、`viewBox`、定義、参照関係をまとめて扱う。

SVGを1ファイルへまとめる範囲は、パス数ではなく、デザイン上のまとまりと表示上の制御単位で決める。

- 背景、アイコン、アウトライン文字などが常に同じ位置関係で表示され、個別に変更する必要がない固定デザインパーツ: 1つのSVGを候補にする。
- ロゴ、キャッチコピー、バッジなど、位置・大きさ・表示条件を別々に調整する素材: 別SVGを候補にする。
- レスポンシブ対応で一部だけ位置・大きさ・表示条件を変える場合: その制御単位で分割を検討する。

仕様確認先:

- [SVG 2 - Document Structure](https://svgwg.org/svg2-draft/struct.html)
- [SVG 2 - Coordinate Systems and `viewBox`](https://svgwg.org/svg2-draft/coords.html#ViewBoxAttribute)

## 判断基準

1. これは意味画像か、装飾背景か
2. 装飾背景なら、背景を描く box に面積があるか
3. ベクター素材かラスター素材かを見分け、用途に合う画像形式を選べているか
4. 外部SVGとして使うなら、書き出したSVG文書全体をファイルとして参照できるか
5. SVGを分ける場合は、位置・大きさ・表示条件を独立して変える単位か
6. 形だけ借りて色や見える範囲をCSSで制御したいなら、`mask-image` を検討する
7. 実装安定化（`object-fit` / `aspect-ratio` / CLS）は 10 で設計する

## 一言でいうと

意味のある画像は原則 `<img>`、装飾は `background-image` が候補。
ベクター素材は `SVG`、写真などは用途に合ったラスター形式を使う。
SVGはパス数ではなく制御単位でまとめ、形だけを利用したい場合は `mask-image` を検討する。
背景が見えない時は、まず描画先の `box` に面積があるか確認する。
