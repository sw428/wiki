# 14_HTMLメールの画像とテキスト設計

## 結論

HTMLメールは「画像だけで作ればよい」のではない。複雑な見た目を画像で固定する利点はあるが、重要な文言・リンク・案内はHTMLテキストでも伝わるようにする。

## Webページと同じ前提にしない理由

メールクライアントは、ブラウザ上の通常ページと同じ範囲のHTML/CSSを必ず処理するわけではない。

Gmailはメール内CSSとして多くのセレクタ、プロパティ、メディアクエリを扱える一方、未対応のプロパティやセレクタは無視される場合がある。対象クライアントごとに実装条件を確認し、通常のWebページで成立したCSSがそのまま再現されるとは考えない。

## 画像中心の構成が選ばれる理由

- 複雑な文字装飾やレイアウトを1つの見た目として固定しやすい。
- キャンペーン部分全体を1つのリンク面として扱いやすい。
- クライアント間でCSS解釈が違っても、画像自体の見た目は比較的保ちやすい。

ただし、これは画像だけにする根拠ではなく、見た目を固定したい部分へ画像を使う理由である。

## 画像だけへ依存しない理由

### 外部画像が表示されない場合がある

- Gmailでは、ユーザーが外部画像を表示前に確認する設定を選べる。疑わしい送信元やメッセージでは自動表示されない場合もある。
- Outlookにも、外部画像の自動ダウンロードを止める設定や、既定でブロックする環境がある。

画像へ本文やCTAをすべて焼き込むと、画像が読み込まれない時に内容と導線が同時に失われる。

### 画像内文字は利用者が調整しにくい

画像内の文字は、通常のHTMLテキストより文字サイズ、色、行間などを利用者側で調整しにくい。ロゴなど見た目自体が重要な場合を除き、読ませる文章は実テキストを優先する。

`alt` は画像が表示されない場合や支援技術への代替になるが、長い本文を画像化してよい理由にはしない。

## 実務での分担

| 内容 | 優先する形 |
|---|---|
| 件名、重要なお知らせ、日時、価格、注意事項 | HTMLテキスト |
| 申し込み・詳細ページへの導線 | 意味の分かるHTMLリンク |
| キャンペーンのキービジュアル、複雑な装飾 | 画像を候補にする |
| 画像内にしかない短い文言 | 同等の内容を `alt` で補う |
| HTML側ですでに伝えている装飾画像 | `alt=""` |

```html
<p>期間限定キャンペーンのお知らせ</p>
<a href="https://example.com/campaign">
  <img
    src="https://example.com/images/campaign.jpg"
    alt="キャンペーン詳細を見る"
    width="600"
    height="300"
  >
</a>
```

画像リンクの `alt` は、画像の色や形ではなく、リンクの目的が分かる内容にする。重要事項は画像の外にもHTMLテキストで置く。

## 判断手順

1. 配信対象のメールクライアントと必要な表示環境を確認する。
2. 画像が非表示でも、最低限の内容とリンク先が分かるか確認する。
3. 見た目を固定する部分と、読ませる・操作させる部分を分ける。
4. 画像内文字が必要なら、周囲のHTMLとの重複を見て `alt` を決める。
5. PC/SP、画像非表示、ダークモード、対象クライアントで実際に確認する。

## 適用範囲と例外

- 見た目を強く固定したい短いキャンペーンメールでは、画像の比重を高くする場合がある。
- 重要通知、長文、取引情報、操作が必要なメールでは、HTMLテキストと明示的なリンクを優先する。
- 実装方法は配信サービスのテンプレート制約と対象クライアントに従い、通常のWebページ用CSSをそのまま流用しない。
