# 03_コンポーネントと責務

## 位置づけ（CSS設計）

このファイルは、コンポーネント本体、配置ラッパー、ページ文脈の責務を分けるための採用方針をまとめるノート。

- 基礎概念: `01_基礎`
- 設計: `01_基礎/設計/CSS設計`
- 検証元: `02_検証`

## このノートで固定すること

- 共通コンポーネントとして扱う範囲
- Element名とラッパーの判断
- 親Blockと子Blockの責務分離
- コンポーネント本体と配置ラッパーの分離
- ページ側で上書きしてよいもの / しないもの
- Modifierへ分ける判断
- 再利用へ昇格する判断

## 基本思想

コンポーネントは「見た目と構造の核」を持つ。

一方で、どこに置くか、周囲とどれだけ離すか、何列で並べるかは、使う場所の文脈が決める。

```txt
コンポーネント本体 = 部品としての同一性
配置ラッパー       = 親の中での置き場所
ページ文脈         = 周囲との距離、並び、例外調整
```

## Element名の判断

Element名は、単に「中にある」という理由では付けない。その要素が担当する役割を表す名前を使用する。

| 名前 | 用途 |
|---|---|
| `__body` | 画像やアイコンなどと対になる、部品の本体領域 |
| `__content` | 見出しや導入部分と分かれた主要内容 |
| `__media` | 画像や動画をまとめる領域 |
| `__header` | Block内部の見出しや導入部分 |
| `__list` | 一覧を構成する要素 |
| `__actions` | ボタンやリンクなどの操作領域 |

### `body` の例

```html
<article class="staff-card">
  <div class="staff-card__media">
    <img class="staff-card__image" src="" alt="">
  </div>

  <div class="staff-card__body">
    <h3 class="staff-card__name">山田 太郎</h3>
    <p class="staff-card__text">紹介文</p>
  </div>
</article>
```

### `content` の例

```html
<section class="staff">
  <header class="staff__header">
    <h2 class="staff__title">スタッフ紹介</h2>
  </header>

  <div class="staff__content">
    <ul class="staff__list">
      ...
    </ul>
  </div>
</section>
```

ラッパーに役割がない場合は、Elementやラッパー自体を追加しない。

## 共通コンポーネントへの昇格

初回から推測で `c-` を付けない。まず `.staff-card` のような通常のBlockとして実装する。

複数箇所で次の内容を共有すると確認できた場合に、共通コンポーネントへ昇格させる。

- HTML構造
- 見た目
- 振る舞い
- 変更理由

見た目が偶然似ているだけの場合は、無理に共通化しない。ページ固有という理由だけで `p-` を付ける運用もしない。

## 親Blockと子Blockの責務

- 親Blockは、直下の子要素や子Block同士の配置を決める。
- 子Blockは、自分自身の内部構造と見た目を管理する。
- カード一覧の列数や間隔は一覧側、カード内部の見た目はカード側で扱う。

```css
.staff__list {
  display: grid;
  gap: 40px 20px;
}

.staff-card {
  /* カード内部の配置と見た目 */
}
```

変更時に「どのクラスを触ればよいか」を予測できることを重視する。

## 配置ラッパーと部品本体

親の中で特定の位置に置きたいだけなら、親側のElementで配置を持つ。
部品本体は独立Blockとして残す。

```html
<div class="blog-articles__newsletter">
  <div class="newsletter">
    <div class="newsletter__inner">...</div>
  </div>
</div>
```

- `blog-articles__newsletter`: 親セクション内での置き場所
- `newsletter`: 独立コンポーネント本体

ラッパーを減らしたい場合は、BEMのMixとして1要素に両方のクラスを付ける。

```html
<div class="newsletter blog-articles__newsletter">
  <div class="newsletter__inner">...</div>
</div>
```

このときも、どちらが配置でどちらが部品本体かを説明できる状態にする。

## コンポーネント上書きの境界

### 上書きしてよいもの（ページ側責務）

- `margin`
- `gap`
- `display`（文脈に応じた使い方）
- 位置・周囲余白
- レイアウト都合の並び

### 上書きしないもの（核）

- 形（丸/角など）
- 色の意味（ブランド色・状態色）
- 構造
- `border-radius` など部品固有の骨格

### サイズ差分の扱い

サイズ違いは都度上書きせず、Modifierで吸収する。

```css
.button--sm {}
.button--lg {}
```

## 再利用へ昇格する判断

- 初回や共有が未確認の段階: 通常のBlockとして扱う
- 複数箇所で構造・見た目・振る舞い・変更理由を共有する: `c-` への昇格候補
- 見た目が同じでも意味や変更理由が違う: 別Blockとして扱う

完全統一ではなく「8割共通、2割ページ調整」が通常運用。

迷ったら次の順で判断する。

1. 核（部品の同一性）なら触らない
2. 配置（文脈差）ならページ側で調整
3. サイズ差はModifierに分離する

## 構造依存セレクタとModifier

一覧内にカードだけが並ぶ前提なら、`:nth-child()` のような構造依存指定で済むことがある。

ただし、広告、見出し、空状態、バナーなどが一覧内に混ざる可能性がある場合は、構造依存セレクタよりModifierを検討する。

```css
.c-blog-card--large {}
```

これは特定Blog実装の正本ではなく、CSS設計側に残す一般判断に限定する。

## まとめ

- 部品の同一性はコンポーネント本体が持つ
- 置き場所と周囲余白は親やページ文脈が持つ
- 再利用が明確になってから `c-` へ昇格する
- 構造依存が不安定になる場合はModifierで意図を明示する
