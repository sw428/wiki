# 05_CSS設計の実装手順

## 位置づけ（CSS設計）

このファイルは、CSS設計を実装へ落とすときの作業順と見返しポイントを固定するノート。

知識の説明ではなく、再現可能な進め方として読む。

## 制作順序（実務編）

1. セクション構造を確定する
   - ヘッダー / メイン / フッター
   - 各Section / Block
2. BlockとElement名を決める
   - 意味ベースで命名する
   - DOMの深さをそのまま名前にしない
3. レイアウト責務を分ける
   - 並び、配置、gapは親や `l-` 側で扱う
   - 部品本体は見た目と内部構造に集中させる
4. 余白ルールを先に固定する
   - 反復間隔は `gap`
   - Block間は `margin-bottom`
   - 箱の内側は `padding`
5. ダミー画像とテキストで骨組みを先に完成させる
6. 見た目をBlock側へ実装する
   - 色
   - 線
   - タイポグラフィ
   - 角丸など部品固有の形
7. 状態差分をModifierで追加する
8. 影響範囲を確認しながら調整する
   - 詳細度競争を避ける
   - 強いセレクタで核を上書きし続けない

## SPファースト後に見返す

最初から未来の変更をすべて予測して分けようとしない。

まずSPを最後まで作り、PCへ拡張し、完成したCSSを見返してから境界を直す。

見返すポイント:

- 同じ幅指定が何度も出ている
- 同じボタン構造が複数出ている
- 外側余白を子Block自身が持っている
- 1クラスに背景、幅、配置、文字装飾が集中している
- 名前を見ても責務が分からない

この反復を、設計経験として扱う。

## ダミー画像の扱い

画像が未確定でも、比率や表示枠が必要な場合はダミー画像で先に骨組みを作ってよい。

```html
<img class="hero__img" src="img/dummy.jpg" alt="">
```

```css
.hero__img {
  width: 100%;
  aspect-ratio: 16 / 9;
  object-fit: cover;
  background-color: #eee;
}
```

これはCSS設計の責務分離そのものではなく、実装を前へ進めるための仮組み手順として扱う。
画像そのものの仕組みは、[10_メディア設計](../../HTML・CSS/10_メディア設計（img・video・object-fit・aspect-ratio）.md) を参照する。

## 実装時の確認順

1. これは「核」か「文脈」かを先に決める
   - 核ならコンポーネント本体
   - 文脈なら親Block / ページ側
2. 問題は「構造」か「余白」かを分ける
   - `grid` / `flex` と `margin` / `gap` / `padding` を混ぜない
3. 子より親を先に確認する
   - 子調整前に、親の `display` / 幅 / 既存余白を確認する
4. 全体ルールを先に作る
   - 例外調整は最後に最小限で追加する
5. 「知っている」と「再現できる」を分ける
   - 採用理由を短く残し、次回同条件で再現できる状態を目標にする

## 判断基準（迷ったら）

- 再利用される可能性がある: 分離する
- 他人が触る前提: 分離する
- CMS / Markdownが絡む: `p`は汚さない
- 1ページ完結・短期: 割り切りOK

## 完了チェック

- Blockとレイアウトが混ざっていない
- `p`に直書き余白を入れていない
- `margin-top`濫用がない
- 3回以上出るレイアウトを共通化できている
- クラス名だけで意図が読める

## まとめ

- 名前を決める
- 部品の責務を分ける
- レイアウトと余白の持ち主を決める
- SPからPCへ進める
- 完成後に境界を見直す
