# 11_表示制御（sp-only／pc-only／revert設計）

## 最初に押さえること

`display: revert` は、普段のページ制作では「ブラウザー側の表示へ戻す」と捉えると入りやすい。自分で書いた横並びを覚えて戻す機能ではない。

たとえば、`div` を `flex` で横並びにしてから非表示にし、`revert` で出し直すと、通常は `block` になり、横並びは戻らない。正確な戻り先と条件は後述する。
まずは「表示が戻ること」と「作った並び方が戻ること」を分けて見る。

読み始めは[実装（基本形）](#実装基本形)と[状態整理](#状態整理)を見比べ、SP/PCそれぞれで「出すか」と「表示時に必要な並び方」を確認する。WikiやAIを使ってこの2点を確かめられれば、表示制御を実装へ当てる目安になる。

「出たけど並びが違う」ときは[「元に戻る」と思ったときの確認例](#元に戻ると思ったときの確認例)へ戻る。出所ごとの厳密な戻り方は[正確には、どこまで戻るのか](#正確にはどこまで戻るのか)、表示は合っていて位置を決めたいときは[SP専用部品は「存在」と「位置」を分ける](#sp専用部品は存在と位置を分ける)を読み足す。すべての条件を先に暗記してから実装する必要はない。

## 目的

- 表示制御を「見た目」ではなく「存在条件」で設計する。
- SP/PC切替時の分岐を、再利用しやすい形で固定する。

## 問題の正体

表示制御でやっていることは本質的に次の2つだけ。

- 表示する
- 表示しない

ここに「要素の種類（`div` / `span` / `button`）」を持ち込みすぎると、ルールが崩れやすい。

## 命名の考え方

### `show` より `only`

`show` は「見た目」起点になりやすく、反対条件の記述が曖昧になりやすい。

```css
/* 推奨 */
.u-sp-only {}
.u-pc-only {}
```

- `sp-only`: SPでだけ存在
- `pc-only`: PCでだけ存在

存在条件が名前に入るため、意図が読みやすい。

## 設計の核心

- コンポーネントやレイアウトの設計とは切り分ける
- ここでは「条件で存在を切る」ことに集中する

## 設計分類ではUtility / Helperとして扱う

- `.u-sp-only` / `.u-pc-only` は、部品の形や構造を作るObject・Componentではない。
- 要素へ表示条件だけを追加する補助クラスなので、実装体系ではUtility / Helperとして分ける。
- `u-` 接頭辞を使うかはプロジェクト規約に従う。既存案件へ途中から別の命名体系を混ぜない。
- 表示制御クラスへサイズ・余白・並び方まで持たせず、レイアウト責務と分離する。

## 実装（基本形）

以下は、表示時にブラウザー側の `display` へ戻してよい要素向けの形。
同じ要素に自分のCSSで `flex` / `grid` などを指定している場合、その復元には使えない。

```css
.u-pc-only {
  display: none;
}

@media (min-width: 768px) {
  .u-sp-only {
    display: none;
  }

  .u-pc-only {
    display: revert;
  }
}
```

## 状態整理

以下は、表示制御の宣言が競合に勝ち、ブラウザー側の値で表示できる場合。

- SP初期状態
  - `u-sp-only`: 表示（未指定のまま）
  - `u-pc-only`: 非表示
- PC条件成立後
  - `u-sp-only`: 非表示
  - `u-pc-only`: ブラウザー側の `display` で表示（`revert`）

## `display: revert` の意味

### 「元に戻る」と思ったときの確認例

基本形のCSSより前に、次の `.actions` を書いた場合を考える。

```html
<div class="actions u-pc-only">
  <div>A</div>
  <div>B</div>
</div>
```

```css
.actions {
  display: flex;
}
/* この後に、上の「基本形」のCSSを置く */
```

他のCSSやユーザースタイルを加えず、通常フローに置いた場合は次のようになる。

| 条件 | `display` と見た目 |
|---|---|
| `.actions` だけを付ける | `flex`。AとBが横に並ぶ |
| `u-pc-only` も付け、768px未満 | `none`。表示されない |
| そのまま768px以上 | `revert` が勝ち、結果は `block`。AとBは縦に並ぶ |

「一度消したのだから、出せば元の横並びに戻る」と考えたくなるが、CSSは直前の見た目を保存していない。
画面幅ごとに有効な宣言から値を決めるため、最初から768px以上で開いても結果は同じになる。

### 正確には、どこまで戻るのか

ページ側（author origin）の `display: revert` がカスケードに勝つと、その要素の `display` に対するページ側の指定を外して値を決める。直前の `display: none` だけを取り消すのではなく、同じページ側で書いた `display: flex` も戻り先から外れる。

戻り先にはユーザースタイル（user origin）とブラウザー標準スタイル（UA origin）がある。ここでいうユーザースタイルは、閲覧者用の出所として適用されるCSSであり、自分が `style.css` に書いたCSSのことではない。これは[CSS Cascading and Inheritance Level 5 の `revert` の定義](https://www.w3.org/TR/css-cascade-5/#defaulting-keywords)に基づく。

- 通常フローの一般的な `div` は、他の指定がなければ `block` になる。
- 同じ条件の `span` は、`inline` になる。
- 常に `block` にする指定でも、以前の自作 `flex` / `grid` を復元する指定でもない。

また、`revert` 自体が競合に負ければ、この戻し処理は使われない。詳細度・記述順・`!important` などを含む勝敗と、Computedの結果を確認する。確認方法は [CSSカスケードとDevToolsの見方](./15_CSSカスケードとDevToolsの見方.md) を参照する。

## 判断基準

1. これは表示制御の問題か（存在条件）
2. それともレイアウト問題か（`flex` / `grid` / `gap`）
3. 表示するとき、ブラウザー側の `display` でよいか、自分で指定した `flex` / `grid` などが必要か
4. 前者なら基本形を検討し、後者なら必要な `display` を表示条件でも成立させる。`revert` に復元を任せない

## 注意点

- この設計は「表示制御専用」
- レイアウト切替（`display: flex/grid`）の主軸としては使わない
- ユーザースタイルやブラウザー側の指定によっては、`revert` 後も非表示になる。表示を無条件に保証する値ではない
- チーム運用時は `revert` の意図を最初に共有しておく
- SP/PCで表示文言を切り替える場合も、同一データ（日時・価格など）の意味値は変えない

## 認知アプローチ（知識に至る手順）

1. 先に「何を表示するか」ではなく「どの条件で存在させるか」を書く
2. SPを初期状態に固定する
3. PC条件で `消す側` と `戻す側` を分ける
4. 戻す側の要素に、自分で指定した `flex` / `grid` などが必要かだけ確認する
5. 実装後に、SP/PCの4状態（sp-only/pc-only）で表示と並び方をチェックする。違和感があれば、その要素のCSSとComputedの `display` を見て原因を分ける

## この設計を先に固める理由（認知負荷）

毎回すべての `display` の種類を暗記し直す必要はない。
まず次の2点に思考を狭める。

- どの条件で存在させるか
- 表示時に、自分で作った並び方を保つ必要があるか

ブラウザー側の表示でよいと確認できた要素では、`revert` を使うことで `div` / `span` ごとに値を書き分けずに済む。
「出たけど並びが違う」と感じたら、その感覚を手がかりに `display` を確認する。細かな仕組みは、その時に上の例とDevToolsへ戻ればよい。

## レイアウト問題と混ぜない境界

- 表示制御: `sp-only` / `pc-only` / `none` / `revert`
- レイアウト制御: `flex` / `grid` / `gap` / `align-*`

表示制御で詰まったときに、レイアウト調整へ逃げないことを優先する。
ただし、責務を分けても、同じ要素の `display` を両方から指定すれば競合する。表示条件と必要な並び方の両方が成立しているかは確認する。

## SP専用部品は「存在」と「位置」を分ける

SPでだけ出すヘッダー行やメニューボタンは、まず存在条件を表示制御クラスで分ける。
そのうえで、どこに置くかは通常フロー・Flex・Grid・`position` の問題として別に判断する。

```html
<div class="site-header__menu u-sp-only">
  <button class="hamburger-button" type="button">...</button>
</div>
```

```css
.site-header__menu {
  display: flex;
  align-items: center;
  justify-content: flex-end;
}
```

- SPでだけ存在させたい: `u-sp-only` / `visible-sp`
- PCでだけ存在させたい: `u-pc-only` / `visible-pc`
- 写真やヒーローの上に重ねたい: `position` を検討する
- 上下の順番どおりに置きたい: 通常フローを優先する

「SPに出すから `position` が必要」ではない。
重ねる必要がないなら、HTML上の順番と通常フローで置いた方が、後から読んだ時に位置関係を追いやすい。

## 一言でいうと

- 表示制御は存在条件の設計
- `only` 命名で条件を明示
- SP初期 + PC上書きで運用
- `revert` はブラウザー側の表示へ戻してよい要素に使い、自作の並び方の復元には使わない
