# リポジトリの整理とまとめ方

## 目的

GitHub上のリポジトリが増えてきたときに、何を分け、何をまとめるかを判断するためのメモ。

GitHubのリポジトリは、PCのフォルダのように完全な階層でまとめるより、名前・一覧README・分割方針で整理する方が扱いやすい。

## 基本方針

- 重要な制作物やWordPressテーマは、基本的に1リポジトリずつ分ける。
- 細かい練習課題は、1つの練習用リポジトリにまとめてもよい。
- リポジトリが増えて見失う場合は、一覧用リポジトリを作る。
- GitHub Pagesで公開するものは、公開設定とURLの見通しも含めて分け方を決める。

## 名前でまとめる

リポジトリ名の先頭をそろえると、GitHub上で見たときにまとまりやすい。

```txt
wp-codejump-blog
wp-codejump-news
codejump-recipe
codejump-scuba
portfolio-main
```

名前は、あとから見て「何の練習か」「どの技術か」が分かることを優先する。

## 一覧用リポジトリを作る

リポジトリ自体を完全なフォルダ管理にしにくい場合は、一覧用リポジトリを作ってREADMEにリンクを置く。

```txt
web-study-index
```

```markdown
# Web制作 学習リポジトリ一覧

## WordPress

- wp-codejump-blog
- wp-codejump-news

## HTML/CSS

- codejump-recipe
- codejump-scuba

## Portfolio

- portfolio-main
```

これは、GitHub上のリポジトリを移動するというより、戻る入口を1つ作る整理。

## 1つにまとめてもよいもの

次のようなものは、1つの練習用リポジトリ内にフォルダでまとめてもよい。

```txt
codejump-practice/
  recipe-diary/
  scuba-marine/
  navigation-menu/
```

- 小さなHTML/CSS練習
- 単発のJS練習
- 公開URLを個別に厳密管理しなくてよいもの

## 分けた方がよいもの

次は、別リポジトリにした方が扱いやすいことが多い。

- WordPressテーマ
- ポートフォリオ本体
- 公開URLやREADMEを独立して見せたい制作物
- 依存関係やビルド手順が違うもの

WordPressテーマは、テーマ単位で構造・確認手順・履歴を追うことが多いため、1テーマ1リポジトリの方が判断しやすい。

## Organizationについて

GitHub Organizationを作って、学習用・案件用・公開用を分ける方法もある。

ただし、個人学習の初期段階では大げさになりやすい。
まずは、名前の統一と一覧用READMEで足りるかを見る。

## 判断基準

1. その制作物を単独で見せたいか
2. 公開URLやREADMEを独立させたいか
3. WordPressテーマのように構造が独立しているか
4. 小さな練習としてまとめた方が管理しやすいか
5. 後から探すときに、名前だけで戻れるか

## 一言でいうと

大事な制作物とWordPressテーマは分ける。
細かい練習はまとめてもよい。
リポジトリが増えたら、まず一覧READMEで入口を作る。
