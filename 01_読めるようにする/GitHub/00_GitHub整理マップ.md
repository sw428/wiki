# GitHub整理マップ

## このカテゴリの役割

GitHubを、Web制作で使う「コードの置き場・履歴共有・公開確認」の基礎として整理する。

ここでは、Gitそのものの細かい内部仕様よりも、VS Codeや制作作業の中で迷いやすい次の点を優先する。

- ローカルのGitと、GitHub上のリモートリポジトリの違い
- `push` / `pull` / `remote` / `upstream` の見方
- VS Codeに出る「ブランチの発行」が何を意味しているか
- GitHub Pagesなど、Web制作の公開確認とGit操作の切り分け

## 会話から拾う対象

Git / GitHubまわりは、会話中に出た次の内容をここへ拾う。

- 実際に出たGitコマンドと、その意味
- PowerShellやVS Codeに出たメッセージの読み方
- GitHub画面で迷った場所
- `main` / `master` / `origin/main` / `upstream` など、混ざりやすい名前の区別
- 次回同じ操作をするときの安全確認順

VS Code本体の設定や拡張機能の採用理由は、[自分のVS Code環境](../vscode/自分のvscode環境/00_自分のvscode環境.md) 側へ分ける。

## Web制作とのつながり

Web制作では、GitHubは主に次の目的で使う。

- 自分が書いたコードの履歴を残す
- 別PCや別環境でも同じコードを扱えるようにする
- GitHub Pagesなどで公開する
- 変更前後を比較し、戻せる状態を作る
- 学習用・案件用・WordPress用など、リポジトリの分け方を整理する

`push` したことと、公開URLに反映されたことは同じではない。
公開確認では、GitHub Pagesの公開元ブランチやデプロイ結果も分けて見る。
