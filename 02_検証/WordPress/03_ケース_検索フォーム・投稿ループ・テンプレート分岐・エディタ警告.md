# 03_ケース_検索フォーム・投稿ループ・テンプレート分岐・エディタ警告

## 位置づけ

CodeJump / WordPress学習中に出た、検索フォーム、投稿ループ、テンプレート階層、ページネーション周りの読み方をまとめる。

このケースでは、WordPress固有の関数暗記よりも、HTML/CSS/PHP/管理画面/エディタ補助のどの層で起きている話かを切り分ける。

## ケース1: 検索欄が表示されない

### 見ること

- テンプレート内で検索フォームを出す処理を呼んでいるか
- `searchform.php` があるか
- `get_search_form()` を呼んだ位置が表示したい場所と合っているか
- CSSで `display: none` や幅ゼロになっていないか
- ウィジェットやブロック側で置いたつもりの検索欄と、テーマテンプレート側の検索欄を混ぜていないか

### 採用認識

WordPressでは、検索フォームは「自動で必ず出るもの」ではない。

テーマ側で出したいなら、表示したい場所に `get_search_form()` を呼ぶ。

```php
<?php get_search_form(); ?>
```

検索欄が表示されない時は、まず「HTMLとして出力されていない」のか、「出力されているがCSSで見えない」のかを分ける。

## ケース2: テンプレート階層は分岐として読む

### 見ること

カテゴリページのテンプレート選択は、条件によって使うファイルが変わる。

```txt
category-hotel.php がある
↓
使う

なければ category.php
↓
なければ archive.php
↓
なければ index.php
```

プログラムの分岐で見ると、次に近い。

```php
if (file_exists('category-hotel.php')) {
  use_template('category-hotel.php');
} elseif (file_exists('category.php')) {
  use_template('category.php');
} elseif (file_exists('archive.php')) {
  use_template('archive.php');
} else {
  use_template('index.php');
}
```

### 採用認識

テンプレート階層は、フォルダ構造ではなく、WordPressが「条件に合うテンプレートを優先順位で探す分岐」として読む。

基本情報などで扱う `if` / `else` / 優先順位の考え方は、WordPressのテンプレート選択にもつながる。

## ケース3: 投稿ループの読み方

### 対象コード

```php
<?php if (have_posts()) : ?>
  <?php while (have_posts()) : the_post(); ?>
    記事を表示
  <?php endwhile; ?>
<?php endif; ?>
```

### 読み方

- `if (have_posts())`: 表示できる記事があるか確認する
- `while (have_posts())`: 記事がある間、繰り返す
- `the_post()`: 次の記事を取り出して「今の記事」として準備する
- `endwhile`: `while` の終わり
- `endif`: `if` の終わり

`the_title()` / `the_time()` / `the_excerpt()` / `the_content()` / `the_permalink()` などは、`the_post()` で準備された「今の記事」の情報を表示する。

### 採用認識

投稿ループは、「投稿があるなら、1件ずつ取り出して表示する」ためのWordPressの定番セット。

抽象的な分岐・ループ理解を、WordPressの実物で見ている状態として扱う。

## ケース4: `global $wp_query;` だけ赤線が出る

### 見ること

`$wp_query` は、自分で作ったローカル変数ではなく、WordPress本体が用意しているグローバル変数。

関数内で使う時は、次のように書くことがある。

```php
function pagination() {
  global $wp_query;

  echo paginate_links(array(
    'total' => $wp_query->max_num_pages,
  ));
}
```

### 採用認識

VS Code / Intelephense がWordPress本体側のグローバル変数まで読めていないと、`global $wp_query;` や `$wp_query->max_num_pages` に警告が出ることがある。

これは、必ずしもWordPress実行時のエラーではなく、エディタ補助側が文脈を解決できていない警告として見る。

ただし、赤線を無視してよいかは、ブラウザ表示、PHPエラー、WordPress上の動作、関数定義の有無を合わせて確認する。

## ケース5: Archiveの線とCSS責務

### 見ること

Archiveのようなリストの線は、WordPress固有ではなく、最終的に出力された `ul > li > a` へCSSを当てる問題として見る。

```css
.p-archive__list {
  border-top: 1px solid #777;
  border-bottom: 1px solid #777;
}

.p-archive__item + .p-archive__item {
  border-top: 1px solid #777;
}
```

### 採用認識

- 外側の上下線: リスト全体の責務
- 項目間の区切り線: 隣接する項目同士の責務
- 文字と線の距離: リンクの `padding`

WordPressの `wp_get_archives()` で生成されたリストでも、見た目の制御はHTML/CSS側の比重が大きい。

## 保留

- ショートコードをボタンのようにコピーできない件は、どのプラグイン・画面・ブロックで起きているかが必要。
- 一般化する前に、対象画面と出力HTMLを確認する。
