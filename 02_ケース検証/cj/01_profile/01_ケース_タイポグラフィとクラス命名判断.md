# ケース: タイポグラフィとクラス命名判断

## 目的

`profile` 作品で、文字スタイル用のクラスをどこまで分けるかを判断する。

特に、`t-` のような typography 用クラスを作るか、作品内の用途名クラスへ直接 `font-size` / `line-height` を書くかを整理する。

## 今回の結論

この `profile` 作品では、無理に `t-` クラスを作らず、用途名クラスへ直接タイポグラフィ指定を書く。

理由は、1ページ規模のLPでは `t-heading-lg` や `t-caption` のような共通文字スタイルを作るより、`.section-title` / `.header__nav` / `.footer__copyright` のように「その場所で何を表すか」が見える方が読みやすいから。

## 今回は採用しない形

`t-` を使う設計自体は間違いではない。

```css
.t-heading-lg {
  font-size: 32px;
  font-weight: 700;
  line-height: 1.5;
}

.t-caption {
  font-size: 10px;
  font-weight: 400;
  line-height: 1.5;
}
```

ただし今回の `profile` では、次のようにHTML上のクラス数が増える。

```html
<h2 class="section-title t-heading-lg">About</h2>
<small class="footer__copyright t-caption">&copy; 2020 Profile</small>
```

この作品では、文字スタイルを複数ページで使い回す前提が強くない。  
そのため、設計練習としてはありだが、今回の実装判断としては大げさと見る。

## 採用する形

この作品では、用途名クラスに文字スタイルも含める。

```css
.header__nav {
  font-size: 14.4px;
  font-weight: 400;
  line-height: 1.46;
  color: var(--color-lead);
}

.section-title {
  font-size: 32px;
  font-weight: 700;
  line-height: 1.5;
  color: var(--color-text);
}

.heading {
  font-size: 16px;
  font-weight: 700;
  line-height: 1.5;
  color: var(--color-text);
}

.text-lead {
  font-size: 14.4px;
  font-weight: 400;
  line-height: 1.46;
  color: var(--color-lead);
}

.footer__copyright {
  font-size: 10px;
  font-weight: 400;
  line-height: 1.5;
  color: var(--color-text);
}
```

## `line-height` の比率化

元の指定が px の場合、`line-height ÷ font-size` で比率にする。

```txt
21 ÷ 14.4 = 1.458333... -> 1.46
48 ÷ 32 = 1.5
24 ÷ 16 = 1.5
15 ÷ 10 = 1.5
```

今回の判断では、細かく合わせる箇所は `1.46`、見た目を整理してよい箇所は `1.5` とする。

## フッターコピーライトの判断

フッターのコピーライトは、汎用の `.small-text` より `.footer__copyright` にする。

理由は、この作品ではその文字スタイルを他の場所で使い回すより、「フッターのコピーライトである」と分かることの方が大事だから。

```html
<footer class="footer">
  <small class="footer__copyright">&copy; 2020 Profile</small>
</footer>
```

```css
.footer__copyright {
  font-size: 10px;
  font-weight: 400;
  line-height: 1.5;
  color: var(--color-text);
}
```

## GPTで型を作ることの扱い

この作品では、GPTに初期案を出してもらうこと自体は問題にしない。

ただし、GPT案をそのまま正解にせず、次の観点で自分が採用判断をする。

- この作品の規模に対して大げさではないか
- クラス名から役割が読めるか
- 共通化する理由が実際にあるか
- ブロック名とタイポグラフィ用クラスが混ざって読みにくくならないか

## 今回の採用判断

```txt
profile 作品では、タイポグラフィ専用の t- クラスは作らない。
用途名クラスへ直接 font-size / font-weight / line-height を書く。
```

## 基礎概念への反映先

今回、作品名を外しても使える判断だけ次へ戻した。

- [`05_インラインと行の仕組み`](../../../01_基礎概念/HTML・CSS/05_インラインと行の仕組み.md)
  - `line-height` を `line-height ÷ font-size` で倍率化する判断
  - 細かく寄せる値と、扱いやすく丸める値の分け方
- [`03_CSS設計方針（BEM × レイアウト分離）`](<../../../01_基礎概念/ex_自分の設計ルール/03_CSS設計方針（BEM × レイアウト分離）.md>)
  - typography用クラスを作る条件
  - 用途名クラスと `t-` クラスの責務分離
  - 小さいLPでは用途名クラスへ直接タイポグラフィ指定を書く判断

一方で、`profile` 作品で `.footer__copyright` を採用することや、具体的な数値セットはこのケース側に残す。
