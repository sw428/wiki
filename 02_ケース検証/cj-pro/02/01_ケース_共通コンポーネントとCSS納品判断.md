# ケース: 共通コンポーネントとCSS納品判断

## 目的

`02` で、Figma上の共通パーツをどう扱うか、また CSS 1ファイル指定に対して SCSS を使うかどうかを判断する。

このケースでは、課題文やカンプ内容を細かく復元せず、自分の実装判断だけを残す。

## 前提として受けたこと

- 複数ページ構成の静的HTMLコーディングとして受ける
- CSSは1ファイルにまとめる前提で考える
- できあがったHTML/CSSは、あとでWordPress側へ組み込まれる想定
- Figma上に、PC用の共通 `header` / `footer` パーツがある

## 共通コンポーネントの扱い

Figma上の `header` / `footer` は、このページだけの一部分ではなく、複数ページで使い回す共通パーツとして見る。

静的HTMLでは各ページに同じ `header` / `footer` を入れる。  
ただし、後でWordPressへ組み込まれる前提があるため、構造は `header.php` / `footer.php` に分けやすい形を意識する。

```html
<header class="header">
  <div class="header__inner">
    <h1 class="header__logo">
      <a href="/">
        <img src="./img/logo.svg" alt="">
      </a>
    </h1>
  </div>
</header>

<main class="main">
  <!-- ページごとの中身 -->
</main>

<footer class="footer">
  <div class="footer__inner">
    <!-- 共通フッター内容 -->
  </div>
</footer>
```

見る順番は次にする。

1. `header` / `footer` が共通パーツか確認する
2. 全ページ共通で使う構造を先に決める
3. ページごとの差分は `<main>` 側へ分ける
4. CSSでは `header` / `footer` を共通パーツとして書く

## CSS 1ファイル指定への判断

今回の前提では、納品物としては `css/style.css` 1ファイルにまとめる。

SCSSを使うこと自体は悪くないが、相手が求めているのは完成したCSSである。  
そのため、SCSSを使う場合でも内部作業用にとどめ、納品はコンパイル済みの `style.css` のみにする。

ただし、今回の規模では、まず `style.css` 1枚で作る方が分かりやすい。

```txt
index.html
page-list.html
page-detail.html
css/
  style.css
img/
```

CSS内では、コメントで領域を分けて管理する。

```css
/* Variables
--------------------------------*/

/* Base
--------------------------------*/

/* Layout
--------------------------------*/

/* Header
--------------------------------*/

/* Footer
--------------------------------*/

/* Top
--------------------------------*/

/* Page list
--------------------------------*/

/* Page detail
--------------------------------*/
```

## 今回の採用判断

```txt
02では、共通 header / footer を先に作る。
ページごとの差分は main 側へ分ける。
CSSは納品前提に合わせて style.css 1ファイルで管理する。
SCSSは必須にしない。
```

## 基礎概念・設計ルールへの反映先

  - 実案件コードはHTML/CSS/JavaScriptを含めて、許可なく公開しない

- [`02_SCSSとCSS分割`](../../../01_基礎概念/設計/CSS設計/02_SCSSとCSS分割.md)

  - SCSSを使う場合も内部作業用にとどめ、納品条件を優先する

## このケースに残すもの

- `02` での共通パーツの見方
- `CSS 1ファイル` 指定に対する実装判断
- WordPress組み込みを見越した静的HTML構造の意識

## このケースに残さないもの

- カンプ画像や素材そのもの
- 課題文・仕様書の原文
- 課題内容を復元できるほどの詳細なページ条件
