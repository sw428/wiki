# ケース検証運用

## 目的

- ケース検証は `02_ケース検証` に集約する。
- フォルダは案件ごとに分ける。
- 基礎概念へは、ケースから抽出できる一般原理・判断順だけを戻す。

このファイルは、ケース検証の入口、案件別フォルダの使い方、基礎概念や設計ルールへの反映先を決めるための共通運用をまとめる。

## 背景

以前は、ケース検証で受けたあとに基礎概念へ戻す流れは作っていたが、基礎概念側と旧実践側の2入口が管理負荷になっていた。

混在ログでは、次の話題が同時に入ることがある。

- 特定ポートフォリオの実装判断
- HTML/CSS/JSなどの基本原理
- BEM命名やSCSS分割のような実務汎用ルール

そのため、ケース検証は `02_ケース検証` に一元化し、案件ごとのフォルダで受けてから反映先を振り分ける。

## 基本ルール

- ポートフォリオ固有の話は、該当案件フォルダへ置く。
- 案件を超えて使える話は、ケース本文内で「一般化できる判断」として残す。
- 一般化できる判断だけを `01_基礎概念` / `03_参照元` / 既存ノートへ戻す。
- どちらへ置くかを事前に厳密化しすぎず、Codex が文脈から振り分ける。
- 判断が割れる場合だけ、ケース本文に理由を短く残す。

## 採用する流れ

1. 貼り付けログを読む
2. まず `02_ケース検証` の案件フォルダで受ける
3. 混在している場合は、必要に応じてケースを分ける
4. ケース本文で、案件固有 / 一般原理 / 実務運用を分ける
5. その後に反映先を決める

## 細かい運用

`AGENTS.md` では「ケース先行」「案件固有と一般化の切り分け」を判断し、このファイルではケースとして受けたあとの具体的な作業順を扱う。

1. 材料を `新規ケース` / `追記` / `統合` / `保留` に分ける。
2. 実装条件や判断履歴を含む場合は、まずケース側に受ける。
3. 案件固有部分が見えたあとで、再利用できる原理だけを抽出する。
4. `01_基礎概念` に戻す前に、既存ノートを確認する。
5. 既存ノートに同じ概念がある場合は、説明を重複させずケース側から参照する。
6. 一般化した場合は、ケース末尾に `基礎概念への反映先` または `基礎概念へ戻した内容` を置く。
7. 条件、理由、例外、一般化しなかったものが追えるように残す。

編集後は、何を `02_ケース検証` に残し、何を `01_基礎概念` / `03_参照元` に戻したかを報告する。

## 反映先の判断

### 特定ポートフォリオの話

- 入口: `02_ケース検証/<案件名>`
- 反映先:
  - 案件固有の検証・実装記録 -> `02_ケース検証/<案件名>/...`
  - 抽象化できるHTML/CSS/JS原理 -> `01_基礎概念`
  - 自分の採用方針として固定する設計判断 -> `01_基礎概念/ex_自分の設計ルール`

特定サイトの構造、素材、カンプ、命名、ページ構成に依存する判断は、まず実践ケースとして受ける。
そこから、案件名や素材条件を外しても成立する原理だけを基礎概念へ戻す。

### 一般的なBEM / SCSSの話

- 入口: `02_ケース検証/<案件名>` または共通運用ケース
- 反映先:
  - 基礎概念として再利用できるCSS原理 -> 必要に応じて `01_基礎概念/HTML・CSS`
  - BEM命名の採用方針 -> `01_基礎概念/ex_自分の設計ルール/01_BEMとクラス命名ルール.md`
  - SCSS導入・分割の採用方針 -> `01_基礎概念/ex_自分の設計ルール/02_SCSSとCSS分割ルール.md`
  - CSS設計全体の採用方針 -> `01_基礎概念/ex_自分の設計ルール/03_CSS設計方針（BEM × レイアウト分離）.md`

BEMやSCSSは、一般概念、案件固有の検証、自分の採用方針が混ざりやすい。
そのため、基礎概念へ自動で入れず、まずケースで「一般概念なのか、特定案件固有なのか、自分の設計ルールとして固定するのか」を分ける。

### 基礎概念へ戻すもの

- HTML/CSS/JSなど、案件名を外しても成立する基本原理
- 表示ボックス、行ボックス、Flex/Grid、画像比率などの確認順
- BEM/SCSSの話でも、CSSの基本原理として切り出せる部分

### ケース検証へ残すもの

- 特定ポートフォリオの実践判断
- 案件ごとの既存構造、命名方針、素材条件に依存する判断

### 自分の設計ルールへ戻すもの

- 自由度が高く、正解が1つに決まりにくい命名・分割・責務境界
- BEMやSCSSの考え方を踏まえた、自分の当面の採用方針
- 案件条件を外しても使いたいが、一般仕様としては言い切りすぎになる運用判断

## 直下に残す例外

- 案件ではなく、このWikiの運用自体を扱うケースだけは、このフォルダ直下に残してよい。

ただし、運用として定着した内容はこのファイルへ統合し、独立ケースとして残し続けない。
